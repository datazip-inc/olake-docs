# Setup OLake Sync as a Kubernetes CronJob

This guide details the process for deploying and managing an OLake data synchronization task as a scheduled Kubernetes CronJob. This configuration uses standard Kubernetes resources (ConfigMaps, PVC, CronJob) to automate recurring OLake `sync` operations using pre-generated streams files.

## Prerequisites

Ensure the following requirements are met before proceeding:

1.  **Kubernetes Cluster Access**: Administrative access to a Kubernetes cluster.
2.  **`kubectl`**: Configured `kubectl` command-line tool. [Installation Guide](https://kubernetes.io/docs/tasks/tools/install-kubectl/).
3.  **Pre-generated OLake streams files (`selected_streams.json` and `available_streams.json`)**: This setup requires both files, generated beforehand using the OLake `discover` command against your source database.
    *   Streams Generation Guides:
        *   [Streams config](https://olake.io/docs/install/docker-cli#streams-config)
    *   The content of each file will be placed within the `cm_olake-streams-config.yaml` ConfigMap.
4.  **Kubernetes Namespace**: The manifests default to the `olake` namespace. Create it (`kubectl create namespace olake`) or update the `namespace` fields in all YAML files if using a different target.
5.  **Node Labels (Optional)**: If you uncomment the `affinity` block in `cronjob_olake.yaml`, ensure target nodes possess the specified labels.
6.  **ReadWriteMany StorageClass**: The PVC that holds the config files and the sync state needs a StorageClass with `ReadWriteMany` support (`kubectl get storageclass`). If any stream uses positional deletes or deletion vectors, use block storage with `ReadWriteOnce` instead; see **Index storage** below.

**2. Customize Downloaded Files**

Edit the downloaded files with your specific configurations:

*   **`cm_olake-source-config.yaml`**: Update `source.json` with your source connection parameters. The sample is a MongoDB replica set; see the [connector docs](https://olake.io/docs/connectors/overview) for the fields of other sources.
*   **`cm_olake-destination-config.yaml`**: Update `destination.json` with your destination configuration.
*   **`cm_olake-streams-config.yaml`**: Replace the content under `selected_streams.json` with your own stream selection. Replace the content under `available_streams.json` with the file generated by `discover` (do not edit it). `partition_regex` uses the Iceberg syntax, for example `"/{created_at, day}"`.
*   **`cronjob_olake.yaml`**:
    *   Set `metadata.namespace` on the CronJob, the PVC and the three ConfigMaps (default `olake`).
    *   Configure `spec.schedule`. Refer for schedule syntax: **[CronTab Guru](https://crontab.guru/)**
    *   Set `spec.suspend` to `false` to enable the schedule.
    *   Update `spec.jobTemplate.spec.template.spec.containers[0].image` with the OLake Go image and version for your source (the sample uses `olakego/source-mongodb:v1.2.2`). See **[OLake Docker Hub Images](https://hub.docker.com/u/olakego)**.
    *   To pin the sync to labelled nodes, uncomment the `affinity` block under `spec.jobTemplate.spec.template.spec` and set the label key and value.
    *   Adjust `resources.requests` and `resources.limits` for the main OLake Go container.
    *   **Crucially, replace `change-me-rwx-storage-class`** with your `storageClassName` in the `PersistentVolumeClaim` definition at the end of the file. This StorageClass must support the `ReadWriteMany` access mode specified in the PVC.

**Sync state.** The sync writes `state.json` next to the config files on the PVC. Each run passes it back with `--state` once it exists, so CDC and incremental streams resume where the last run stopped.

The first run starts without `--state`, which gives a new pipeline the current state version. Deleting the PVC (or `state.json`) makes the next run start from scratch.

**Index storage.** Streams with `update_type` set to `pos` (positional deletes) or `dv` (deletion vectors) keep a row index between runs. The sync container sets `OLAKE_INDEX_DB_DIR=/mnt/config/index-db`, so the index lives on the same PVC; without it, every run would rebuild the index by scanning the whole Iceberg table. Streams with `eq` (equality deletes) or append mode do not use it.

The index needs file locking and reliable `fsync`, so the PVC must then be block storage: set `accessModes` to `ReadWriteOnce` and use a block StorageClass (an EBS, Persistent Disk or Azure Disk class) with room for the index. Shared filesystems such as NFS, EFS, Filestore and Azure Files are not supported for it.

`concurrencyPolicy: Forbid` keeps one sync pod at a time, so a single-attach volume is enough. See [index storage](https://olake.io/docs/install/docker-cli#index-storage) for the details.

## Deployment Procedure

Apply the configured manifests to your Kubernetes cluster:

1.  **Apply ConfigMaps**:
    ```bash
    kubectl apply -f cm_olake-source-config.yaml -n olake
    kubectl apply -f cm_olake-destination-config.yaml -n olake
    kubectl apply -f cm_olake-streams-config.yaml -n olake
    ```

2.  **Apply CronJob and PVC**:
    ```bash
    kubectl apply -f cronjob_olake.yaml -n olake
    ```

3.  **Verify PVC Status**:
    ```bash
    kubectl get pvc olake-config-pvc -n olake
    ```
    *(Ensure `STATUS` is `Bound`. Troubleshoot StorageClass or provisioner if `Pending`).*

4.  **Verify CronJob Status**:
    ```bash
    kubectl get cronjob olake-sync -n olake
    ```

## Manual Job Execution and Control

*   **Trigger Manually**: Create a Job instance immediately from the CronJob template. This is useful for testing or running outside the defined schedule.
    ```bash
    kubectl create job --from=cronjob/olake-sync manual-olake-sync-$(date +%s) -n olake
    ```
    *Monitor the manually created job using the commands in the Monitoring section below.*

*   **Suspend CronJob**: Prevent the CronJob from creating *new* jobs based on the schedule. Does not affect running jobs.
    ```bash
    kubectl patch cronjob olake-sync -n olake -p '{"spec":{"suspend":true}}'
    ```

*   **Unsuspend CronJob**: Re-enable the CronJob's schedule.
    ```bash
    kubectl patch cronjob olake-sync -n olake -p '{"spec":{"suspend":false}}'
    ```
    
## Cleanup

To remove the deployed resources:

1.  **Delete CronJob**: `kubectl delete cronjob olake-sync -n olake`
2.  **Delete PVC**: `kubectl delete pvc olake-config-pvc -n olake` (**Caution:** Deletes persisted data, including the sync state).
3.  **Delete ConfigMaps**:
    ```bash
    kubectl delete configmap olake-source-config -n olake
    kubectl delete configmap olake-destination-config -n olake
    kubectl delete configmap olake-streams-config -n olake
    ```
