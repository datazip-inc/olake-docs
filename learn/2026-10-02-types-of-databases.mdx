<TLDR title='Key takeaways'>

The main types of databases are relational (tables and SQL), document, key-value, wide-column, graph, time-series, vector, search, analytical and embedded. Two questions place most databases. What shape is your data?

And do you mostly make many small updates or run big reports? For business records with rules between them, start with relational. Each specialist type suits one job and has a named limit outside it, and a few products now cover more than one type.

- A **database** is an organized collection of data, and a database management system (DBMS) is the software that lets people and apps use it, per IBM's [database guide](https://www.ibm.com/think/topics/database).
- Sources can't agree on the count: [IBM](https://www.ibm.com/think/topics/database) names six common types and two more under other types, [Matillion's April 2025 page](https://www.matillion.com/blog/the-types-of-databases-with-examples) lists eleven, and [AlgoMaster](https://blog.algomaster.io/p/15-types-of-databases) lists fifteen. Two questions place any database, whatever the count.
- Relational databases suit exact records and joins. Document, key-value, wide-column, graph, time-series, vector and search databases each suit one narrower job.
- Every type has a named limit. Key-value stores offer limited queries, for example, and a search index shouldn't be your primary store.
- Labels blur. PostgreSQL, Redis and Google Spanner each cover more than one type, so shop by the job you need done.

</TLDR>

## Types of databases at a glance

Each row gives the data shape, real products, the job it fits and its limit.

| Type | Stores data as | Example products | Good for | Named limit |
| --- | --- | --- | --- | --- |
| Relational (SQL) | Tables of rows and columns | PostgreSQL, MySQL, SQL Server, Oracle | Orders, inventory, billing | Scaling out generally needs sharding (splitting data across servers) |
| Document | JSON-like documents | MongoDB, Azure Cosmos DB for NoSQL | Catalogs, profiles, content | Document size growth; narrower transaction scope |
| Key-value | One value per unique key | Redis, DynamoDB | Caches, sessions, carts | Limited queries; DynamoDB has no join |
| Wide-column | Rows grouped in partitions | Cassandra, HBase | Write-heavy telemetry | Key design up front; less query freedom |
| Graph | Nodes and relationships | Neo4j, Amazon Neptune | Fraud rings, social links | Not ideal for bulk analytical scans |
| Time-series | Timestamped values | InfluxDB, TimescaleDB | Metrics, events | Tag cardinality and retention cost |
| Vector | Lists of numbers (embeddings) | pgvector, Pinecone | Similarity search | Indexes trade some recall for speed |
| Search engine | Indexed text and fields | Elasticsearch | Full-text search, logs | Index is eventually consistent |
| Analytical (OLAP) | Columns, scanned in bulk | BigQuery, ClickHouse, Redshift | Reports over history | Built for heavy reads, not many small writes |
| Embedded | One local file | SQLite | Local data for one app | No separate server process |

Example uses come from that page and each vendor's docs. Product names and licences were checked in October 2026. Vendors change them, so confirm on the vendor page before you buy.

## What is a database, and how do we sort the types?

[IBM defines a database](https://www.ibm.com/think/topics/database) as a digital repository for storing, managing and securing organized collections of data. The software that runs it is a database management system (DBMS), though people often say "database" for both.

Most lists of database types mix two ways of sorting. Keep them apart and each later choice is easier to explain and to check.

1. **Data shape.** Is your data tables, documents, key and value pairs, links between things, or readings over time?
2. **Workload.** Do you make many small, fast changes (this is called OLTP, short for online transaction processing), or run big reports over lots of history (this is called OLAP, short for online analytical processing)? Our [OLTP vs OLAP guide](/learn/oltp-vs-olap/) goes deeper on that split.

[Microsoft's Azure Architecture Center guide](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) makes the same point from the workload side. It says one data store rarely fits every access pattern.

So most production systems end up using more than one model. [Microsoft calls that polyglot persistence](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models), which is a fancy name for "different tools for different jobs."

### Words that are not types

Some lists count "cloud database" as a type. It isn't one. That describes where a database runs, not how it stores data.

[DynamoDB's docs](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Introduction.html), for instance, call it a serverless, fully managed NoSQL database. Serverless and managed describe how it runs.

"SQL" and "NoSQL" trip people up too. SQL is a query language, and [MongoDB's NoSQL explainer](https://www.mongodb.com/resources/basics/databases/nosql-explained) calls NoSQL a database management approach, so the two aren't matching halves. We dig into that split below.

## Relational databases

A relational database stores data in tables of rows and columns, and the tables link to each other through shared keys.

You read and change the data with SQL (Structured Query Language). [Microsoft says](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) relational stores enforce integrity and support complex joins.

They also support transactions that follow ACID (atomicity, consistency, isolation and durability) rules. In plain words, changes are all-or-nothing and stay consistent.

Examples are PostgreSQL, MySQL, SQL Server and Oracle. Our [PostgreSQL vs MySQL comparison](/compare/postgres-vs-mysql/) sets the first two side by side. [PostgreSQL's About page](https://www.postgresql.org/about/) calls it an open-source object-relational database system that extends SQL, and says its origins date back to 1986. [Oracle's own pages](https://www.oracle.com/database/) now call its product Oracle AI Database (checked Oct 2026).

**Fits:** order management, inventory, billing and any case with strict rules between records. [Microsoft's own choice table](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) sends "strict multi-entity transactions" to relational.

**Named limit:** Microsoft says horizontal scale [generally requires sharding or partitioning](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) (checked Oct 2026).

CockroachDB is one example of a distributed SQL database. [Its docs](https://docs.cockroachlabs.com/docs/stable/frequently-asked-questions) say it is built on a strongly consistent key-value store and that transactions use the strongest standard isolation level by default (checked Oct 2026). We found no list of its limits on the pages we read, so we won't guess.

## Document databases

A document database stores each record as a self-contained document, usually JSON, so related details can sit inside one document instead of in separate tables. [MongoDB's manual](https://www.mongodb.com/docs/manual/introduction/) says it stores data in flexible, JSON-like documents.

MongoDB is a common example. [Microsoft also lists](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) Azure Cosmos DB for NoSQL as a document store.

**Fits:** product catalogs, content management and profile stores. Each item has its own shape, and the app reads a whole item at once.

**Named limit:** Microsoft lists [document size growth and selective transactional scope](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models). It also says you need careful data shape design for high-scale queries (checked Oct 2026).

Licence is worth a look too. MongoDB's [server licence file](https://raw.githubusercontent.com/mongodb/mongo/master/LICENSE-Community.txt) (checked Oct 2026) is the Server Side Public License (SSPL), published by MongoDB, so read it before you adopt MongoDB.

## Key-value databases

A key-value database stores one value against a unique key, like a locker number and what's inside. You ask for the key and you get the value back, and [Microsoft says](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) most key-value stores support only simple query, insert and delete operations.

[Amazon DynamoDB](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Introduction.html) and Redis are the usual examples. DynamoDB's docs say it supports both key-value and document data models, and that it provides ACID transactions.

Redis calls itself an in-memory data store. [Its docs](https://redis.io/docs/latest/get-started/) list roles as a cache, vector database, document database, streaming engine and message broker.

**Fits:** caches, sessions, shopping carts and feature flags. DynamoDB's own example is a shopping cart.

**Named limits:** [Microsoft says](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) changing part of a value means overwriting the whole value, and queries are limited. [DynamoDB's docs](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Introduction.html) say it has no join operator (checked Oct 2026). So you copy data into the shape you read it in.

Check Redis's licence too. Its [repository page](https://github.com/redis/redis) (checked Oct 2026) lists three licences from Redis `8`: the Redis Source Available License (RSALv2), the SSPL `v1` and the Affero General Public License (AGPL) `v3`. Redis `7.2` and earlier remain under the 3-clause Berkeley Software Distribution licence.

## Wide-column databases

A wide-column database keeps rows in partitions, and each row can have its own set of columns. [Apache Cassandra](https://cassandra.apache.org/doc/latest/cassandra/architecture/overview.html) says it implements a partitioned wide-column storage model with eventually consistent semantics. Eventually consistent means a read can briefly show older data after a write.

[Microsoft names](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) Cassandra and HBase as column-family examples and sends "wide, sparse, write-heavy telemetry" here.

**Named limit:** [Cassandra's docs](https://cassandra.apache.org/doc/latest/cassandra/architecture/overview.html) say all performant queries supply the partition key (checked Oct 2026). [Microsoft adds](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) that you must design row keys and column families up front. Query flexibility is lower than relational, so plan your questions before you pick this one.

A naming trap: "columnar" is used for two different designs. [Cassandra's docs](https://cassandra.apache.org/doc/latest/cassandra/architecture/overview.html) call its model wide-column and say queries supply the partition key.

[ClickHouse's docs](https://clickhouse.com/docs/intro) call it a column-oriented database for analytical processing. [Microsoft lists](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) wide-column and analytics stores as separate categories, so don't treat them as interchangeable.

## Graph databases

A graph database stores things (nodes) and the links between them (relationships). [Neo4j's docs](https://neo4j.com/docs/getting-started/get-started-with-neo4j/graph-database/) say it stores data as nodes, relationships and properties instead of tables or documents.

Neo4j and Amazon Neptune are the common examples. [Neptune's docs](https://docs.aws.amazon.com/neptune/latest/userguide/intro.html) say it supports the Gremlin and openCypher query languages, plus SPARQL (another query language for graph data).

**Fits:** fraud rings, social networks, knowledge graphs and supply chain dependencies, which are the graph workloads [Microsoft lists](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models). A typical question is "who is connected to whom, three steps out?"

**Named limit:** Microsoft says graph stores add [overhead if relationships are shallow](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models). They need careful modelling and are not ideal for bulk analytical scans (checked Oct 2026).

## Time-series databases

If your data is basically "a number and when it happened," this is your type. A time-series database stores values that arrive with a timestamp, such as metrics and events. [Microsoft says](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) these stores are typically append-only and built for high-volume ingestion and time-window queries.

[InfluxDB's docs](https://docs.influxdata.com/influxdb3/core/) call InfluxDB 3 Core a database built to collect, process, transform and store event and time series data. [TimescaleDB](https://github.com/timescale/timescaledb) is a PostgreSQL extension for the same job, which [Microsoft says](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) Azure Database for PostgreSQL supports.

**Named limit:** Microsoft lists [four points to watch](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models): tag cardinality, retention cost, downsampling and specialized query languages (checked Oct 2026). In plain words: plan how many unique tags you store and how long you keep the data.

## Vector databases

A vector database stores embeddings, which are long lists of numbers that a machine learning model makes to describe text, images or other data.

You search for items whose numbers are close to your query's numbers. That's similarity search, and [Microsoft lists](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) semantic document search and recommendation engines among its uses.

[pgvector](https://github.com/pgvector/pgvector) adds this to Postgres and offers two index types, `HNSW` (a multilayer graph) and `IVFFlat` (lists of vectors). [Pinecone's docs](https://docs.pinecone.io/guides/get-started/overview) describe Pinecone Database as a managed database that brings full-text and semantic search together.

**Named limit:** [pgvector's readme file](https://github.com/pgvector/pgvector) says approximate indexes, which covers both `HNSW` and `IVFFlat`, trade some recall (finding every true match) for speed (checked Oct 2026). [Microsoft lists](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) indexing complexity, storage overhead and latency versus accuracy as the considerations.

Measure recall on your own queries before you trust any vendor's speed claim.

## Search engines

A search engine database indexes text and fields so you can run full-text queries and rank results by relevance. [Microsoft's strengths list](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) names full-text queries, scoring and fuzzy matching.

[Elasticsearch's repository page](https://raw.githubusercontent.com/elastic/elasticsearch/main/README.asciidoc) calls it a distributed search and analytics engine, scalable data store and vector database. Its [repository licence file](https://raw.githubusercontent.com/elastic/elasticsearch/main/LICENSE.txt) (checked Oct 2026) sets a default triple licence of AGPL `v3.0` only, SSPL `v1` and Elastic License `2.0`.

**Named limit:** Microsoft says search indexes are [eventually consistent and need a separate ingestion pipeline](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models). Large index updates also cost more (checked Oct 2026).

[Microsoft also lists](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) a search index becoming the primary data store as an antipattern. Our read: keep the source of truth somewhere else.

## Analytical databases and data warehouses

An analytical database reads a mountain of data to answer one question, such as total sales by region over five years. [Microsoft's guide to online analytical processing (OLAP)](https://learn.microsoft.com/en-us/azure/architecture/data-guide/relational-data/online-analytical-processing) says OLAP databases are optimized for heavy-read and low-write tasks. [ClickHouse describes itself](https://clickhouse.com/docs/intro) as a column-oriented SQL database management system for online analytical processing.

BigQuery and Amazon Redshift are cloud platforms in this group. [BigQuery's docs](https://cloud.google.com/bigquery/docs/introduction) call it a fully managed serverless data warehouse. [Redshift's docs](https://docs.aws.amazon.com/redshift/latest/mgmt/welcome.html) call it a fully managed, petabyte-scale data warehouse service.

Those are the vendors' own descriptions. "Managed" does not tell you what your bill will be, so check each pricing page and run a small test on your own queries.

**Named limit:** Microsoft lists [query latency for ad-hoc work and the cost and complexity of coordinating the feeding pipelines](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) (checked Oct 2026). [AWS says](https://aws.amazon.com/compare/the-difference-between-olap-and-oltp/) most companies use online transaction processing (OLTP) and OLAP systems together. An OLTP database can be one source for an OLAP system.

In that set-up, the app that records sales sits on a relational store and the reports run on an analytical one.

## Embedded databases

An embedded database runs inside your application instead of as a separate server. [SQLite](https://www.sqlite.org/about.html) calls itself an in-process library that implements a self-contained, serverless, zero-configuration, transactional SQL database engine.

Its code is in the [public domain](https://www.sqlite.org/about.html) (checked Oct 2026). It also claims to be the most widely deployed database in the world, which we did not check.

**Named limit:** [the SQLite page](https://www.sqlite.org/about.html) says it has no separate server process. It adds, "Think of SQLite not as a replacement for Oracle but as a replacement for fopen()." So it is a file for one app. The same page lists a maximum database size of `281 terabytes` (checked Oct 2026).

## Older and niche types

Some types sound like history, but a few are still around. Hierarchical databases store data as a tree of parent and child records, and [IBM still sells one](https://www.ibm.com/products/ims), the Information Management System (IMS).

It calls IMS a high-performance hierarchical database and transaction manager for z/OS. That is a current vendor product, so hierarchical databases are not gone.

Object-oriented databases appear on [IBM's list of types](https://www.ibm.com/think/topics/database). We did not verify a current product page for any, so we name none.

Ledger databases show how fast a niche can shrink. AWS's own [Japanese-language migration post](https://aws.amazon.com/jp/blogs/news/migration-from-amazon-qldb/) says support for Amazon Quantum Ledger Database (QLDB) would end on July 31, 2025 (checked Oct 2026).

AWS's [Database Blog](https://aws.amazon.com/blogs/database/category/database/amazon-quantum-ledger-database/) posted two guides on July 18, 2024 for moving QLDB ledgers to Amazon Aurora PostgreSQL. If a list still shows QLDB as a current example, check its date.

## When one product covers several types

The labels above are useful, but products love to cross them. A database that fits one row today may add another row next year.

- **PostgreSQL** is relational, and extensions add vector search (pgvector) and time-series features (TimescaleDB).
- **Redis** lists cache, document database, vector database and streaming engine on [its docs page](https://redis.io/docs/latest/get-started/).
- **Google Spanner**, on [its overview page](https://cloud.google.com/spanner/docs/overview), says it is one database that unifies relational, graph, key-value and search, with built-in full-text and vector search and a PostgreSQL interface. Its page also headlines "always-on" and "virtually unlimited scale". Those are Google's marketing claims, and we did not test them.

![PostgreSQL, Redis and Spanner each cover more than one database type, so a single label does not decide the choice](/img/blog/2026/10/types-of-databases-labels-blur.webp)

[Microsoft's guide](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) notes that one service may support several models. It advises picking the best-fit model and not mixing models in ways that make operations harder.

So don't add a new database just because a label is missing. Check first whether the one you already run does the job well enough.

Before you rely on this, ask Google for the published limits and the service level agreement that apply to your setup. Then test each model on your own job.

## SQL vs NoSQL, in one paragraph

SQL is a query language, and NoSQL is a loose label for databases that aren't relational. [IBM defines NoSQL](https://www.ibm.com/think/topics/nosql-databases) as an approach that stores and queries data outside the traditional structures of relational databases.

[MongoDB's NoSQL explainer](https://www.mongodb.com/resources/basics/databases/nosql-explained) lists two common misconceptions. One is that NoSQL databases don't store related data well, and MongoDB says they can, for example by nesting related data in one document. The other is that NoSQL databases don't support ACID transactions, and MongoDB says some, including MongoDB, do.

So "SQL or NoSQL" is a poor first question. Ask what shape your data has and what you do with it.

## Which type should you pick?

The table below uses [Microsoft's published heuristics](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models), plus [SQLite's own description](https://www.sqlite.org/about.html) for the embedded row, with the named limits from above.

| If you mostly need | Start with | Be careful about |
| --- | --- | --- |
| Strict rules across several records | Relational | Scaling out needs sharding |
| JSON-like items that change shape | Document | Document size, narrow transactions |
| Simple lookups by key, or caching | Key-value | Limited queries, whole-value overwrites |
| Heavy, wide, write-heavy telemetry | Wide-column or time-series | Key design up front |
| Deep relationship questions | Graph | Weak at bulk scans |
| Timestamped metrics and windows | Time-series | Tag cardinality, retention cost |
| Similarity or semantic search | Vector | Recall versus speed |
| Full-text relevance | Search engine | Not a primary store |
| Reports over years of history | Analytical | Not for many small writes |
| A local file inside one app | Embedded | No shared server |

Start with a relational database when the work is strict records with rules between them, because [Microsoft's choice table](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) sends strict multi-entity transactions there. Add a specialist when an access pattern clearly diverges, as Microsoft puts it.

## When data has to move between types

With mixed types, the data has to get from one to the other. [Microsoft says](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models) most production systems use more than one storage model, so orders may live in a relational database, a cache in Redis and reports in a warehouse.

Change data capture (CDC) reads a database's own change log and copies each insert, update and delete elsewhere.

Support varies by product. [DynamoDB's docs](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Streams.html) say it streams item-level change records through DynamoDB Streams. [Cassandra's CDC feature](https://cassandra.apache.org/doc/latest/cassandra/managing/operating/cdc.html) rejects writes to a CDC-enabled table once its log reaches its configured size (checked Oct 2026).

## Where OLake Go fits

OLake Go copies a database into Apache Iceberg tables or Parquet files for analytics. [The Apache Iceberg site](https://iceberg.apache.org/) calls Iceberg an open table format for analytic datasets, so analytical engines can query the copy. That fits the pattern AWS describes above, where an OLTP database is one source for an OLAP system.

Our docs list several sources from this post: the relational databases [PostgreSQL](/docs/connectors/postgres/), [MySQL](/docs/connectors/mysql/), [SQL Server](/docs/connectors/mssql/), [Oracle](/docs/connectors/oracle/) and [Db2](/docs/connectors/db2/), and the document database [MongoDB](/docs/connectors/mongodb/). See the [sources and sync modes table](/docs/). All of them support full refresh and full refresh plus incremental sync. CDC (full refresh plus CDC, or CDC only) works for Postgres, MySQL and MariaDB, MongoDB and SQL Server.

OLake Go writes Iceberg tables to catalogs such as AWS Glue, Hive Metastore, JDBC (Java Database Connectivity) and REST (web API) catalogs (Nessie, Polaris, Unity, Lakekeeper, BigLake, S3 Tables and [Snowflake Horizon](/docs/writers/iceberg/catalog/rest/?rest-catalog=horizon), v0.11.0 and later). It can also write Parquet files. See our [catalog compatibility page](/docs/understanding/compatibility-catalogs/). You run OLake Go yourself, and the [quickstart](/docs/getting-started/quickstart/) shows the first sync.

## Why other lists give different counts

We read several top-ranking pages. These differences explain why the counts vary.

- [IBM](https://www.ibm.com/think/topics/database) and [Matillion](https://www.matillion.com/blog/the-types-of-databases-with-examples) count "cloud" databases as a type. We treat that as a deployment style, not a data model.
- Time-series databases and search engines are missing from IBM's list of types, even though [Microsoft treats each as its own category](https://learn.microsoft.com/en-us/azure/architecture/data-guide/technology-choices/understand-data-store-models).
- [AlgoMaster's list](https://blog.algomaster.io/p/15-types-of-databases) names Amazon QLDB as a ledger example, though [AWS announced](https://aws.amazon.com/jp/blogs/news/migration-from-amazon-qldb/) that QLDB support would end on July 31, 2025 (checked Oct 2026).

## Conclusion

Ask two questions. What shape is the data, and what do you do with it?

Relational suits records with rules between them, such as orders and billing, and that is where Microsoft's choice table starts. Each specialist type earns its place at one job and carries one named limit, so read that limit before you commit.

Treat labels as hints. PostgreSQL, Redis and Spanner already cross them, and licences vary, as Redis, MongoDB and Elasticsearch show. Check the vendor's own page before you sign anything.
