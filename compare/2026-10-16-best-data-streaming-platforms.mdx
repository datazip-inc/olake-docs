There's no single best data streaming platform. ## What a data streaming platform is

Picture a conveyor belt that never stops, with a notebook beside it that writes down everything that passes. That's a data streaming platform: software that takes in a continuous flow of events, stores them, and lets other programs read them in order. The notebook is called a log, an ordered list of events that readers can replay from any point still kept.

Most platforms split that log into topics (named channels) and spread each topic across partitions (parallel lanes), so many machines share the work. A broker is a server that holds part of the log. Producers write events in, and consumers read them out.

It isn't a database or a batch tool.

## What to check before you choose

Five questions cut the list fast; the first two do most of the cutting.

1. **Who will run it?** Your team, a vendor, or your cloud provider.
2. **Which API does your code use?** The Kafka API, or another interface.
3. **How long must events stay replayable?** Pub/Sub topics stop at `31 days` and Kinesis at `365 days`.
4. **Where must the data live?** One cloud, several clouds, or inside your own account.
5. **Where do events go next?** Some platforms write Iceberg tables, with limits listed below, and OLake Go can read a Kafka topic into Iceberg (see where OLake Go fits).

## The 10 best data streaming platforms

### Platforms that speak the Kafka API

The Kafka API is the set of commands Kafka programs use to write and read events. The platforms in this group say they support it, and Microsoft says existing Kafka code can often use the Event Hubs endpoint after a settings change.

![Self-run platforms put sizing and patching on your team, while managed services bill by usage and run the brokers](/img/blog/2026/10/best-data-streaming-platforms-who-runs-it.webp)

#### 1. Apache Kafka: for teams that want full control

**At a glance**
- Run by: You, on servers, containers or in the cloud
- Price: No licence fee, you pay for machines and staff

Kafka is the open-source project whose API most of the platforms here copy. By the project's own account ([its intro page](https://kafka.apache.org/intro)) it does three things: publish and subscribe to streams of events, store them durably, and process them. Its [downloads page](https://kafka.apache.org/community/downloads/) (checked Oct 2026) lists `4.3.1`, `4.2.2` and `4.1.2` as supported releases and says the project ships a release about every four months.

**What's good**

- No licence fee ([Apache License 2.0](https://raw.githubusercontent.com/apache/kafka/trunk/LICENSE) (checked Oct 2026)). The [Kafka intro page](https://kafka.apache.org/intro) says you can run it on bare-metal hardware, virtual machines and containers, on premises or in the cloud, either self-managed or through fully managed services from a variety of vendors.
- Kafka Connect continuously imports and exports data as event streams to link Kafka with existing systems such as relational databases, and the same page says the community already provides hundreds of ready-to-use connectors.
- Events are not deleted after consumption, so they "can be read as often as needed", and retention is a per-topic setting. Each partition is read in the order its events were written, and a replication factor of `3` is named as a common production setting.
- The [Kafka design page](https://kafka.apache.org/42/design/design/) says the producer has had an idempotent delivery option since `0.11.0.0`, so resending does not create duplicate log entries, and that exactly-once delivery is supported in Kafka Streams and, with a transactional producer and a read-committed consumer, when reading, processing and writing Kafka topics.
- Consumers pull, so a slow one "simply falls behind and catches up when it can". Share groups let a group have more consumers than a topic has partitions, with records acknowledged one by one.

**Where it falls short**

- The [Kafka intro page](https://kafka.apache.org/intro) describes Kafka Connect, not the brokers, as the part that imports data from systems such as relational databases, and it describes no Iceberg writer. So those jobs come from add-on connectors, vendor features or a reader such as OLake Go, which reads Kafka topics into Iceberg or Parquet (see our [Kafka docs](/docs/connectors/kafka/)). To read database changes into Iceberg without Kafka, see our [comparison of the options](/compare/database-to-iceberg-without-kafka/).
- Your team owns upgrades, sizing and failures, all of it.
- Defaults need a look. Per the [Kafka broker config docs](https://kafka.apache.org/42/configuration/broker-configs/) (checked Oct 2026), `default.replication.factor` is `1` for automatically created topics, `log.retention.hours` is `168` (seven days) and `message.max.bytes` is `1048588`, about 1 MB.
- Delivery is at-least-once by default. At-most-once means disabling producer retries and committing offsets before processing.
- Exactly-once into outside systems takes extra work: the [design page](https://kafka.apache.org/42/design/design/) says many output systems will not support a two-phase commit, so the consumer may have to store its offset in the same place as its output.
- Patch releases carry real fixes. The [Kafka downloads page](https://kafka.apache.org/community/downloads/) says `4.3.1` fixed "a critical Kafka Streams RocksDB native memory leak (KAFKA-20616)" and about 15 other issues, so running Kafka means tracking releases like this.

**What users say:** One Hacker News commenter on "Kafka is Fast" (October 2025) [wrote](https://news.ycombinator.com/item?id=45748198) "self-managing kafka is a job in of itself". [Another](https://news.ycombinator.com/item?id=44747082) on the Ursa thread (July 2025) called Kafka "one of the pieces of software that has been rock solid for me".

#### 2. Confluent Cloud: for Kafka without running servers

**At a glance**
- Run by: Confluent, on AWS, Azure and Google Cloud
- Price: Basic from $0 a month, Standard about $385, Enterprise about $895

Confluent's [docs overview](https://docs.confluent.io/cloud/current/overview.html) describes Confluent Cloud as a fully managed Kafka service.

Confluent's [press release](https://www.confluent.io/press-release/ibm-completes-acquisition-of-confluent/) of March 17, 2026 says International Business Machines (IBM) completed its acquisition of Confluent. The [pricing page](https://www.confluent.io/confluent-cloud/pricing/) (checked Oct 2026) lists those three starting monthly figures for cluster tiers. It also says prices vary by cloud region.

Confluent also sells ready-made connectors, and says its Tableflow feature turns Kafka topics into Apache Iceberg or Delta Lake tables.

**What's good**

- Its [Tableflow docs](https://docs.confluent.io/cloud/current/topics/tableflow/overview.html) (the overview page) say Tableflow materializes Kafka topics or Flink tables as Iceberg or Delta Lake tables, publishes new data to a table approximately every `5 minutes`, and compacts and cleans up small files for you.
- The same docs list a built-in Iceberg REST catalog plus catalog integration with AWS Glue, Databricks Unity, Apache Polaris and Snowflake Open Catalog, and say you can use your own storage on Amazon S3, Azure or Google Cloud Storage.
- With Confluent Cloud for Apache Flink you can filter, deduplicate, remove personally identifiable information (PII) and join streams on topics that Tableflow then materializes.
- Its [connectors page](https://docs.confluent.io/cloud/current/connectors/overview.html) says Confluent offers "120+ pre-built connectors" (open source or community, commercial and premium, plus partner-verified ones), and lists Debezium change capture connectors for MongoDB, MySQL, PostgreSQL and SQL Server. Its [pricing page](https://www.confluent.io/confluent-cloud/pricing/) (checked Oct 2026) says connectors are billed per task-hour and per GB.
- The [pricing page](https://www.confluent.io/confluent-cloud/pricing/) (checked Oct 2026) feature table lists uptime SLAs of 99.5% for Basic, 99.9% or 99.99% for Standard and Enterprise (depending on eCKU count) and 99.99% for Freight.
- The [same table](https://www.confluent.io/confluent-cloud/pricing/) (checked Oct 2026) lists throughput in and out of `250` and `750` MBps for Basic and Standard, `1,920` and `5,760` MBps for Enterprise, and `9,120` and `27,360` MBps for Freight.

**Where it falls short**

- The bill has lots of moving parts: cluster, network, storage, connectors and Flink. Confluent's [billing dimensions page](https://docs.confluent.io/cloud/current/billing/billing-dimensions.html) (checked Oct 2026) says a cluster unit (an eCKU) is billed per hour at the maximum used in that hour (usage between 2 and 3 eCKUs bills as 3), and storage is charged after replication, so billed storage is typically about 3x the volume written.
- Confluent charges for all data transfers, including requests the Cloud Console makes to show messages in the message browser, and ingress and egress charges are multiplied by a regional multiplier. A paused managed connector keeps accruing hourly task costs ([billing dimensions](https://docs.confluent.io/cloud/current/billing/billing-dimensions.html) (checked Oct 2026)).
- The [Tableflow overview](https://docs.confluent.io/cloud/current/topics/tableflow/overview.html) says Tableflow is not available for Confluent Platform (the self-managed product). Tableflow has its own meters (topic hours, data processed and storage on the [billing dimensions page](https://docs.confluent.io/cloud/current/billing/billing-dimensions.html)), and neither the [Tableflow billing docs](https://docs.confluent.io/cloud/current/topics/tableflow/concepts/tableflow-billing.html) nor the [pricing page](https://www.confluent.io/confluent-cloud/pricing/) we read shows a dollar rate (checked Oct 2026).
- The [Tableflow overview](https://docs.confluent.io/cloud/current/topics/tableflow/overview.html) lists these limits: schemaless topics are not supported (the key and the value must both have a schema), retract tables are not supported, and Confluent Cloud for Apache Flink cannot query Iceberg tables.
- The [same overview](https://docs.confluent.io/cloud/current/topics/tableflow/overview.html) says tables are exposed read-only and that only topics using custom storage sync to external catalogs.
- It also says Tableflow keeps between `10` and `100` snapshots, not user-configurable, and that once a topic is enabled with custom storage, changing the bucket is not supported ([Tableflow overview](https://docs.confluent.io/cloud/current/topics/tableflow/overview.html)).

#### 3. Amazon MSK: for AWS teams that already use Kafka

**At a glance**
- Run by: AWS
- Price: Standard broker $0.21 an hour for a `kafka.m5.large`, plus $0.10 per GB-month of storage (US East, N. Virginia)

AWS says Amazon MSK runs open-source Kafka and that your existing applications and tools work without code changes. The [MSK pricing page](https://aws.amazon.com/msk/pricing/) (checked Oct 2026) lists three styles: Standard brokers, Express brokers ($0.408 an hour for an `msk.m7g.large` in US East, N. Virginia, plus $0.01 per GB ingested) and Serverless ($0.75 per cluster-hour plus per-partition and per-GB charges, US East, Ohio).

**What's good**

- AWS's [MSK developer guide](https://docs.aws.amazon.com/msk/latest/developerguide/what-is-msk.html) says MSK "runs open-source versions of Apache Kafka", and that existing applications, tooling and plugins from partners and the Apache Kafka community work without changes to application code.
- Provisioned clusters offer two broker types, Standard and Express, and in MSK Serverless AWS manages the broker nodes. KRaft controllers are included at no additional cost.
- It names MSK Connect for streaming data to and from your cluster and MSK Replicator for replicating data across MSK Provisioned clusters, in the same or different Regions. MSK Connect is billed in units of 1 vCPU and 4 GB of memory at one-second resolution, $0.11 per hour per unit in AWS's US East (N. Virginia) example ([pricing page](https://aws.amazon.com/msk/pricing/) (checked Oct 2026)).
- The [pricing page](https://aws.amazon.com/msk/pricing/) (checked Oct 2026) says you are not charged for data transfer used for replication between brokers or between metadata nodes and brokers.
- Per the [MSK quotas page](https://docs.aws.amazon.com/msk/latest/developerguide/limits.html) (checked Oct 2026), Express brokers have unlimited maximum storage and up to `15 MB/s` per partition, and MSK Serverless retention is unlimited.
- Its [streaming tables docs](https://docs.aws.amazon.com/msk/latest/developerguide/msk-data-delivery-iceberg.html) (checked Oct 2026) say Kafka topics are continuously materialized as Apache Iceberg tables on Amazon S3 Tables, with freshness set between `5` and `15` minutes, at $10.00 per TB delivered and no extra charge for inline compaction.

**Where it falls short**

- In Provisioned mode you still pick broker types and counts, with a minimum of one broker per Availability Zone.
- Amazon MSK is an AWS service (the [MSK developer guide](https://docs.aws.amazon.com/msk/latest/developerguide/what-is-msk.html) calls it a fully managed service from AWS), so teams on other clouds need a different option.
- MSK Serverless has per-cluster caps of `200 MBps` in and `400 MBps` out, per-partition caps of `5 MBps` in and `10 MBps` out, a maximum message size of `8 MiB` and `2,400` partitions for non-compacted topics ([MSK quotas](https://docs.aws.amazon.com/msk/latest/developerguide/limits.html) (checked Oct 2026)).
- Standard brokers top out at `60` brokers per KRaft-based cluster and `16,384 GiB` of storage per broker ([MSK quotas](https://docs.aws.amazon.com/msk/latest/developerguide/limits.html) (checked Oct 2026)).
- The [MSK streaming tables docs](https://docs.aws.amazon.com/msk/latest/developerguide/msk-data-delivery-iceberg.html) say they need Express brokers (Standard brokers and MSK Serverless are not supported). They deliver to S3 Tables in the same Region, cross-account delivery is not supported, and they need a dead-letter queue bucket and JSON data with an AWS Glue Schema Registry schema.
- The [same docs](https://docs.aws.amazon.com/msk/latest/developerguide/msk-data-delivery-iceberg.html) say a streaming tables channel does not backfill earlier data, and that it creates a new Iceberg table for each configuration because delivery to existing Iceberg tables is not supported.

**What users say:** A Hacker News commenter on "What's your go-to message queue in 2025?" (May 2025) [wrote](https://news.ycombinator.com/item?id=44006992) that, with Confluent Cloud and Amazon MSK, "infra is relatively trivial to maintain".

#### 4. Redpanda: for the Kafka API in a single program

**At a glance**
- Run by: You, or Redpanda (Serverless or bring your own cloud)
- Price: Serverless is pay as you go or annual commit, with a "Start for free" sign-up; BYOC needs an annual commitment

Redpanda says producers and consumers use the Apache Kafka API, and that it comes packaged as a single binary with no outside systems to wire up.

The [pricing page](https://www.redpanda.com/pricing) (checked Oct 2026) lists three plans. Serverless allows up to `100 MB/s` of writes with a 99.9% service level agreement (SLA), which is the uptime promise in the contract. Bring your own cloud (BYOC) allows `2 GB/s` with 99.99%, and a self-managed Enterprise Edition has a 30-day trial.

**What's good**

- Serverless is multi-tenant on AWS and GCP, with pay as you go or an annual commit plan. The [pricing page](https://www.redpanda.com/pricing) (checked Oct 2026) lists `100 MB/s` write, `300 MB/s` read and `5,000` partitions.
- BYOC runs fully managed Redpanda clusters in your own VPC on AWS, GCP or Azure, and the [page](https://www.redpanda.com/pricing) (checked Oct 2026) lists `2 GB/s` write, `4 GB/s` read and `112,500` partitions. The Enterprise Edition is the run-it-yourself option, with a 30-day trial.
- Per Redpanda's [licensing docs](https://docs.redpanda.com/current/get-started/licensing/overview/) (checked Oct 2026), every new cluster gets a 30-day trial license, and after a trial or license expires the cluster keeps operating without data loss while enterprise features are restricted.
- Its [Iceberg topics docs](https://docs.redpanda.com/current/manage/iceberg/about-iceberg-topics/) say brokers store topic data as Parquet files in an Iceberg-compatible format in object storage, with the catalog in the same bucket or an Iceberg REST catalog endpoint, and that the feature requires an enterprise license (checked Oct 2026).
- The same docs describe per-topic Iceberg modes: `key_value` (a key column and a binary value column), `value_schema_id_prefix` (matches the topic's Redpanda schema) and `value_schema_latest` (matches the latest schema in the Schema Registry). The default is `disabled`.

**Where it falls short**

- Dollar rates weren't in the [pricing page](https://www.redpanda.com/pricing) text we read, so we can't quote them, and the SLA figures are Redpanda's own promises (ask for the contract terms).
- Iceberg topics need an enterprise license and Tiered Storage ([Iceberg topics docs](https://docs.redpanda.com/current/manage/iceberg/about-iceberg-topics/)) on the topics that generate tables. The [pricing page](https://www.redpanda.com/pricing) (checked Oct 2026) lists them under BYOC and Enterprise Edition, not in the Serverless feature list, and shows no Iceberg-specific rate, so ask Redpanda which plan includes them.
- Enabling Iceberg on an existing topic does not backfill the table, and topic data cannot be appended to an existing Iceberg table that Redpanda did not create ([Iceberg topics docs](https://docs.redpanda.com/current/manage/iceberg/about-iceberg-topics/)).
- The [Iceberg topics page](https://docs.redpanda.com/current/manage/iceberg/about-iceberg-topics/) we read does not describe compaction, upsert or delete handling.
- BYOC needs an annual commitment, with a 14-day trial available by contacting Redpanda ([pricing page](https://www.redpanda.com/pricing) (checked Oct 2026)).
- JSON schemas for Iceberg topics are supported starting with Redpanda version `25.2` ([Iceberg topics docs](https://docs.redpanda.com/current/manage/iceberg/about-iceberg-topics/)).

**What users say:** A Hacker News commenter on "IBM to acquire Confluent" (December 2025) [wrote](https://news.ycombinator.com/item?id=46194417) "RedPanda was a huge win for us".

Redpanda's [licensing docs](https://docs.redpanda.com/current/get-started/licensing/overview/) (checked Oct 2026) say the free Community Edition uses the Business Source License, which is source-available and not Apache 2.0. You can't offer Redpanda as a commercial streaming service to others, and the code converts to Apache 2.0 four years after each merge.

#### 5. WarpStream: for Kafka that stores data in your own bucket

**At a glance**
- Run by: Your cloud account for data, WarpStream's cloud for control
- Price: Billed by cluster tier and by Tableflow usage on its pricing page

WarpStream's [Tableflow launch blog post](https://www.warpstream.com/blog/the-case-for-an-iceberg-native-database-why-spark-jobs-and-zero-copy-kafka-wont-cut-it) calls it a drop-in replacement for Apache Kafka, built on object storage. Confluent's [press release](https://www.confluent.io/press-release/confluent-acquires-warpstream-to-advance-next-gen-byoc-data-streaming/) of September 9, 2024 says Confluent acquired WarpStream.

WarpStream says its Tableflow product turns Kafka topics into Iceberg tables too. The [Tableflow docs](https://docs.warpstream.com/warpstream/tableflow/tableflow) (checked Oct 2026) say it currently supports append-only tables, and that you cannot use another system to write or maintain those tables.

**What's good**

- The docs say compaction and table maintenance are "included out-of-the-box with no tuning required".
- Its [Tableflow product page](https://www.warpstream.com/tableflow) says Tableflow works with any Kafka-compatible source (open-source Kafka, MSK, Confluent Cloud, WarpStream) and can ingest from several Kafka clusters at once. It says raw data is processed on your VMs and stored in your object storage buckets.
- On the [pricing page](https://www.warpstream.com/pricing) (checked Oct 2026), BYOC keeps the data plane in your cloud account and the control plane in WarpStream's, and new users get "$400 in non-expiring credits" with no credit card.
- The [same page](https://www.warpstream.com/pricing) (checked Oct 2026) publishes usage rates: Kafka write throughput from $0.01 per GiB and Tableflow write throughput from $0.04 per GiB for the first 50 TiB a month (uncompressed).
- The [docs](https://docs.warpstream.com/warpstream/tableflow/tableflow) say schema migrations follow Iceberg schema evolution rules, covering added columns, required fields made optional, and widened integer and floating point types. Inline schema mode supports JSON, Avro and Protobuf.
- By default data is ingested from the start of the topic, and a `start_ingestion_at: latest` setting skips what is already there.

**Where it falls short**

- Rows from a compacted source topic are not deduplicated and tombstones may not comply with the schema. Compacted topic support is "coming soon" in the [docs](https://docs.warpstream.com/warpstream/tableflow/tableflow).
- A Tableflow cluster is separate from a WarpStream Kafka cluster, because Tableflow agents "only perform Tableflow operations and do not expose the Apache Kafka protocol" ([Tableflow docs](https://docs.warpstream.com/warpstream/tableflow/tableflow)).
- Reordering, renaming and removing a column are not supported as in-place migrations ([Tableflow docs](https://docs.warpstream.com/warpstream/tableflow/tableflow)).
- A table can have at most `5` sort fields ("Contact support if you need a higher limit", per the [Tableflow docs](https://docs.warpstream.com/warpstream/tableflow/tableflow)).
- Neither the [Tableflow docs page](https://docs.warpstream.com/warpstream/tableflow/tableflow) nor the [product page](https://www.warpstream.com/tableflow) states a delivery guarantee such as exactly-once.
- Billing has several meters (from the [pricing page](https://www.warpstream.com/pricing) (checked Oct 2026)): Tableflow cluster minutes are billed in 15-minute increments for any interval in which the cluster receives requests, and the 99.999% uptime tier needs Multi-Region Clusters. We didn't compare cluster rates, because its units differ from Confluent's.

**What users say:** Independent discussion is thin, so take this with salt. A [Hacker News commenter](https://news.ycombinator.com/item?id=47137744) (2026) said "we've seen great improvements over traditional Kafka".

### Cloud services with no stated Kafka API

#### 6. Amazon Kinesis Data Streams: for AWS-only teams

**At a glance**
- Run by: AWS
- Price: On-demand $0.08 per GB in and $0.04 per GB out, plus $0.04 per stream-hour (US East, Ohio)

AWS says Kinesis Data Streams collects and processes large streams of records in real time. Its [pricing page](https://aws.amazon.com/kinesis/data-streams/pricing/) (checked Oct 2026) lists On-demand Standard at $0.08 per GB in, $0.040 per GB out and $0.040 per stream-hour (US East, Ohio). AWS says it may suit you if you prefer not to manage capacity. Provisioned mode bills $0.015 per shard-hour, where one shard carries `1 MB/s` in and `2 MB/s` out.

Per the [Kinesis quotas page](https://docs.aws.amazon.com/streams/latest/dev/service-sizes-and-limits.html) (checked Oct 2026), records can be up to `10 MiB` and are kept from `24 hours` to `365 days`.

**What's good**

- The [Kinesis introduction page](https://docs.aws.amazon.com/streams/latest/dev/introduction.html) says the put-to-get delay is "typically less than 1 second".
- Producers push data directly into a stream. AWS gives the example of two applications reading the same stream, one updating an Amazon DynamoDB table and the other archiving to a store such as Amazon S3.
- A record payload can be up to `10 MiB` before base64 encoding, and retention runs from `24 hours` to `365 days` ([quotas page](https://docs.aws.amazon.com/streams/latest/dev/service-sizes-and-limits.html) (checked Oct 2026)).
- New on-demand streams start at `4 MB/s` write and `8 MB/s` read. In US East (N. Virginia), US West (Oregon) and Europe (Ireland) they scale up to `10 GB/s` write and `20 GB/s` read, and elsewhere to `200 MB/s` and `400 MB/s` ([quotas page](https://docs.aws.amazon.com/streams/latest/dev/service-sizes-and-limits.html) (checked Oct 2026)).
- AWS's [pricing page](https://aws.amazon.com/kinesis/data-streams/pricing/) (checked Oct 2026) describes it as a fully managed, serverless streaming data service. On-demand Advantage uses lower per-GB rates in its US East example ($0.032 ingested, $0.016 retrieved) with no fixed stream-hour charge, and AWS says it might suit you with at least `10 MB/s` of ingest in aggregate.
- Its [data delivery docs](https://docs.aws.amazon.com/streams/latest/dev/data-delivery.html) describe streaming tables on Apache Iceberg with freshness configurable from `5` to `15` minutes, and say records from a shard are delivered exactly once, with no duplicates or omissions within the shard.

**Where it falls short**

- AWS's [pricing page](https://aws.amazon.com/kinesis/data-streams/pricing/) (checked Oct 2026) says Amazon Kinesis Data Streams is "NOT currently available in AWS Free Tier".
- The [Kinesis pages](https://docs.aws.amazon.com/streams/latest/dev/introduction.html) we read do not mention Kafka API support, and the [quotas page](https://docs.aws.amazon.com/streams/latest/dev/service-sizes-and-limits.html) (checked Oct 2026) lets each stream register up to `20` enhanced fan-out readers in most modes (`50` in On-demand Advantage).
- In provisioned mode each shard supports up to `1 MB/sec` or `1,000 records/sec` of writes and `2 MB/sec` or `2,000 records/sec` of reads. By default you can create up to `50` on-demand streams ([quotas page](https://docs.aws.amazon.com/streams/latest/dev/service-sizes-and-limits.html) (checked Oct 2026)).
- Provisioned mode charges extra for retention: $0.020 per shard-hour for extended retention and $0.023 per GB-month beyond seven days, and enhanced fan-out retrieval is $0.013 per GB ([pricing page](https://aws.amazon.com/kinesis/data-streams/pricing/) (checked Oct 2026) examples).
- On-demand Advantage has (per the [pricing page](https://aws.amazon.com/kinesis/data-streams/pricing/) (checked Oct 2026)) a minimum charge of `25 MB/s` ingested and `25 MB/s` retrieved at account level across all on-demand streams.
- Streaming tables and Amazon S3 delivery are not supported in provisioned mode ([data delivery docs](https://docs.aws.amazon.com/streams/latest/dev/data-delivery.html)). They need a dead-letter queue in Amazon S3, and the stream, the S3 table bucket and the AWS Glue Schema Registry must be in the same account and Region.

**What users say:** One [PeerSpot reviewer](https://www.peerspot.com/products/amazon-kinesis-reviews) (October 2025) gave stability a 10, saying "We have never had any stability issues", but the same review said "We are contemplating moving away from Amazon Kinesis primarily because of the cost."

#### 7. Azure Event Hubs: for Azure teams, including Kafka clients

**At a glance**
- Run by: Microsoft
- Price: Throughput units (Basic, Standard), processing units (Premium), capacity units (Dedicated); we could not read dollar rates, so check the live page

Microsoft [calls Event Hubs](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-about) a fully managed, real-time data streaming platform that supports the Kafka, HTTPS and Advanced Message Queuing Protocol (AMQP) `1.0` protocols. Its Capture feature writes events to Azure Blob Storage or Data Lake Storage.

**What's good**

- Microsoft's [Event Hubs overview](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-about) (checked Oct 2026) states an SLA of up to 99.99%, and retention of up to `90 days` on Premium and Dedicated.
- It lists native integration with Stream Analytics, Azure Functions and Data Explorer, and says the ecosystem also supports Azure Spring Apps, Kafka Connectors, Apache Spark and Apache Flink.
- Microsoft's [Event Hubs for Apache Kafka overview](https://learn.microsoft.com/en-us/azure/event-hubs/azure-event-hubs-apache-kafka-overview) says you can often use the Kafka endpoint without code changes, modifying only the configuration, and that Apache Kafka version `1.0` and later is supported.
- Events up to `20 MB` are supported with dedicated clusters, listed as large message support (preview) ([Event Hubs overview](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-about) (checked Oct 2026)).

**Where it falls short**

- The Kafka endpoint needs Standard or higher, and Kafka Streams and transactions are public previews on Premium and Dedicated ([Kafka overview](https://learn.microsoft.com/en-us/azure/event-hubs/azure-event-hubs-apache-kafka-overview) (checked Oct 2026)).
- Kafka compression is supported only in Premium and Dedicated, and the `compression.type` setting accepts `none` or `gzip` ([Kafka overview](https://learn.microsoft.com/en-us/azure/event-hubs/azure-event-hubs-apache-kafka-overview) (checked Oct 2026)).
- Delivery is at least once, so a consumer can see the same event twice. Your code has to cope with that, and Microsoft's [docs](https://learn.microsoft.com/en-us/azure/event-hubs/azure-event-hubs-apache-kafka-overview) call for the idempotent consumer pattern.
- On Standard, retention tops out at `7 days`, so replay beyond a week means Premium or Dedicated ([Event Hubs overview](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-about) (checked Oct 2026)).
- Capture writes to Azure Blob Storage or Data Lake Storage, and the [pages we read](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-about) do not describe an Iceberg writer.

#### 8. Google Cloud Pub/Sub: for Google Cloud apps that need messaging

**At a glance**
- Run by: Google
- Price: First 10 GiB a month free, then $40 per TiB, in all regions

Google [describes Pub/Sub](https://docs.cloud.google.com/pubsub/docs/overview) as an asynchronous and scalable messaging service that decouples the programs that produce messages from the ones that process them. A GiB (gibibyte) is about 1.07 billion bytes, and a TiB is 1,024 GiB. The throughput rate is on the Pub/Sub pricing page (linked under the storage figure below), and import topics and export subscriptions are priced separately ([pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026)).

**What's good**

- A free monthly allowance, and per-use billing with no servers or capacity to set. The first 10 GiB each month is free and the price after that is $40 per TiB in all Google Cloud regions ([pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026)).
- Google's [Pub/Sub overview](https://docs.cloud.google.com/pubsub/docs/overview) says latencies are "typically on the order of 100 milliseconds".
- It offers push-based delivery of messages as HTTP POST requests to webhooks.
- Google describes using a stream processing tool such as Dataflow to deliver events to BigQuery, Bigtable and Cloud Storage.
- BigQuery and Cloud Storage subscriptions read from a subscription and write straight to those stores, at $50 per TiB in all Google Cloud regions ([pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026)).

**Where it falls short**

- Per the [quotas page](https://docs.cloud.google.com/pubsub/quotas) (checked Oct 2026), a topic can keep messages for at most `31 days` when retention is turned on, a subscription keeps unacknowledged messages for `7 days` by default, and a message can be up to `10 MB`.
- Publisher throughput defaults to `4 GB/s` per region in the seven regions the page calls large (`europe-west1`, `europe-west4`, `us-central1`, `us-east1`, `us-east4`, `us-west1` and `us-west2`) ([quotas page](https://docs.cloud.google.com/pubsub/quotas) (checked Oct 2026)).
- When a topic is set to retain messages, the [Pub/Sub pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026) lists storage at $0.27 per GiB-month.
- A minimum of `1 KB` is billed for each request whatever the message size, so batching small messages is cheaper ([pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026)).
- The first 10 GiB of BigQuery and Cloud Storage subscription throughput is not free, and import topics and export subscriptions are priced separately ([pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026)).
- We found no Kafka protocol statement on the [pages we read](https://docs.cloud.google.com/pubsub/docs/overview), so assume your Kafka code needs changes. They also describe no self-hosted option and no Iceberg writer.

**What users say:** Recent independent discussion is thin. One older [Hacker News comment](https://news.ycombinator.com/item?id=38629762) (December 2023, on a thread about Google cancelling storage) said "PubSub was actually pretty nice" despite lock-in worries.

Google defines throughput as bytes written to a topic plus bytes read from a subscription, so one message read by one subscription is billed twice ([pricing page](https://cloud.google.com/pubsub/pricing) (checked Oct 2026)).

**What's good**

- Subscription types are `exclusive`, `shared`, `failover` and `key_shared`, and the docs list native transactions for atomic operations across topics and partitions.

- The client API has bindings for Java, Go, Python, C++, C#/.NET, Node.js and WebSocket.
- Pulsar Functions is described as a serverless lightweight framework for stream-native processing, and Pulsar IO as a serverless connector framework built on it.
- The [Pulsar IO connector docs](https://pulsar.apache.org/docs/next/io-connectors/) list source connectors including Debezium MySQL, PostgreSQL, MongoDB, Oracle and SQL Server, DynamoDB, Kafka, Kinesis and RabbitMQ.

**Where it falls short**

- The [Pulsar download page](https://pulsar.apache.org/download/) (checked Oct 2026) lists `5.0` (LTS) as the latest version, released October 5, 2026, with active support until October 5, 2028. The `4.0` LTS line's active support ended on October 21, 2026, and its security support runs until October 21, 2027.
- You run it, and we didn't cover managed versions from vendors. The [Pulsar architecture docs](https://pulsar.apache.org/docs/next/concepts-architecture-overview/) describe brokers, a BookKeeper cluster of bookies for persistent storage, and a metadata store cluster ("Oxia, ZooKeeper, or other supported backend").
- Kafka protocol compatibility is not stated on the [architecture page](https://pulsar.apache.org/docs/next/concepts-architecture-overview/).
- Connectors live in a separate repository with their own release cycle, and the server distribution and Docker image do not bundle them ([IO connectors page](https://pulsar.apache.org/docs/next/io-connectors/)).
- The [IO connectors page](https://pulsar.apache.org/docs/next/io-connectors/) does not name an Iceberg source or sink connector.

**What users say:** A Hacker News commenter on "Kafka is Fast - I'll use Postgres" (October 2025) [liked that](https://news.ycombinator.com/item?id=45757539) it is "easy to setup and requires almost no maintenance". ### A worked cost example

Take one steady workload: 1,000 GB written in a month, read once by one application, in records of 1 KB each. We use a 730-hour month and the rates quoted above, so treat the results as a sketch (and we ignore the roughly 7% gap between GB and GiB).

## Where OLake Go fits

OLake Go, our open-source tool, reads Kafka topics and writes them to Apache Iceberg or Parquet (see our [Kafka docs](/docs/connectors/kafka/)). It needs Kafka `2.4.0` or later and reads JSON or Avro messages (Avro needs a Confluent Schema Registry). It was tested with Amazon MSK and uses standard Kafka protocols, so other Kafka distributions should work. Each topic can run in Append or Upsert mode. Upsert mode as a whole needs OLake Go `0.12.1` and OLake UI `0.7.1` or later. It uses a deduplication key, and when that key is `_kafka_key`, a message with a null value deletes the matching row. A topic pattern, which is a regular expression, limits which topics are discovered.

The Kafka source has one synchronization mode, and OLake Go cannot sync messages Kafka has already deleted, so run syncs more often than your topic's retention period. It adds `_kafka_key`, `_kafka_offset`, `_kafka_partition` and `_kafka_timestamp` columns to each row, and it works with [eleven Iceberg catalog types](/docs/understanding/compatibility-catalogs/). You run it yourself, from the [OLake UI](/docs/install/olake-ui/), the [Docker CLI](/docs/install/docker-cli/) or [Kubernetes with Helm](/docs/install/kubernetes/) (see the [quickstart](/docs/getting-started/quickstart/)). Each job runs on a schedule you set in the UI, from every minute to a cron expression ([job settings](/docs/getting-started/job-level-properties/)).

If your events start in a database instead of a topic, OLake Go also reads [Postgres](/docs/connectors/postgres/), [MySQL/MariaDB](/docs/connectors/mysql/), [MongoDB](/docs/connectors/mongodb/) and [SQL Server](/docs/connectors/mssql/) with change capture (CDC). It writes straight to Iceberg or Parquet, with no Kafka in between. See our [comparison of the options](/compare/database-to-iceberg-without-kafka/).
