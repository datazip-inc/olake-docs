<TLDR title='Key takeaways'>

The big Snowflake competitors are Databricks, Google BigQuery, Amazon Redshift and Microsoft Fabric, and the right one mostly follows the cloud and the skills you already have. Pick Databricks if your team writes code and trains models. Pick BigQuery if you live on Google Cloud, Redshift if you live on AWS, and Fabric if Power BI (Microsoft's reporting tool) runs your reporting.

ClickHouse, MotherDuck, Dremio and Amazon Athena are aimed at narrower jobs. Prices don't line up one to one because the billing units differ.

- **The options bill in different units.** Snowflake sells credits, Databricks sells Databricks Units (DBU), BigQuery bills per tebibyte (TiB) scanned, Redshift Serverless per Redshift Processing Unit (RPU) hour, and Dremio per Dremio Compute Unit.
- **Apache Iceberg lowers the cost of leaving.** Most of these options document a way to read Iceberg tables in your own storage, each with limits.
- **OLake Go can fill the tables.** It copies database data into Iceberg tables that several of these engines read, and into Snowflake itself through the Snowflake Horizon Catalog. See [Where OLake Go fits](#where-olake-go-fits).

</TLDR>

Every price below comes from the vendor's own page, read in October 2026, and we name the page next to the number. If a vendor doesn't publish a price, we say "not published" and leave it there.

## Why teams look past Snowflake

Snowflake is a cloud data warehouse that runs on Amazon Web Services, Microsoft Azure and Google Cloud, according to its Service Consumption Table. Its pricing page describes consumption-based pricing, and that's where most of the friction starts.

You pay in credits, and what a credit costs depends on your edition and region. On AWS US East (Northern Virginia) a credit costs $2.00 on Standard, $3.00 on Enterprise and $4.00 on Business Critical, per Snowflake's [Service Consumption Table](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf) effective October 2, 2026. In AWS EU Frankfurt the same editions cost $2.60 and $3.90 for Standard and Enterprise.

Then there's the warehouse size. It sets how many credits you burn per hour: 1 for an X-Small, 4 for a Medium, 8 for a Large on a Standard warehouse, per the same table.

![Snowflake Service Consumption Table listing on-demand price per credit by edition and AWS region, from 2 dollars on Standard](/img/blog/2026/10/snowflake-credit-prices.webp)

*Snowflake Service Consumption Table, effective October 2, 2026, read October 2026.*

A Medium warehouse (4 credits an hour) running 8 hours a day for 22 working days is 176 hours. That costs $1,408 on Standard at $2.00 a credit and $2,112 on Enterprise at $3.00. The hours are our assumption, and the credit prices are Snowflake's.

Two other things push teams to look around. Some features sit in higher editions: multi-cluster warehouses and Time Travel beyond one day need Enterprise or above, per Snowflake's editions page and Time Travel docs. And Snowflake's Iceberg docs warn that reading or writing across regions or clouds can add egress charges (fees for moving data out of a cloud).

## First, choose the shape

**Broad platforms** try to run most of your SQL, reporting and, in some cases, machine learning. Databricks, BigQuery, Redshift and Fabric live here. **Narrower engines** do one job well: fast scans of event data (ClickHouse), analytics for a small team (MotherDuck), or SQL straight over files in your own storage (Dremio, Athena, Trino).

## The 8 best Snowflake alternatives

### 1. Databricks: for teams that write code and train models

![Databricks home page showing its headline and main navigation](/img/blog/2026/10/landing-databricks.webp)

*Databricks home page, October 2026.*

**At a glance:** proprietary platform on AWS, Azure and Google Cloud, SQL Serverless $0.70 per Databricks Unit (DBU) on the Premium plan (AWS US East), pay-as-you-go per second.

Databricks calls itself a "unified, open analytics platform" in its introduction docs. Its notebooks support Python, R and Scala as well as SQL, and it lists machine learning tools such as MLflow.

On its [SQL pricing page](https://www.databricks.com/product/pricing/databricks-sql), SQL Classic is $0.22 per DBU, SQL Pro $0.55 and SQL Serverless $0.70 (Premium plan, AWS US East). The Serverless rate includes the cloud machines. Classic and Pro are self-managed warehouses that run in your own cloud account, so that machine bill is separate.

![Databricks SQL pricing page showing SQL Serverless at 0.70 dollars, Classic at 0.22 and Pro at 0.55 per DBU](/img/blog/2026/10/databricks-sql-pricing.webp)

*Databricks SQL pricing page, AWS US East, Premium plan, October 2026.*

**What's good**

- One platform for SQL, pipelines and model training. Its introduction docs list Delta Lake, Apache Spark, MLflow and Unity Catalog among the open source projects Databricks employees created, and notebooks support Python, R and Scala as well as SQL.
- Its Iceberg docs say it supports Iceberg tables on Parquet at specification `v1`, `v2` and `v3`, managed by Unity Catalog or by foreign catalogs such as AWS Glue, Hive metastore or Snowflake Horizon Catalog.
- Outside engines can use the same tables: the Iceberg docs say the Iceberg REST Catalog API "supports read and write operations from external Iceberg engines", and managed tables can be created by engines such as Apache Spark, Flink, Trino or Kafka.
- Serverless SQL warehouses start in typically 2 to 6 seconds, per its warehouse docs.

**Where it falls short**

- DBUs used per hour by warehouse size aren't on the sizing docs page we read, so check the vendor calculator to forecast a bill.
- Managed Iceberg tables need Unity Catalog, Databricks Runtime `16.4` LTS or above and serverless compute, and they can only be created when predictive optimization is enabled for table maintenance.
- Foreign Iceberg tables are read-only in Databricks. They don't support partition evolution, and only the `main` branch is accessible, because branching and tagging aren't supported.
- On Iceberg `v2`, position deletes and equality-based deletes aren't supported. Databricks uses Iceberg `v3` deletion vectors for row-level deletes instead.
- External Iceberg engines can't read views through the REST catalog. Partition evolution on managed tables works through external engines but not through Databricks SQL.
- Classic and Pro warehouses take about 4 minutes to start, against 2 to 6 seconds for Serverless.

**What users say:** Praise on Hacker News, "Databricks acquires Neon" thread ([May 2025](https://news.ycombinator.com/item?id=43982947)): "Coming from hadoop, databricks is utopia. It's stable, fast, scales really well if you have massive datasets".

### 2. Google BigQuery: for Google Cloud teams that want no servers

![Google BigQuery home page showing its headline and main navigation](/img/blog/2026/10/landing-bigquery.webp)

*Google BigQuery home page, October 2026.*

**At a glance:** serverless, run by Google Cloud, $6.25 per TiB scanned after the first free TiB each month, or slot pricing under editions.

Google describes BigQuery as a "fully managed serverless data warehouse".

On-demand pricing charges for the bytes your queries read, per its [pricing page](https://cloud.google.com/bigquery/pricing), and the first `1 TiB` each month is free.

![BigQuery on-demand pricing table: first 1 TiB per month free, then 6.25 dollars per TiB, Iowa region](/img/blog/2026/10/snowflake-alternatives--bigquery-on-demand-per-tib.webp)

*BigQuery pricing page, Iowa (us-central1) column, October 2026.*

A team that scans 10 TiB in a month pays for 9 TiB, which is $56.25. Capacity pricing is the other model. The Standard edition shows $0.04 per slot-hour with no commitment, billed per second after a one-minute minimum (a slot is a unit of query compute).

**What's good**

- No cluster to size or pause: the introduction docs describe "zero infrastructure management" and say the BigQuery engineering team handles updates and maintenance.
- Its Iceberg docs say managed tables live in storage buckets you own, accept GoogleSQL data changes (DML) and support schema changes such as adding, dropping and renaming columns.
- Those tables also offer automatic storage optimization (adaptive file sizing, automatic clustering, garbage collection and metadata optimization).
- The Iceberg docs list export of an Iceberg `v2` snapshot for direct reads by open source engines such as Spark.
- The pricing page gives a monthly free tier of `1 TiB` of queries and the first `10 GiB` of storage. Storage not modified for `90 consecutive days` drops about 50 percent in price.
- Enterprise and Enterprise Plus list a 1-year capacity commitment at a 20 percent discount or a 3-year commitment at 40 percent, per the editions table.

**Where it falls short**

- On-demand billing follows bytes scanned, and the pricing page says you are charged for the columns you select even with an explicit `LIMIT`, so one careless query over a whole large table costs real money.
- On-demand queries get "up to 2,000 concurrent slots, shared among all queries in a single project".
- The Standard edition has no column-level access control, row-level security, data masking, BigQuery ML or VPC Service Controls, and it has no access to capacity commitments.
- On Iceberg managed tables only one mutating DML statement (`UPDATE`, `DELETE` or `MERGE`) runs at a time per table, and the others queue.
- Iceberg managed tables don't support renaming, table copies, table clones or table snapshots.
- It's a Google Cloud service, and a self-hosted option isn't stated.

**What users say:** Praise on PeerSpot ([2025 to 2026](https://www.peerspot.com/products/bigquery-pros-and-cons)): "BigQuery allows for very fast access, and it is efficient in handling large datasets compared to other SQL databases". Complaint on [SoftwareReviews](https://www.softwarereviews.com/products/google-bigquery) (October 2025): "What I dislike most is the lack of real-time cost visibility and predictability".

### 3. Amazon Redshift: for teams that already live on AWS

![Amazon Redshift home page showing its headline and main navigation](/img/blog/2026/10/landing-redshift.webp)

*Amazon Redshift home page, October 2026.*

**At a glance:** managed AWS data warehouse, Provisioned from $0.543 per hour or Serverless from $1.50 per hour, per its [pricing page](https://aws.amazon.com/redshift/pricing/).

AWS calls Redshift a "fully managed, petabyte-scale data warehouse service in the cloud". Serverless is billed at $0.375 per Redshift Processing Unit (RPU) hour (RPU is its unit of compute) in the page's US East examples. One example there prices 128 RPUs for 8,190 seconds at $109.20.

New Serverless users can claim a $300 credit that expires after 90 days. AWS also says its zero-ETL (no extract, transform, load pipeline for you to build) integrations copy data into Redshift. Sources include Aurora, RDS (managed databases) and DynamoDB, per its docs.

![Redshift pricing worked example: 8,190 seconds at 128 RPU and 0.375 dollars per RPU-hour gives 109.20 dollars a day](/img/blog/2026/10/snowflake-alternatives--redshift-serverless-rpu-price.webp)

*Amazon Redshift pricing page, October 2026.*

**What's good**

- Serverless compute is billed per second with no charges during idle periods, and base capacity can be set from `4` to `1024` RPUs, per the pricing page.
- Serverless Reservations reduce compute costs by up to 45 percent for a 3-year term or up to 24 percent for a 1-year term.
- Each Redshift cluster earns up to one hour of free Concurrency Scaling credits per day.
- Its zero-ETL docs list sources such as Aurora MySQL and PostgreSQL, DynamoDB, and RDS for MySQL, PostgreSQL and Oracle, plus applications such as Salesforce, SAP, ServiceNow and Zendesk.
- The pricing page says Redshift adds no extra fee for zero-ETL. You still pay for storage, compute and cross-AZ transfer, and the source may add fees.
- Its Iceberg query docs say it queries Iceberg tables in the Glue catalog, `v1` to `v3`, and `INSERT INTO` or `CREATE TABLE AS` can copy an Iceberg table into a local Redshift table.

**Where it falls short**

- Writing new Iceberg tables from Redshift itself isn't stated on the Iceberg query page, which says to create them in the Glue Data Catalog with a service such as Athena or Amazon EMR.
- AWS's docs say Redshift will no longer support Python user-defined functions after June 30, 2026, and AWS says it's enforcing this in phases. That date has passed, so check any you rely on.
- Zero-ETL tables need a primary key, data is replicated as-is with no transformation, and the destination database is read-only in Redshift, per its zero-ETL limits page.
- Zero-ETL is capped at `50` integrations per Redshift target. The minimum latency is 15 minutes for DynamoDB and 1 hour for application sources.
- The pricing page's Provisioned example of four RG instances for 730 hours comes to $8,884.60 a month on demand.
- It's an AWS service with no self-hosted option stated.

**What users say:** Praise on PeerSpot ([June 2025](https://www.peerspot.com/products/amazon-redshift-reviews)). A reviewer wrote: "Amazon Redshift handles scalability automatically, so we do not need to scale up or down; it is all managed by Redshift". Complaint on PeerSpot (April 2024): "Amazon Redshift could work on reducing its costs, as they tend to increase significantly".

### 4. Microsoft Fabric: for Power BI and Azure estates

**At a glance:** Microsoft's analytics platform, capacity-based, F SKUs billed per second, with an optional yearly reservation.

You buy Fabric as capacity, and per Microsoft's [licensing page](https://learn.microsoft.com/en-us/fabric/enterprise/licenses) F capacities are billed per second with a one-minute minimum and no commitment. Microsoft's Fabric pricing page says a 1 or 3 year reservation can save about 41 percent against pay-as-you-go.

Its storage layer, OneLake, stores tables in Delta Parquet or Iceberg format, per Microsoft's OneLake overview. Fabric's engines store data in the open Delta Parquet format, and metadata virtualization bridges Iceberg to it.

**What's good**

- Free-licence users can view Power BI content when the capacity is `F64` or larger, per the licensing page above.
- Shortcuts reference data in OneLake, Azure Data Lake Storage, Azure Blob storage, Amazon S3 and S3-compatible stores, Iceberg-compatible sources and more, and unify data across clouds without copying it, per the OneLake overview.
- One OneLake per tenant keeps storage in a single place. It supports Azure Data Lake Storage Gen2 APIs and SDKs, so existing applications for that service can be used.
- The OneLake overview says you can write Iceberg tables directly to OneLake or create shortcuts to Iceberg tables stored elsewhere. Metadata virtualization lets Iceberg tables be read as Delta Lake tables inside Fabric, and Delta Lake tables be read by external Iceberg readers.
- The same overview says database mirroring continuously replicates data from an operational database into OneLake as Delta tables.
- Power BI reports can be built on top of OneLake with Direct Lake mode in the Analysis Services engine.

**Where it falls short**

- The dollar rates for each F SKU didn't load in the pricing page text we read, so use the Azure calculator.
- On capacities smaller than `F64`, each person viewing Power BI content needs a Pro or Premium Per User licence, or an individual trial.
- The roughly 41 percent saving needs a yearly commitment. The per-second option has none, so the two suit different loads.
- Delta Lake to Iceberg conversion produces Iceberg `v2` metadata, per Microsoft's Iceberg conversion docs.
- Iceberg `v3` source tables are only partially supported, equality deletes make conversion fail, and Parquet is the only underlying file format.
- Source tables must have fewer than `5,000` commits for conversion to happen. Generating the metadata can take 5 seconds to 2 minutes, and conversion isn't supported on tenants or workspaces with private links enabled.

**What users say:** Complaint on Hacker News, ["Fabric Is Just Plain Unreliable, and Microsoft's Hiding It"](https://news.ycombinator.com/item?id=44029566) thread (May 2025). One commenter wrote: "Fabric will be great in 5 years, but right now it tends to be unreliable, unergonomic, and surprisingly expensive". The blog post was later updated to note better reliability.

### 5. ClickHouse: for fast scans of event data

![ClickHouse home page showing its headline and main navigation](/img/blog/2026/10/landing-clickhouse.webp)

*ClickHouse home page, October 2026.*

**At a glance:** open source under Apache 2.0, plus ClickHouse Cloud, Basic from $53 a month, Scale from $437 a month and Enterprise from $571 a month, per its [pricing page](https://clickhouse.com/pricing).

ClickHouse describes itself as a "column-oriented SQL database management system (DBMS) for online analytical processing (OLAP)". OLAP just means questions that sum or count across many rows, like dashboards.

You can run the open source server yourself or pay for the cloud service. It meters compute and storage separately and offers $300 in credits for 30 days.

![ClickHouse Cloud plan cards: Basic from 53 dollars, Scale from 437 dollars, Enterprise from 571 dollars a month](/img/blog/2026/10/snowflake-alternatives--clickhouse-cloud-pricing.webp)

*ClickHouse pricing page, October 2026.*

**What's good**

- You can self-host it: the intro docs say it is available as both open source software and a cloud offering, and the repository licence is Apache 2.0.
- Compute and storage are metered separately and scale to zero when idle in the cloud service. Compute is metered per minute in units of `8 GiB` of RAM and `2 vCPUs`, and storage is $25.30 per TB per month in the pricing page's N. Virginia view.
- In N. Virginia, a compute unit costs $0.2181 an hour on Basic, $0.2985 on Scale and $0.3903 on Enterprise.
- The Iceberg table engine docs say ClickHouse reads tables that use position deletes, equality deletes (from version `25.8`) and deletion vectors.
- Its distinctive features page says "No locks are taken when new data is ingested."
- The Enterprise plan lists SAML single sign-on, private regions, transparent data encryption (CMEK), and "HIPAA and PCI compliance".

**Where it falls short**

- Its Iceberg table engine page says it "is available but may have limitations", and that ClickHouse "wasn't originally designed to support tables with externally changing schemas".
- Deletion vector support is read-only, `ALTER TABLE ... DELETE` and `UPDATE` aren't supported on Iceberg `format-version 3` tables, and ClickHouse cannot create an Iceberg schema with `Bool`, `Decimal`, `FixedString`, `Int8`, `UInt8`, `Int16` or `UInt16` columns.
- The docs list "No full-fledged transactions" and no ability to modify or delete inserted data "with a high rate and low latency" among the features that can be disadvantages.
- The same list says the sparse index makes ClickHouse "not so efficient for point queries retrieving single rows by their keys".
- Its docs describe change data capture (copying database changes) through ClickPipes for ClickHouse Cloud, and its MongoDB pipe is in public beta.
- Enterprise starts at $571 a month on the page, so treat that as the minimum.

**What users say:** Praise on Hacker News, "ClickHouse gets lazier and faster" thread ([April 2025](https://news.ycombinator.com/item?id=43763688)). One commenter wrote: "We migrated some analytics workloads from postgres to clickhouse last year, it's crazy how fast it is". Complaint on [PeerSpot](https://www.peerspot.com/products/clickhouse-reviews) (December 2025): "Too many issues exist for beginners to set up ClickHouse".

### 6. MotherDuck: for small teams and embedded analytics

![MotherDuck home page showing its headline and main navigation](/img/blog/2026/10/landing-motherduck.webp)

*MotherDuck home page, October 2026.*

**At a glance:** managed cloud service built on DuckDB. Lite is $0; Business is $250 per org per month plus usage, per its [pricing page](https://motherduck.com/product/pricing/).

DuckDB is an open source database that runs inside your own program, with no server to install. It's under the MIT (permissive open source) licence, per DuckDB's own page. MotherDuck sells a hosted version for sharing and scale.

Lite includes up to `3` internal active users, `10 GB` of storage and `10 hours` of Pulse compute per month. Standard compute is $2.40 per hour billed per second, and storage is $0.04 per GB per month. Business adds up to `10` internal users and read-scaling replicas, and it offers a 7-day free trial.

**What's good**

- A free Lite plan, and Business at $250 per org per month, per its pricing page.
- Hosted by MotherDuck, so there is no cluster for you to run. The pricing page says the plans fit "customer-facing analytics and internal data warehousing use cases".
- Pulse compute is $0.60 per compute unit hour, metered per query with a minimum of one compute unit second.
- You can pay MotherDuck directly or through an AWS Marketplace private offer on your AWS invoice.
- Its Iceberg docs say you can attach an Iceberg REST catalog as a MotherDuck database. The catalog table shows read and write for Amazon S3 Tables, Apache Polaris, AWS Glue, Cloudflare R2, Databricks Unity Catalog and Snowflake Horizon (Unity and Horizon tables must be backed by external storage).

**Where it falls short**

- Lite caps internal users at `3`, and Business at `10`. Enterprise pricing is custom.
- Iceberg updates, deletes and merges write small delete files (merge-on-read). Copy-on-write isn't supported, and a `DELETE` against a copy-on-write table fails.
- Per the Iceberg docs, `INSERT` and `UPDATE` fail on a table that declares a sort order. Reading from REST catalogs is limited to S3, S3-compatible storage including Cloudflare R2, S3 Tables and GCS backends.
- The larger Jumbo, Mega and Giga instances cost $4.80, $12.00 and $24.00 per hour.

**What users say:** Praise on Hacker News, ["A Preview of DuckDB v2.0"](https://news.ycombinator.com/item?id=49332159) thread (August 2026): "I've been using MotherDuck as a data warehouse for some time now. No regrets". Complaint on Hacker News, [Arc launch](https://news.ycombinator.com/item?id=45506671) thread (October 2025): "I'm looking to self-host duckdb because MotherDuck is way too expensive".

### 7. Dremio: for an Iceberg lakehouse

![Dremio platform page showing its headline and main navigation](/img/blog/2026/10/landing-dremio.webp)

*Dremio platform page, October 2026.*

**At a glance:** Dremio Cloud at $0.20 per Dremio Compute Unit (DCU), on AWS, with Azure listed as coming soon, and Dremio Enterprise by quote, per its [pricing page](https://www.dremio.com/pricing/).

Dremio sells a lakehouse query platform, and its pricing page lists Apache Iceberg as an open source technology and an Iceberg lakehouse use case. Enterprise can be self-managed on cloud, Kubernetes or on-premises, and the page also lists a free Community Edition query engine for local machines or servers.

![Dremio pricing page showing Dremio Cloud at 0.20 dollars per Dremio Compute Unit and Dremio Enterprise as Contact Sales](/img/blog/2026/10/dremio-cloud-pricing.webp)

*Dremio pricing page, October 2026.*

The page also says "Query your data in minutes, no manual configuration required". That is Dremio's claim.

Ownership just changed. SAP (the business software company) lists its completed acquisition of Dremio on its news site, dated July 6, 2026, and the Dremio pricing page banner reads "Dremio is now part of SAP". The page we read doesn't say what happens to Dremio Cloud's pricing or products.

**What's good**

- Lists an Iceberg lakehouse as a use case on its pricing page.
- Its Iceberg docs say connected sources use default Iceberg catalogs that support both read and write commands, and the built-in Iceberg catalog is based on Apache Polaris (incubating).
- Its data sources docs list lakehouse catalogs (including AWS Glue, Hive, Iceberg REST, Nessie and Unity Catalog), object storage (Amazon S3, Azure Storage, Google Cloud Storage, HDFS and NAS) and databases such as MongoDB, MySQL, Oracle, PostgreSQL and SQL Server.
- A published cloud rate of $0.20 per DCU, with a 30-day trial that includes $400 in credits and needs no credit card, per the pricing page FAQ.
- A self-managed Enterprise option, and a free Community Edition query engine.

**Where it falls short**

- The Enterprise price is not published ("Contact Sales"), so you can't budget for it from the page.
- The cloud service is on AWS today, with Azure only listed as coming soon.
- On Iceberg, the docs say only Parquet file formats are currently supported and Amazon DynamoDB and JDBC catalogs are not supported. They also say Dremio does not support reading global equality deletes for Iceberg `v2` tables in one described case, and the page doesn't mention Iceberg `v3`.
- Relational sources must use a collation equivalent to `LATIN1_GENERAL_BIN2`, and case-sensitive source file and table names are not supported.
- The SAP deal is new, and the plans after it aren't stated on the page we read.

**What users say:** Praise in PeerSpot's [summary of reviews](https://www.peerspot.com/products/dremio-reviews): setting up Dremio is "straightforward and rapid, often taking about a day". Complaint on PeerSpot: "We had a memory leak on some versions, which sometimes stopped the service".

### 8. Amazon Athena: for occasional queries on files in S3

![Amazon Athena home page showing its headline and main navigation](/img/blog/2026/10/landing-amazon-athena.webp)

*Amazon Athena home page, October 2026.*

**At a glance:** serverless SQL on files in Amazon S3, $5 per TB scanned (US East Ohio example), `10 MB` minimum per query, per its [pricing page](https://aws.amazon.com/athena/pricing/) and the AWS price list for US East (Ohio).

Athena is a query service. It reads files in S3 and bills for the data each query scans.

AWS's own example shows a 3 TB scan costing $15 on text files and $1.25 once converted to compressed Parquet for a one-column query (a compact column file format). For steady load it also sells Capacity Reservations, and its example uses $0.30 per Data Processing Unit (DPU) hour.

**What's good**

- Serverless per AWS, so there is no server to run. You can use SQL or Apache Spark, and the default bill follows the data each query scans.
- It queries data directly in Amazon S3, with no additional storage charges for querying.
- Its Iceberg docs say it can read, time travel, write and run DDL queries on Iceberg tables, and engine version `3` supports the Parquet, ORC and Avro file formats.
- Converting to Parquet cuts the scan bill sharply, per AWS's example.
- Spark use is billed per DPU-hour: AWS's example prices 3.0 DPU-hours at $0.35 each, or $1.05.
- AWS's price list shows DDL, failed queries and statements that create or load partitions as free query types.

**Where it falls short**

- Its Iceberg docs say only tables created against the AWS Glue catalog are supported, and that Athena operates on Iceberg `v2` tables only.
- Table definition commands (DDL) are not supported on Iceberg tables registered with Lake Formation, and timestamps are limited to millisecond precision.
- Athena supports AWS Glue optimistic locking only. Using it to modify an Iceberg table with any other lock implementation can cause data loss and break transactions.
- It doesn't support `ALTER TABLE SET LOCATION` on Iceberg tables or partitioning them by nested fields.
- The bill follows bytes scanned, with a `10 MB` minimum per query, so large text files are the costly case, as AWS's own $15 example shows.

**What users say:** Praise on Hacker News, ["Apache iceberg the Hadoop of the modern-data-stack?"](https://news.ycombinator.com/item?id=43277214) thread (March 2025): "I never found Athena expensive. Compared to employment cost it will be miniscule". Complaint on PeerSpot ([2025 to 2026](https://www.peerspot.com/products/amazon-athena-reviews)): "Since the pricing is $5 per TB, large queries on big datasets can result in substantial bills".

## Other Snowflake competitors worth knowing

- **Trino** is an open source query engine (Apache 2.0 repository licence). Its docs say it's not a replacement for databases such as MySQL or PostgreSQL, and that it wasn't designed for online transaction processing, the many small writes an app makes. Its Iceberg connector docs say it supports table versions `v1` and `v2`, with `v3` experimental.

  **What users say:** Praise on [Hacker News](https://news.ycombinator.com/item?id=49667560) (September 2026): "It is extremely mature and well understood with lots of extensions". Complaint in a [Trino GitHub issue](https://github.com/trinodb/trino/issues/26563) (September 2025). The reporter wrote: "About 5-10% of queries on iceberg tables are taking more than 1 minutes and up to 10 minutes to complete the planning stage".

## Apache Iceberg and the cost of leaving

Apache Iceberg is an open table format: a set of metadata files that tells any engine which Parquet files make up a table. If your tables sit in your own bucket in Iceberg format, several engines can read them. Trying a competitor gets cheaper because you don't copy the data first.

Snowflake's [Iceberg docs](https://docs.snowflake.com/en/user-guide/tables-iceberg) say it supports Iceberg tables with Parquet files and externally managed writes on `v2` or `v3` of the spec. Its release notes list partition evolution for Iceberg tables as generally available on September 18, 2026. When the account and the storage sit in different regions or clouds, egress charges can apply.

Most options above document Iceberg support, but the depth varies.

Databricks, BigQuery and Fabric document managed or bridged tables. Redshift and Athena lean on the Glue catalog, and ClickHouse warns about limits. Test your exact table, catalog and engine pair before you promise anyone a quick move.

## Where Snowflake fits

Choose Snowflake if you need one of these, per its own docs.

- **Sharing data between accounts.** Snowflake's data sharing docs say that with Secure Data Sharing, no actual data is copied or transferred between accounts.
- **AI functions inside the warehouse.** Its Cortex AI functions offer models from OpenAI, Anthropic, Meta, Mistral AI, DeepSeek and xAI, and its Cortex docs say the models are deployed within the Snowflake Service perimeter.
- **Three clouds.** It lists AWS, Azure and Google Cloud, where BigQuery, Redshift and Fabric each come from one cloud owner.

On cost, Select's run (a single third party's test; Select sells cost tools for Snowflake and Databricks) used 22 queries on a standard benchmark data set at scale factor `1000`. At $2 per credit, Snowflake was 34 percent faster and 17 percent cheaper than Databricks at $0.70 per DBU. At $3 per credit, Databricks was 20 percent cheaper in that same sequential test, per [Select, April 10, 2026](https://select.dev/posts/snowflake-vs-databricks-showdown). The result followed the credit price.

## What usually needs rework when you move

The table data is the easy part. The work sits in the Snowflake-specific code and settings on top.

- **Semi-structured columns.** Snowflake's `VARIANT` type stores a value of any other type, including objects and arrays, up to `128 MB` uncompressed, per its data types docs. Every target has its own JSON or struct type, so list the queries that read `VARIANT` columns first.
- **SQL dialect.** Databricks tells migrating teams to convert SQL "from dialects such as T-SQL, Snowflake, and Oracle" with its agentic code converter, per its migration docs. Treat any converter output as a first draft.
- **History and recovery.** Snowflake keeps one day of Time Travel by default, and Enterprise can raise it up to `90 days` on permanent tables, per its docs. Check what each target offers for recovering a dropped table.
- **Scheduling and permissions.** We did not find a vendor page that maps these across tools, so plan a manual review. We found no standard migration time either, so we won't quote one.

## What to test before you switch

1. **Run your real queries.** Take a week of your actual query log and price it in each vendor's unit.
2. **Check your SQL.** Dialects differ, so run your ten most important queries and compare the results.
3. **Test Iceberg on your own tables.** Use your catalog and your engine, and try an update and a delete as well as a read.
4. **Read the exit costs.** Look for egress fees between regions or clouds, and for minimum commitments.
5. **Run both side by side for one billing cycle.** Compare the invoices before you cancel anything.

## Where OLake Go fits

[OLake Go](/docs/) is an open-source tool (Apache 2.0) that copies data from databases such as [Postgres](/docs/connectors/postgres/), [MySQL](/docs/connectors/mysql/), [MongoDB](/docs/connectors/mongodb/), [SQL Server](/docs/connectors/mssql/), [Oracle](/docs/connectors/oracle/) and [Db2](/docs/connectors/db2/) into Apache Iceberg tables or Parquet files on storage you control. You run it yourself, and the [quickstart](/docs/getting-started/quickstart/) shows how.

Change data capture covers Postgres, MySQL and MariaDB, MongoDB and SQL Server. Snowflake has two routes. From v0.11.0, OLake Go can write Iceberg tables into a Snowflake database through the [Snowflake Horizon Catalog](/docs/writers/iceberg/catalog/rest/?rest-catalog=horizon), using a programmatic access token, key-pair authentication or External OAuth. Or OLake Go writes to another catalog, such as AWS Glue, and Snowflake reads those tables from an external catalog as read-only. Our [compatibility page](/docs/understanding/compatibility-engines/) also lists Databricks, BigQuery, Redshift, Athena, Trino and Dremio among the engines that query the tables OLake Go writes. OLake Go's destinations are Iceberg and Parquet.
