## So what is a "data pipeline tool", anyway?

A data pipeline is a series of processing steps that prepare enterprise data for analysis, which is broad enough to cover almost anything. A pipeline has four jobs, and a tool built for one usually isn't built for the others.

- **Ingest:** copy data from where it lives, such as a database or an app, to a new place.
- **Store:** keep it in a warehouse (a database built for reports) or a data lake (cheap file storage many tools can read).
- **Transform:** clean, join and reshape the data so people can use it.
- **Orchestrate:** run the other steps on a schedule, in the right order, and retry or alert when one fails.

Reshape data before it lands and that's called extract, transform, load (ETL). Reshape it after and it's extract, load, transform (ELT). Streaming is a way of doing the first and third jobs: instead of moving data in batches every hour, a streaming tool handles each change as it happens.

![One pipeline has four jobs: ingest, store, transform, and orchestrate, and most tools here do only one of them](/img/blog/2026/10/best-data-pipeline-tools-four-jobs.webp)

A scheduler doesn't move or reshape a single row. It starts the other tools in the right order and alerts you when one fails.

## How we picked

We picked 14 tools that are actively maintained, publish documentation we could open, and between them cover all four jobs. We read each vendor's pricing and docs pages on October 8, 2026, and we did not run the other tools. This is a reading of vendor pages, not a lab test.

Estuary, Stitch, Skyvia, Informatica, Talend and others are not on this list, and the order inside each group is not a ranking.

## Ingestion tools: get your data into one place

### 1. Fivetran: best for hands-off loading from many sources

![Fivetran home page showing its headline and main navigation](/img/blog/2026/10/landing-fivetran.webp)

*Fivetran home page, October 2026.*

**At a glance**
- Price: Free up to 500,000 monthly active rows (MAR, the rows that change in a month); paid rates in its [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table), not on the pricing page. Standard starts at $495 per million MAR plus a $5 base per connection, list price before discounts (October 2026)

Fivetran's pricing page lists 700+ connectors, 15-minute syncs on Standard and 1-minute syncs on Enterprise. Fivetran says it runs the pipeline for you, a claim we did not test.

One 2026 change matters. Fivetran announced that its merger with dbt Labs closed on June 1, 2026, so a managed loader and a transform tool now share an owner. If you use both, ask whether pricing or packaging will change.

**What's good**

- The Free plan includes Standard plan features, with up to 500,000 monthly active rows free for connections, 3,500 for activations and 5,000 monthly model runs for transformations (pricing page, October 2026). Its claims that loading is fully managed and runs hands-off are the vendor's own, and we did not test them.
- Standard lists unlimited users, 15-minute syncs, 700+ fully managed connectors and a dbt Core integration. Enterprise adds 1-minute syncs, custom roles, SCIM and a Hybrid deployment option, and Business Critical adds customer-managed encryption keys and PCI DSS Level 1 certification (pricing page).
- For database sources, its docs say it captures changes with the source's native change data capture mechanism or a Fivetran proprietary method, depending on the database. They also say database connectors sync new and modified data every 15 minutes by default (Fivetran's database connector docs).
- Each connection is billed on its own volume curve, so the per-row rate falls as one connection grows. On Standard it goes from $495 per million rows at the start to $170 per million past 1M rows and $58 per million past 4M (Service Consumption Table, version V.10, effective February 1, 2026).
- Transformations get 5,000 model runs a month free, then $0.01 per run up to 30,000, $0.007 up to 100,000 and $0.002 beyond that (Service Consumption Table).

**Where it falls short**

- Paid list rates live in a separate table, and each connection has its own curve, so you need rows per connection to predict a bill. The table also says you cannot combine rows across connections to get a better rate.
- Our read: the $5 base per connection is the easiest line to miss (pricing page). By the consumption table formula, 20 connections of 2,000 rows each come to $119.80 a month (our arithmetic).
- Deleted rows also count as paid rows: the pricing page counts updates as modifications to existing rows in your destination, including deletes.
- Teleport Sync is its option when you cannot or do not want to give Fivetran access to your database's change logs. The docs say that if you update large portions of a table between syncs it may be unable to find the changes, and the connection then re-syncs the entire table (database connector docs).
- The pricing page calls Oracle and High-Volume Agent connectors "enterprise database connectors", and the Enterprise plan card lists them where Standard lists plain database connectors (pricing page).

### 2. Airbyte: best for a long connector list with a free self-hosted core

![Airbyte home page showing its headline and main navigation](/img/blog/2026/10/landing-airbyte.webp)

*Airbyte home page, October 2026.*

**At a glance**
- Price: Core is free; Cloud Standard $20 a month with 5 credits and $5 per extra credit; Plus from $189 for 40 credits ([Airbyte release notes](https://docs.airbyte.com/release_notes/cloud), September 15, 2026)

Airbyte's docs say it has over 600 pre-built connectors, so check the current status of the connector you actually need.

Its CDC (change data capture) docs describe log-based replication, but they also say syncs are scheduled and CDC sources aren't treated as infinite streams.

**What's good**

- Per its docs, you can self-host the free core or pay for the cloud, and build connectors with a no-code builder or a Python kit. We did not test how well any of these work.
- Plus runs from 40 credits for $189 ($4.75 a credit) up to 2,000 credits for $4,999, and overage credits fall from $5 to $2.50 on the top tier. All Plus plans include 15-minute syncs, two workspaces, single sign-on and premium support (release notes, September 15, 2026).
- Unused Cloud credits now roll over for 3 months, up from 2, and Cloud free trials last 14 days (release notes, September and October 2026).
- Its CDC docs list Postgres, MySQL, Microsoft SQL Server, MongoDB, Oracle, SAP HANA and IBM Db2 under current support. They name no plan or connector support level for Oracle, SAP HANA or Db2 (Airbyte's CDC docs).

**Where it falls short**

- It isn't a continuous streaming tool: CDC syncs are launched on a sync interval, and the CDC docs say "We do not treat CDC sources as infinite streaming sources."
- For most sources, CDC incremental sync works only for tables with primary keys, and a refresh is required after any new table or collection is added to a CDC connection (CDC docs).
- Changes made by TRUNCATE or ALTER won't appear in the logs, so they don't reach the destination (CDC docs).
- On Cloud Standard, scheduled or cron syncs can run at most every 60 minutes and an organization gets 1 workspace; Plus allows every 15 minutes (Airbyte's Cloud limits docs). SSO is no longer available on Standard, except for existing users who keep their plan (Airbyte's Cloud release notes).
- Standard got dearer in September 2026: the base price rose from $10 to $20 a month, free credits from 4 to 5 and extra credits from $2.50 to $5.00 (release notes).
- The core uses the Elastic License 2.0, and Airbyte's license FAQ says it stops you providing the products to others as a managed service.

### 4. OLake Go: best for copying Postgres, MySQL, MongoDB or SQL Server into Iceberg

<img src="/img/logo/olake-blue-with-text.svg" alt="OLake" height="32" style={{display: 'block', margin: '2px 0 14px'}} />

![OLake home page showing its headline and main navigation](/img/blog/2026/10/landing-olake.webp)

*OLake home page, October 2026.*

**At a glance**
- Price: Open source under [Apache 2.0](https://github.com/datazip-inc/olake); you run it on your own infrastructure with [Docker](/docs/install/docker-cli/), [Helm on Kubernetes](/docs/install/kubernetes/) or the [OLake UI](/docs/install/olake-ui/)

OLake Go copies [PostgreSQL](/docs/connectors/postgres/), [MySQL and MariaDB](/docs/connectors/mysql/), [MongoDB](/docs/connectors/mongodb/) and [SQL Server](/docs/connectors/mssql/) with a full load plus change data capture, and writes Apache Iceberg tables or Parquet files on storage you control. [Oracle](/docs/connectors/oracle/), [Db2](/docs/connectors/db2/), [S3](/docs/connectors/s3/) and [Kafka](/docs/connectors/kafka/) also work as sources, without database change capture.

**What's good**

- One tool does the first load and then the change capture, with Full Refresh, Full Refresh + Incremental, Full Refresh + CDC and CDC Only sync modes ([docs](/docs/)).
- It writes Iceberg tables to catalogs such as [AWS Glue](/docs/writers/iceberg/catalog/glue/), with eleven catalog types listed on the [catalog compatibility page](/docs/understanding/compatibility-catalogs/).
- Engines such as Athena, Spark, Flink and Trino can read the Iceberg tables it writes ([query engine compatibility](/docs/understanding/compatibility-engines/)).
- Syncs are stateful and resumable: after a crash, a network failure or a pause they resume from the last checkpoint instead of starting over ([docs](/docs/)).
- Parallel chunking splits large tables into chunks that are read in parallel, in the Full Refresh, Full Refresh + CDC and Full Refresh + Incremental modes ([docs](/docs/)).
- Schema discovery runs at the start of every sync, and a new source column is added to the Iceberg schema automatically ([schema evolution docs](/docs/features/schema/)).

### 5. Debezium: best for engineers who need every database change as an event

![Debezium home page showing its headline and main navigation](/img/blog/2026/10/landing-debezium.webp)

*Debezium home page, October 2026.*

**At a glance**
- Price: Free; you run it yourself; you pay for servers and staff

Its FAQ says Debezium records all row-level changes committed to each database table, so applications can react to insert, update and delete events, though after a failure they can see an event more than once. The docs list eight main source connectors, including PostgreSQL, MySQL, MongoDB, SQL Server and Oracle.

**What's good**

- It's free, and its docs describe delay in the millisecond range for MySQL and PostgreSQL. That is the project's claim, not our measurement, so test it on your own load (Debezium's features page).
- The connector index lists eight main source connectors: MongoDB, MariaDB, MySQL, PostgreSQL, SQL Server, Oracle, Db2 and Cassandra. Seven more are marked incubating: Vitess, Spanner, Informix, CockroachDB, YashanDB, Ingres and Milvus (Debezium's connector index).
- Beyond Kafka Connect, the same docs list Debezium Server, a Debezium Operator, a Debezium Management Platform and guides for running on Kubernetes and OpenShift (connector index).
- The FAQ says all events within a topic are totally ordered, and that even if events are duplicated during failures the end result after applying them all stays the same (FAQ).
- The FAQ also says Debezium connectors do not store any information inside the upstream databases (FAQ).

**Where it falls short**

- It captures changes and nothing more. You still need a place to send them, a way to run it and someone to keep it healthy.
- The FAQ says consumers see every event exactly once only when systems run nominally or shut down gracefully; when things go wrong they can see events at least once, so the destination has to cope with repeats (FAQ).
- Running a connector may place additional load on the source database (FAQ).
- On MySQL, the FAQ says delete events can be missing when CASCADE DELETE statements are used, because those deletions are not part of the binlog (FAQ).
- On Amazon RDS for MySQL, log_bin is managed by AWS and off by default, and the FAQ's fix is to turn on read replicas or automated backups (FAQ).
- Incubating connectors are released for preview and are subject to changes that may not always be backward compatible (connector index).

## Streaming tools: react to each change as it happens

### 6. Apache Kafka: best for moving event streams between many systems

![Apache Kafka home page showing its headline and main navigation](/img/blog/2026/10/landing-kafka.webp)

*Apache Kafka home page, October 2026.*

**At a glance**
- Price: Free; managed Kafka is priced by each vendor

Kafka's own introduction calls it an event streaming platform that publishes, stores and processes streams of events. Its Kafka Connect part continuously imports and exports data from systems such as relational databases. 

**What's good**

- It's free, and its docs say it stores streams of events durably, which we did not test.
- Events are not deleted after consumption, so a topic can be read as often as needed. How long they are kept is a per-topic setting (Kafka intro).
- Any consumer of a topic-partition reads that partition's events in the order they were written, and a common production setting is a replication factor of 3, meaning three copies of the data (Kafka intro).
- It can run on bare-metal hardware, virtual machines and containers, on-premises or in the cloud, and you can self-manage it or use fully managed services from a variety of vendors (Kafka intro).
- Its 4.2 design docs say it supports exactly-once delivery in Kafka Streams, and in the transactional producer paired with a read-committed consumer. The producer also has an idempotent delivery option, so resending does not create duplicate log entries (Kafka's design docs).

**Where it falls short**

- It's a platform you run, not a ready-made pipeline. Kafka itself doesn't reshape warehouse tables, and it needs connectors at both ends.
- The intro describes capture as something a connector does, for example a PostgreSQL connector capturing every change to a set of tables, not something the brokers do. It describes no Iceberg writer.
- The intro says the Kafka community provides hundreds of ready-to-use connectors, and the Apache project publishes no exact count (Kafka intro).
- Exactly-once is not the default: the 4.2 design docs say Kafka guarantees at-least-once delivery by default.

### 7. Apache Flink: best for reshaping streams as they flow

![Apache Flink home page showing its headline and main navigation](/img/blog/2026/10/landing-apache-flink.webp)

*Apache Flink home page, October 2026.*

**At a glance**
- Price: Free; you pay for servers and staff

Flink's site describes it as "stateful computations over data streams", and it shows 2.3 as the current stable release. The Apache Iceberg docs say the Flink sink for Iceberg guarantees exactly-once semantics.

**What's good**

- Its site describes stateful computations on streams and, per the Iceberg docs, it can write batch and streaming data to Iceberg tables. We did not test either.
- The Flink home page lists low latency, high throughput and in-memory computing as features.
- The Iceberg docs say it supports UPSERT based on the primary key when writing to a v2 table (Iceberg Flink writes).
- The same docs say IcebergSink can run table maintenance after each commit: compacting small data files, expiring old snapshots and removing orphan files, so a separate maintenance job is not required (Iceberg Flink writes).

**Where it falls short**

- It's a framework you program and operate, and it's overkill for hourly batch jobs.
- Streaming jobs do not support INSERT OVERWRITE; overwrite works in batch jobs (Iceberg Flink writes).
- UPSERT needs the v2 table format and a primary key or identifier fields, and OVERWRITE and UPSERT cannot be enabled at the same time (Iceberg Flink writes).
- The Iceberg docs call the newer SinkV2-based IcebergSink "currently an experimental feature so use it with caution" (Iceberg Flink writes).
- Iceberg commits happen after a successful Flink checkpoint, in the notifyCheckpointComplete callback, so the job needs checkpointing set up (Iceberg Flink writes).

### 9. AWS Glue: best for teams that already write Spark jobs on AWS

![AWS Glue home page showing its headline and main navigation](/img/blog/2026/10/landing-aws-glue.webp)

*AWS Glue home page, October 2026.*

**At a glance**

Here's the catch: the Glue docs say jobs created without a version default to 5.1, the higher rate.

**What's good**

### 10. Azure Data Factory: best for Microsoft-centred batch pipelines

![Azure Data Factory home page showing its headline and main navigation](/img/blog/2026/10/landing-azure-data-factory.webp)

*Azure Data Factory home page, October 2026.*

**At a glance**
- Price: Per activity run plus integration runtime hours; Microsoft's retail price feed shows $1.00 per 1,000 activity runs and $0.25 per data integration unit (DIU) hour of data movement in US East ([Azure Retail Prices feed](https://prices.azure.com/api/retail/prices?$filter=serviceName%20eq%20'Azure%20Data%20Factory%20v2'%20and%20armRegionName%20eq%20'eastus'), October 2026)

Microsoft's pricing page says you pay for running pipelines by activity run and for execution by integration runtime hours. The page loads rates dynamically, so the run and data movement figures above come from the Azure Retail Prices feed, and the data flow rates below come from the page's own tab table.

One more thing: Microsoft's docs say that if you're new to data integration you should start with Fabric Data Factory, which it calls the next generation.

**What's good**

- Microsoft's docs call it a managed service for ETL, ELT and data integration projects, so loading and running pipelines sit in one place.
- The pricing page describes the integration runtime as "serverless in Azure and self-hosted in hybrid scenarios", and charges are prorated by the minute and rounded up, so 2 minutes 20 seconds bills as 3 minutes (pricing page).
- Data flows on General Purpose compute list $0.274 per vCore-hour pay as you go, $0.205 with a 1-year reservation (about 25% savings) and $0.178 with a 3-year reservation (about 35%) (pricing page tab table).
- It has a change data capture resource that can run continuously. Native CDC in mapping data flows needs no timestamp or ID columns and lists SAP CDC, Azure SQL Database, SQL Server, Azure SQL Managed Instance, Azure Cosmos DB and Snowflake as connectors (Azure Data Factory's CDC docs).
- The Copy activity can write Iceberg format through an IcebergSink (Azure Data Factory's Iceberg format docs).

**Where it falls short**

- Pipelines are batch only. The CDC docs say "Pipelines in ADF are batch only, but the CDC resource can run continuously."
- The Iceberg sink supports only Azure Data Lake Storage Gen2, and the page names no Iceberg catalog such as Glue, REST, Polaris or Unity (Azure Data Factory's Iceberg format docs).
- The self-hosted runtime runs only on Windows (Azure Data Factory's integration runtime docs).
- Native log-based CDC for PostgreSQL, MySQL, MongoDB or Oracle is not on the CDC page's connector list, and auto incremental extraction from databases needs an incremental column to find changes (CDC docs).
- Data flows start at a minimum cluster of 8 vCores and also bill for the managed disk and blob storage they need (pricing page).
- Copying data out of an Azure datacenter adds a separate outbound data transfer line item (pricing page).

## How to choose, in five questions

Answer these in order. The first answer usually knocks out half the list.

1. **Which job is missing?** If data isn't landing anywhere yet, start with the ingestion group. If it lands but it's messy, look at dbt. If someone runs steps by hand, look at the schedulers.
2. **How fast must changes show up?** Hourly or slower points to a loader or a batch tool. Seconds points to Debezium, Kafka and Flink, which you run yourself.
3. **Who runs it?** If nobody wants to touch servers, choose a managed tool or a cloud bundle. If you have engineers, free software drops the licence bill and adds the work.
4. **Which cloud are you on?** Inside AWS or Azure, the bundles save you from joining parts.
5. **How does the tool count?** Rows, events, credits, models and compute hours grow in different ways. Work out your own number before you sign anything.

### Check before you rely on a claim

Speed, uptime, ease and savings claims on vendor pages are the vendor's own. Before you sign, ask for the status of the exact connector you need, a bill estimate from your own volumes in writing, and what the next price step is past the free limit.
