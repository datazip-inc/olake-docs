Short version: there's no single best data pipeline tool, because a pipeline has four jobs and most tools only do one. Fivetran, Airbyte, Hevo, OLake Go and Debezium load your data. Kafka and Flink handle streams, dbt reshapes data once it has landed, and Airflow, Dagster and Prefect run the steps in order.

Matillion, AWS Glue and Azure Data Factory bundle several jobs inside one vendor's cloud, so pick one tool per job (or one bundle) and check how each one bills.

- **Billing meters differ a lot.** Fivetran counts changed rows, Hevo counts events, Airbyte and Dagster count credits, dbt counts models built, and AWS Glue counts compute time.
- **Free isn't zero.** Most of the 14 tools have free software or a free plan, each with a ceiling, and open-source tools still cost servers and people.

## So what is a "data pipeline tool", anyway?

A data pipeline is a series of processing steps that prepare enterprise data for analysis, which is broad enough to cover almost anything. A pipeline has four jobs, and a tool built for one usually isn't built for the others.

- **Ingest:** copy data from where it lives, such as a database or an app, to a new place.
- **Store:** keep it in a warehouse (a database built for reports) or a data lake (cheap file storage many tools can read).
- **Transform:** clean, join and reshape the data so people can use it.
- **Orchestrate:** run the other steps on a schedule, in the right order, and retry or alert when one fails.

Reshape data before it lands and that's called extract, transform, load (ETL). Reshape it after and it's extract, load, transform (ELT). Streaming is a way of doing the first and third jobs: instead of moving data in batches every hour, a streaming tool handles each change as it happens.

![One pipeline has four jobs: ingest, store, transform, and orchestrate, and most tools here do only one of them](/img/blog/2026/10/best-data-pipeline-tools-four-jobs.webp)

A scheduler doesn't move or reshape a single row. It starts the other tools in the right order and alerts you when one fails.

Estuary, Stitch, Skyvia, Informatica, Talend and others are not on this list, and the order inside each group is not a ranking.

## Ingestion tools: get your data into one place

### 1. Fivetran: best for hands-off loading from many sources

**At a glance**
- Price: Free up to 500,000 monthly active rows (MAR, the rows that change in a month); paid rates in its [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table), not on the pricing page. Standard starts at $495 per million MAR plus a $5 base per connection, list price before discounts ([pricing page](https://www.fivetran.com/pricing)) (checked Oct 2026)

Fivetran's [pricing page](https://www.fivetran.com/pricing) lists 700+ connectors, 15-minute syncs on Standard and 1-minute syncs on Enterprise (checked Oct 2026). Fivetran says it runs the pipeline for you, a claim we did not test.

One 2026 change matters. Fivetran [announced that its merger with dbt Labs closed on June 1, 2026](https://www.fivetran.com/press/fivetran-dbt-labs-complete-merger-to-create-the-data-infrastructure-for-trusted-ai-agents), so a managed loader and a transform tool now share an owner. If you use both, ask whether pricing or packaging will change.

**What's good**

- The Free plan includes Standard plan features, with up to 500,000 monthly active rows free for connections, 3,500 for activations and 5,000 monthly model runs for transformations, per the [pricing page](https://www.fivetran.com/pricing) (checked Oct 2026).
- Standard lists unlimited users, 15-minute syncs, 700+ fully managed connectors and a dbt Core integration. Enterprise adds 1-minute syncs, custom roles, SCIM and a Hybrid deployment option, and Business Critical adds customer-managed encryption keys and PCI DSS Level 1 certification, per the [pricing page](https://www.fivetran.com/pricing) (checked Oct 2026).
- For database sources, its docs say it captures changes with the source's native change data capture mechanism or a Fivetran proprietary method, depending on the database. They also say database connectors sync new and modified data every 15 minutes by default, per the [database connector docs](https://fivetran.com/docs/connectors/databases) (checked Oct 2026).
- Each connection is billed on its own volume curve, so the per-row rate falls as one connection grows. On Standard it goes from $495 per million rows at the start to $170 per million past 1M rows and $58 per million past 4M, per the [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) (checked Oct 2026).
- Transformations get 5,000 model runs a month free, then $0.01 per run up to 30,000, $0.007 up to 100,000 and $0.002 beyond that, per the [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) (checked Oct 2026).

**Where it falls short**

- Paid list rates live in a separate table, and each connection has its own curve, so you need rows per connection to predict a bill. The [table](https://www.fivetran.com/legal/service-consumption-table) also says you cannot combine rows across connections to get a better rate (checked Oct 2026).
- Our read: the $5 base per connection is the easiest line to miss, per the [pricing page](https://www.fivetran.com/pricing) (checked Oct 2026). By the consumption table formula, 20 connections of 2,000 rows each come to $119.80 a month (our arithmetic).
- Deleted rows also count as paid rows: the [pricing page](https://www.fivetran.com/pricing) counts updates as modifications to existing rows in your destination, including deletes (checked Oct 2026).
- Teleport Sync is its option when you cannot or do not want to give Fivetran access to your database's change logs. The docs say that if you update large portions of a table between syncs it may be unable to find the changes, and the connection then re-syncs the entire table, per the [database connector docs](https://fivetran.com/docs/connectors/databases) (checked Oct 2026).
- The pricing page calls Oracle and High-Volume Agent connectors "enterprise database connectors", and the Enterprise plan card lists them where Standard lists plain database connectors, per the [pricing page](https://www.fivetran.com/pricing) (checked Oct 2026).

### 2. Airbyte: best for a long connector list with a free self-hosted core

**At a glance**
- Price: Core is free; Cloud Standard $20 a month with 5 credits and $5 per extra credit; Plus from $189 for 40 credits ([Airbyte release notes](https://docs.airbyte.com/release_notes/cloud), September 15, 2026) (checked Oct 2026)

[Airbyte's docs](https://docs.airbyte.com/integrations/) say it has over 600 pre-built connectors, so check the current status of the connector you actually need.

Its [CDC (change data capture) docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) describe log-based replication, but they also say syncs are scheduled and CDC sources aren't treated as infinite streams.

**What's good**

- Per [its docs](https://docs.airbyte.com/platform/), you can self-host the free core or pay for the cloud, and build connectors with a no-code builder or a Python kit. We did not test how well any of these work.
- Plus runs from 40 credits for $189 ($4.75 a credit) up to 2,000 credits for $4,999, and overage credits fall from $5 to $2.50 on the top tier. All Plus plans include 15-minute syncs, two workspaces, single sign-on and premium support, per the [release notes](https://docs.airbyte.com/release_notes/cloud) (checked Oct 2026).
- Unused Cloud credits now roll over for 3 months, up from 2, and Cloud free trials last 14 days, per the [release notes](https://docs.airbyte.com/release_notes/cloud) (checked Oct 2026).
- Its CDC docs list Postgres, MySQL, Microsoft SQL Server, MongoDB, Oracle, SAP HANA and IBM Db2 under current support. They name no plan or connector support level for Oracle, SAP HANA or Db2, per [Airbyte's CDC docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) (checked Oct 2026).

**Where it falls short**

- It isn't a continuous streaming tool: CDC syncs are launched on a sync interval, and the [CDC docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) say "We do not treat CDC sources as infinite streaming sources." (checked Oct 2026)
- For most sources, CDC incremental sync works only for tables with primary keys, and a refresh is required after any new table or collection is added to a CDC connection, per the [CDC docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) (checked Oct 2026).
- Changes made by `TRUNCATE` or `ALTER` won't appear in the logs, so they don't reach the destination, per the [CDC docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) (checked Oct 2026).
- On Cloud Standard, scheduled or cron syncs can run at most every 60 minutes and an organization gets 1 workspace; Plus allows every 15 minutes, per [Airbyte's Cloud limits docs](https://docs.airbyte.com/platform/cloud/managing-airbyte-cloud/understand-airbyte-cloud-limits) (checked Oct 2026). SSO is no longer available on Standard, except for existing users who keep their plan, per [Airbyte's Cloud release notes](https://docs.airbyte.com/release_notes/cloud) (checked Oct 2026).
- Standard got dearer in September 2026: the base price rose from $10 to $20 a month, free credits from 4 to 5 and extra credits from $2.50 to $5.00, per the [release notes](https://docs.airbyte.com/release_notes/cloud) (checked Oct 2026).
- The core uses the Elastic License 2.0, and [Airbyte's license FAQ](https://docs.airbyte.com/platform/developer-guides/licenses/license-faq) says it stops you providing the products to others as a managed service (checked Oct 2026).

### 3. Hevo: best for small teams that want no-code pipelines into a warehouse

**At a glance**
- Price: Free up to 1M events a month (each insert, update or delete in the destination is one event); Starter $265 a month on annual billing, or $299 monthly, from 5M events, per the [Hevo pricing page](https://hevodata.com/pricing/) (checked Oct 2026)

Hevo's [pricing page](https://hevodata.com/pricing/) (checked Oct 2026) lists 150+ connectors. Streaming pipelines show up on the custom Business Critical card, and its comparison table also lists them for Professional.

**What's good**

- Its free plan lets you try it with real data before you pay, per the [pricing page](https://hevodata.com/pricing/) (checked Oct 2026).
- The Free plan is $0 forever with up to 1M events a month and up to 5 users. Starter adds up to 10 users, 150+ connectors, a dbt integration and SSH/SSL, per the [pricing page](https://hevodata.com/pricing/) (checked Oct 2026).
- Professional is $849 a month, or $750 on annual billing, from 20M events, per the [pricing page](https://hevodata.com/pricing/) (checked Oct 2026).
- Its docs list the log read for each log-based source: BinLog for MySQL, logical replication for PostgreSQL, Streams for DynamoDB, Change Streams or OpLog for MongoDB, Change Tracking for SQL Server and Redo Logs for Oracle, per [Hevo's log-based pipelines docs](https://docs.hevodata.com/pipelines/working-with-pipelines/log-based-pipelines/).

**Where it falls short**

- Every update is an event, so busy tables eat a quota fast. The [pricing page](https://hevodata.com/pricing/) counts each insert, update or delete in the destination as one event (checked Oct 2026).
- Usage above your plan's quota is on-demand and charged on top of the plan, and the page shows no rate for it, per the [pricing page](https://hevodata.com/pricing/) (checked Oct 2026).
- Its docs say streaming pipelines cover those log-based sources except SQL Server and DynamoDB, and you must contact Hevo Sales to enable them, per [Hevo's log-based pipelines docs](https://docs.hevodata.com/pipelines/working-with-pipelines/log-based-pipelines/) (checked Oct 2026).
- The comparison table gives a 1-hour sync frequency on Free and Starter, per the [pricing page](https://hevodata.com/pricing/) (checked Oct 2026).
- Its connector list is also smaller than Fivetran's or Airbyte's: [Hevo lists 150+](https://hevodata.com/pricing/), [Fivetran 700+](https://www.fivetran.com/pricing) and [Airbyte's docs over 600](https://docs.airbyte.com/integrations/) (checked Oct 2026).
- The Free card says "Free forever for limited connectors", while all available connectors start at Starter, per the [pricing page](https://hevodata.com/pricing/) (checked Oct 2026).

### 4. OLake Go: best for copying Postgres, MySQL, MongoDB or SQL Server into Iceberg

<img src="/img/logo/olake-blue-with-text.svg" alt="OLake" height="32" style={{display: 'block', margin: '2px 0 14px'}} />

![OLake home page showing its headline and main navigation](/img/blog/2026/10/landing-olake.webp)

*OLake home page, October 2026.*

**At a glance**
- Price: Open source under [Apache 2.0](https://github.com/datazip-inc/olake); you run it on your own infrastructure with [Docker](/docs/install/docker-cli/), [Helm on Kubernetes](/docs/install/kubernetes/) or the [OLake UI](/docs/install/olake-ui/)

OLake Go copies [PostgreSQL](/docs/connectors/postgres/), [MySQL and MariaDB](/docs/connectors/mysql/), [MongoDB](/docs/connectors/mongodb/) and [SQL Server](/docs/connectors/mssql/) with a full load plus change data capture, and writes Apache Iceberg tables or Parquet files on storage you control. [Oracle](/docs/connectors/oracle/), [Db2](/docs/connectors/db2/), [S3](/docs/connectors/s3/) and [Kafka](/docs/connectors/kafka/) also work as sources, without database change capture.

**What's good**

- One tool does the first load and then the change capture, with Full Refresh, Full Refresh + Incremental, Full Refresh + CDC and CDC Only sync modes ([docs](/docs/)).
- It writes Iceberg tables to catalogs such as [AWS Glue](/docs/writers/iceberg/catalog/glue/), with eleven catalog types listed on the [catalog compatibility page](/docs/understanding/compatibility-catalogs/).
- Those catalogs include [Snowflake Horizon](/docs/writers/iceberg/catalog/rest/?rest-catalog=horizon) (OLake Go v0.11.0 and later), so OLake Go can create Iceberg tables in a Snowflake database. They also include [BigLake](/docs/writers/iceberg/catalog/rest/?rest-catalog=biglake) for Google Cloud and [Unity Catalog](/docs/writers/iceberg/catalog/rest/?rest-catalog=unity) for Databricks.
- Engines such as Athena, Spark, Flink and Trino can read the Iceberg tables it writes ([query engine compatibility](/docs/understanding/compatibility-engines/)).
- Syncs are stateful and resumable: after a crash, a network failure or a pause they resume from the last checkpoint instead of starting over ([docs](/docs/)).
- Parallel chunking splits large tables into chunks that are read in parallel, in the Full Refresh, Full Refresh + CDC and Full Refresh + Incremental modes ([docs](/docs/)).
- Schema discovery runs at the start of every sync, and a new source column is added to the Iceberg schema automatically ([schema evolution docs](/docs/features/schema/)).
- Jobs run on a schedule, from every minute to a cron expression you write ([job settings docs](/docs/getting-started/job-level-properties/)).
- OLake Fusion, a companion product, compacts the Iceberg tables OLake Go writes ([Fusion docs](/docs/fusion/compaction/types-of-compaction/)).

### 5. Debezium: best for engineers who need every database change as an event

**At a glance**
- Price: Free; you run it yourself; you pay for servers and staff

Its [FAQ](https://debezium.io/documentation/faq/) says Debezium records all row-level changes committed to each database table, so applications can react to insert, update and delete events, though after a failure they can see an event more than once. The [connector index](https://debezium.io/documentation/reference/stable/connectors/index.html) lists eight main source connectors, including PostgreSQL, MySQL, MongoDB, SQL Server and Oracle.

**What's good**

- It's free, and its docs describe delay in the millisecond range for MySQL and PostgreSQL. That is the project's own claim, so test it on your own load, per [Debezium's features page](https://debezium.io/documentation/reference/stable/features.html).
- The connector index lists eight main source connectors: MongoDB, MariaDB, MySQL, PostgreSQL, SQL Server, Oracle, Db2 and Cassandra. Seven more are marked incubating: Vitess, Spanner, Informix, CockroachDB, YashanDB, Ingres and Milvus, per [Debezium's connector index](https://debezium.io/documentation/reference/stable/connectors/index.html).
- Beyond Kafka Connect, the same docs list Debezium Server, a Debezium Operator, a Debezium Management Platform and guides for running on Kubernetes and OpenShift, per the [connector index](https://debezium.io/documentation/reference/stable/connectors/index.html).
- The FAQ says all events within a topic are totally ordered, and that even if events are duplicated during failures the end result after applying them all stays the same, per the [FAQ](https://debezium.io/documentation/faq/).
- The FAQ also says Debezium connectors do not store any information inside the upstream databases, per the [FAQ](https://debezium.io/documentation/faq/).

**Where it falls short**

- It captures changes and nothing more. You still need a place to send them, a way to run it and someone to keep it healthy.
- The FAQ says consumers see every event exactly once only when systems run nominally or shut down gracefully; when things go wrong they can see events at least once, so the destination has to cope with repeats, per the [FAQ](https://debezium.io/documentation/faq/) (checked Oct 2026).
- Running a connector may place additional load on the source database, per the [FAQ](https://debezium.io/documentation/faq/) (checked Oct 2026).
- On MySQL, the FAQ says delete events can be missing when `CASCADE DELETE` statements are used, because those deletions are not part of the binlog, per the [FAQ](https://debezium.io/documentation/faq/) (checked Oct 2026).
- On Amazon RDS for MySQL, `log_bin` is managed by AWS and off by default, and the FAQ's fix is to turn on read replicas or automated backups, per the [FAQ](https://debezium.io/documentation/faq/) (checked Oct 2026).
- Incubating connectors are released for preview and are subject to changes that may not always be backward compatible, per the [connector index](https://debezium.io/documentation/reference/stable/connectors/index.html) (checked Oct 2026).

## Streaming tools: react to each change as it happens

### 6. Apache Kafka: best for moving event streams between many systems

**At a glance**
- Price: Free; managed Kafka is priced by each vendor

[Kafka's own introduction](https://kafka.apache.org/intro) calls it an event streaming platform that publishes, stores and processes streams of events. Its Kafka Connect part continuously imports and exports data from systems such as relational databases. 

**What's good**

- It's free, and [its docs](https://kafka.apache.org/intro) say it stores streams of events durably, which we did not test.
- Events are not deleted after consumption, so a topic can be read as often as needed. How long they are kept is a per-topic setting, per the [Kafka intro](https://kafka.apache.org/intro).
- Any consumer of a topic-partition reads that partition's events in the order they were written, and a common production setting is a replication factor of `3`, meaning three copies of the data, per the [Kafka intro](https://kafka.apache.org/intro) (checked Oct 2026).
- It can run on bare-metal hardware, virtual machines and containers, on-premises or in the cloud, and you can self-manage it or use fully managed services from a variety of vendors, per the [Kafka intro](https://kafka.apache.org/intro).
- Its `4.2` design docs say it supports exactly-once delivery in Kafka Streams, and in the transactional producer paired with a read-committed consumer. The producer also has an idempotent delivery option, so resending does not create duplicate log entries, per [Kafka's design docs](https://kafka.apache.org/42/design/design/) (checked Oct 2026).

**Where it falls short**

- It's a platform you run, and you build the pipeline on top of it. Kafka itself doesn't reshape warehouse tables, and it needs connectors at both ends.
- The [intro](https://kafka.apache.org/intro) describes capture as something a connector does, for example a PostgreSQL connector capturing every change to a set of tables. It describes no Iceberg writer.
- The intro says the Kafka community provides hundreds of ready-to-use connectors, and the Apache project publishes no exact count, per the [Kafka intro](https://kafka.apache.org/intro) (checked Oct 2026).
- Exactly-once is not the default: the `4.2` [design docs](https://kafka.apache.org/42/design/design/) say Kafka guarantees at-least-once delivery by default (checked Oct 2026).

### 7. Apache Flink: best for reshaping streams as they flow

**At a glance**
- Price: Free; you pay for servers and staff

[Flink's site](https://flink.apache.org/) describes it as "stateful computations over data streams", and it shows `2.3` as the current stable release (checked Oct 2026). The [Apache Iceberg docs](https://iceberg.apache.org/docs/latest/flink-writes/) say the Flink sink for Iceberg guarantees exactly-once semantics.

**What's good**

- [Its site](https://flink.apache.org/) describes stateful computations on streams and, per the [Iceberg docs](https://iceberg.apache.org/docs/latest/flink-writes/), it can write batch and streaming data to Iceberg tables. We did not test either.
- The [Flink home page](https://flink.apache.org/) lists low latency, high throughput and in-memory computing as features.
- The Iceberg docs say it supports `UPSERT` based on the primary key when writing to a `v2` table, per the [Iceberg Flink writes](https://iceberg.apache.org/docs/latest/flink-writes/).
- The same docs say `IcebergSink` can run table maintenance after each commit: compacting small data files, expiring old snapshots and removing orphan files, so a separate maintenance job is not required, per the [Iceberg Flink writes](https://iceberg.apache.org/docs/latest/flink-writes/).

**Where it falls short**

- It's a framework you program and operate, and it's overkill for hourly batch jobs.
- Streaming jobs do not support `INSERT OVERWRITE`; overwrite works in batch jobs, per the [Iceberg Flink writes](https://iceberg.apache.org/docs/latest/flink-writes/) (checked Oct 2026).
- `UPSERT` needs the `v2` table format and a primary key or identifier fields, and `OVERWRITE` and `UPSERT` cannot be enabled at the same time, per the [Iceberg Flink writes](https://iceberg.apache.org/docs/latest/flink-writes/) (checked Oct 2026).
- The Iceberg docs call the newer `SinkV2`-based `IcebergSink` "currently an experimental feature so use it with caution", per the [Iceberg Flink writes](https://iceberg.apache.org/docs/latest/flink-writes/) (checked Oct 2026).
- Iceberg commits happen after a successful Flink checkpoint, in the `notifyCheckpointComplete` callback, so the job needs checkpointing set up, per the [Iceberg Flink writes](https://iceberg.apache.org/docs/latest/flink-writes/) (checked Oct 2026).

## All-in-one cloud services: several jobs, one vendor

### 8. Matillion: best for teams that load and transform inside a cloud warehouse

**At a glance**
- Price: Credits used by task hours; the pricing page shows no dollar price, per the [Matillion pricing page](https://www.matillion.com/pricing) (checked Oct 2026)

Matillion's [pricing page](https://www.matillion.com/pricing) lists Developer, Teams and Scale editions. Its [credit terms](https://www.matillion.com/legal/credit-consumption-terms) charge 1 credit per task hour for scheduling work and transformation 3 credits per task hour (checked Oct 2026).

[Matillion's own comparison blog](https://www.matillion.com/learn/blog/matillion-vs-fivetran) says Maia generates native SQL that runs inside Snowflake, Databricks or AWS Redshift.

**What's good**

- [Matillion's pages](https://www.matillion.com/pricing) describe one product for loading, transforming and scheduling, so there are fewer parts to join. We did not test it.
- Developer lists 1 developer user, unlimited projects, pre-built connectors, a low-code canvas with SQL/Python and a built-in Git repository. Teams adds 5 developer users, an audit log and a Service Level Agreement, and Scale adds custom SSO, hybrid cloud deployment, data lineage tracking and streaming change data capture, per the [pricing page](https://www.matillion.com/pricing) (checked Oct 2026).
- Credits cover task hours and extra developer users, and the pricing FAQ says you can contract directly with Matillion or pay through your AWS, Azure or Snowflake account, per the [pricing page](https://www.matillion.com/pricing).
- Task hours are charged only while a pipeline runs, in 2-second increments, and validation or sampling does not count towards them, per the [credit terms](https://www.matillion.com/legal/credit-consumption-terms).

**Where it falls short**

We found no Apache Iceberg destination in [its docs](https://docs.maia.ai/docs/streaming/streaming-pipelines) (checked Oct 2026).
- Extra developer users cost credits: the credit terms list 70 credits per Developer User a month. Customer support on the Developer edition is community support, with Standard on Teams, per the [credit terms](https://www.matillion.com/legal/credit-consumption-terms) and [pricing page](https://www.matillion.com/pricing) (checked Oct 2026).

- Streaming schema changes are driven by data rather than DDL, so a change to a source table is not reflected in the target until the data changes. A column dropped at the source stays in the destination, with later values inserted as `NULL`, per [Maia's streaming docs](https://docs.maia.ai/docs/streaming/streaming-pipelines) (checked Oct 2026).

**What's good**

## Transformation: reshape data once it has landed

### 11. dbt: best for SQL-first teams that model data in a warehouse

**At a glance**

**What's good**

**Where it falls short**

- Nothing happens until data is already in the warehouse, so you have to add a loader. The [docs](https://docs.getdbt.com/docs/introduction) say dbt works alongside your ingestion tools.
- The free Developer plan allows only one seat, one project and 3,000 successful models built a month, per the [pricing page](https://www.getdbt.com/pricing) (checked Oct 2026).
- Billing counts models that build successfully even if the overall run later fails: a job of 100 models that fails after 51 are built counts as 51, per [dbt's billing docs](https://docs.getdbt.com/docs/platform/billing/how-pricing-works) (checked Oct 2026).
- The dbt State add-on is priced on its own, at $0.094 per daily active target table pay as you go, per the [pricing page](https://www.getdbt.com/pricing) (checked Oct 2026).
- Starter allows 1 project, against 30 on Enterprise, per the [pricing page](https://www.getdbt.com/pricing) (checked Oct 2026).

## How to choose, in five questions

Answer these in order. The first answer usually knocks out half the list.

1. **Which job is missing?** If data isn't landing anywhere yet, start with the ingestion group. If it lands but it's messy, look at dbt. If someone runs steps by hand, look at the schedulers.
2. **How fast must changes show up?** Hourly or slower points to a loader or a batch tool. Seconds points to Debezium, Kafka and Flink, which you run yourself.
3. **Who runs it?** If nobody wants to touch servers, choose a managed tool or a cloud bundle. If you have engineers, free software drops the licence bill and adds the work.
4. **Which cloud are you on?** Inside AWS or Azure, the bundles save you from joining parts.
5. **How does the tool count?** Rows, events, credits, models and compute hours grow in different ways. Work out your own number before you sign anything.
