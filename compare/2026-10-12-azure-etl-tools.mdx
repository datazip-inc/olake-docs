<TLDR title='Key takeaways'>

Start with where your data should land, because that answers half the question. If your analytics live in Microsoft Fabric, look at Fabric mirroring (free replication compute, read-only Delta tables) or a Fabric Copy job. Paying per use outside Fabric?

Azure Data Factory still works, though Microsoft now calls Fabric Data Factory its next generation. On Azure Databricks, use Lakeflow Connect; for lots of SaaS connectors and no servers, look at Fivetran or Hevo. For Azure databases into Iceberg on your own storage, look at OLake Go.

- **Microsoft has two Data Factory products.** Azure Data Factory (ADF) is billed per use. Fabric Data Factory is billed through a Fabric capacity, and [Microsoft's docs](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) call it "the next generation of Azure Data Factory".
- **Fabric mirroring is free to run, but not free to use.** [Microsoft says](https://learn.microsoft.com/en-us/fabric/mirroring/overview) replication compute and storage are free up to a limit (checked Oct 2026). You still need a running Fabric capacity.
- **Log-based change capture is narrower than it looks.** Fabric's [Copy job lists](https://learn.microsoft.com/en-us/fabric/data-factory/copy-job-connectors) change data capture (CDC) in preview for a short list of connectors, and PostgreSQL, MySQL and MongoDB aren't on it.
- **Most Microsoft and Databricks lake paths write Delta, not Iceberg.** Fabric and Databricks Lakeflow Connect write Delta tables. ADF can write Iceberg to Azure Data Lake Storage (ADLS) Gen2, and [Fivetran's docs](https://fivetran.com/docs/destinations/managed-data-lake-service) say its data lake service always writes Iceberg metadata over Parquet files.
- **One printed ADF price doesn't match Microsoft's.** [Hevo's Azure ETL page](https://hevodata.com/learn/azure-etl-tools/) (September 8, 2026) lists ADF at "$0.005/activity run." [Microsoft's price feed](https://prices.azure.com/api/retail/prices?$filter=serviceName%20eq%20'Azure%20Data%20Factory%20v2'%20and%20armRegionName%20eq%20'eastus') shows $1 per 1,000 activity runs (checked Oct 2026), so check the source before you trust any rate you see on a third-party page.

</TLDR>

ETL means extract, transform, load: you copy data out of one system, reshape it, and put it in another. Plenty of teams now load first and reshape later (that's ELT, short for extract, load, transform), and search lumps both under "ETL." So this page covers both kinds, plus a few tools that only copy.

## ETL or ELT? Decide this first

Before you compare any tools, pick the pattern. [Microsoft's ETL guide](https://learn.microsoft.com/en-us/azure/architecture/data-guide/relational-data/etl) says choose ETL for heavy transformation away from a constrained target, complex rules or staging audits. Choose ELT when the target is a lakehouse or warehouse with elastic compute, or when you need raw data kept.

| If this is true | Lean toward | Azure tools that fit |
| --- | --- | --- |
| Your target is Fabric, Databricks or a lake with its own compute | ELT: load raw, reshape in the target | Fabric Copy job and mirroring, Lakeflow Connect, Fivetran, Hevo |
| You must clean or audit data before it lands | ETL: reshape in the pipeline | Azure Data Factory data flows, Matillion, Informatica |

Prices and limits come from each vendor's own pages, read in October 2026. Plans change often, so check the vendor's page before you decide.

We did not run the other tools.

## How we picked

The rules were simple. A tool had to move data into an Azure service or an Azure-hosted lake, and its own pages had to say how you buy it. We read Microsoft's documentation first, then looked at outside tools that name an Azure source or target.

If we couldn't source a tool from a primary page, it's out. The order is *not* a ranking. Entries for other vendors list limits from their own pages, and that includes each Microsoft service.

## Which Azure ETL tools fit where your data lands

Where the data lands removes half the list at once.

![Which Azure ETL option fits by where data lands: Fabric OneLake, Azure SQL or Synapse and lake storage, or Databricks](/img/blog/2026/10/azure-etl-tools-which-fits.webp)

One term you'll see a lot is change data capture (CDC), which means reading a database's own change log instead of re-reading whole tables, so a copy stays fresh without hammering the source.

The [same ETL guide](https://learn.microsoft.com/en-us/azure/architecture/data-guide/relational-data/etl) lists Fabric Data Factory first for pipelines and Azure Data Factory for "hybrid and non-Fabric scenarios". That's the split this page follows.

## The 11 Azure ETL tools

Eleven tools, three groups, starting with the Microsoft services.

### Microsoft services

#### 1. Fabric Data Factory: copy jobs into OneLake

**At a glance**
- Kind: Microsoft's software-as-a-service (SaaS) data movement inside Microsoft Fabric
- Billing: Fabric capacity units (CUs). Copy job meters are 1.5 CU-hours for a full copy and 3 CU-hours for an incremental copy, per the [copy job pricing page](https://learn.microsoft.com/en-us/fabric/data-factory/pricing-copy-job) (checked Oct 2026)
- Entry price: Microsoft's [Fabric pricing page](https://azure.microsoft.com/en-us/pricing/details/microsoft-fabric/) lists F2 (2 capacity units) at $262.80 a month, pay as you go (checked Oct 2026)

Microsoft's [compare page](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) says Fabric Data Factory is "the next generation of Azure Data Factory" and uses OneLake, Fabric's built-in data lake. A Copy job moves data on a schedule, and you don't have to build a pipeline. Per Microsoft's [data movement guide](https://learn.microsoft.com/en-us/fabric/data-factory/decision-guide-data-movement), it can do a full copy, an incremental copy using a watermark column, or CDC replication.

**Where it fits**

- The [data movement guide](https://learn.microsoft.com/en-us/fabric/data-factory/decision-guide-data-movement) says to use a Copy job for raw (bronze) data, because it handles scheduling, column mapping and incremental loads without pipelines.
- Per Microsoft's [Copy job connector page](https://learn.microsoft.com/en-us/fabric/data-factory/copy-job-connectors), it supports append, overwrite, upsert and a history-keeping mode called SCD Type 2 (in preview). It also runs behind firewalls through a gateway (checked Oct 2026).
- The same [connector page](https://learn.microsoft.com/en-us/fabric/data-factory/copy-job-connectors) (last updated 2026-09-16) lists Oracle, PostgreSQL, MySQL, MariaDB, MongoDB, Snowflake, Google BigQuery, Salesforce and Azure Data Lake Storage Gen2 among the sources and destinations for a Copy job.
- [Microsoft says](https://learn.microsoft.com/en-us/fabric/data-factory/copy-job-connectors) CDC in copy jobs "enables automated replication of changed data (including inserted, updated, and deleted records)" from a source to a destination, so deletes are carried over on the supported connectors.
- Microsoft's [compare page](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) says approximately 90% of the activities in Azure Data Factory are already available in Fabric Data Factory, and that billing has "no charges for external or pipeline activities, only activity runs and pipeline data movement" on top of the capacity (checked Oct 2026).

**Where it falls short**

- CDC replication is Preview and covers Azure SQL, SQL Server, Oracle and a few more, but not PostgreSQL, MySQL or MongoDB, per Microsoft's [connector page](https://learn.microsoft.com/en-us/fabric/data-factory/copy-job-connectors) (checked Oct 2026).
- SSIS runtimes and managed virtual networks are "To be determined" in Fabric, per the [compare page](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) (checked Oct 2026). The same page lists the SSIS activity, Synapse Notebook and Spark job definition activities as not available (N/A) in Fabric Data Factory, though ADF has them.
- Incremental copy meters at 3 CU hours against 1.5 for a full copy, and Microsoft says the 3 CU hours rate applies to the initial full load in incremental mode as well as the later runs, per its [Copy job pricing page](https://learn.microsoft.com/en-us/fabric/data-factory/pricing-copy-job) (checked Oct 2026).
- On the [connector page](https://learn.microsoft.com/en-us/fabric/data-factory/copy-job-connectors), SCD Type 2 in Copy job "is currently in preview", and it is not supported yet when you run CDC replication from Oracle sources (checked Oct 2026).
- Microsoft's [Copy job pricing page](https://learn.microsoft.com/en-us/fabric/data-factory/pricing-copy-job) says consumption rates "are subject to change at any time." (checked Oct 2026)

#### 2. Azure Data Factory: hybrid pipelines and SSIS

**At a glance**
- Kind: Microsoft's platform-as-a-service (PaaS) pipeline service
- Billing: $1 per 1,000 activity runs and $0.25 per data integration unit (DIU) hour for copying (East US, US dollars), per [Microsoft's pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) (checked Oct 2026)
- Data flows: $0.274 per vCore-hour with an 8 vCore minimum, on [Microsoft's live page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) (checked Oct 2026)

ADF is, in [Microsoft's words](https://learn.microsoft.com/en-us/azure/data-factory/introduction), a managed cloud service for hybrid ETL, ELT and data integration. It runs copies, data flows and SQL Server Integration Services (SSIS) packages. A self-hosted runtime reaches data on your own network.

**Where it fits**

- It has a self-hosted runtime for on-premises data and runs SSIS packages. Microsoft's [compare page](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) lists the SSIS activity as available in ADF and N/A in Fabric Data Factory, and Azure-SSIS integration runtimes as "To be determined" in Fabric (checked Oct 2026).
- Microsoft's [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) shows the meters, and [Microsoft's retail price feed](https://prices.azure.com/api/retail/prices?$filter=serviceName%20eq%20'Azure%20Data%20Factory%20v2'%20and%20armRegionName%20eq%20'eastus') lists a one-year reservation for data flows at $1,795, about $0.205 per vCore-hour by our arithmetic (checked Oct 2026).
- Integration runtime charges on the [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) are "prorated by the minute and rounded up", so you pay by the minute rather than by the hour (checked Oct 2026).
- Microsoft's [change data capture page](https://learn.microsoft.com/en-us/azure/data-factory/concepts-change-data-capture) says native CDC in mapping data flow uses the database's own change capture with "no timestamp or ID columns" needed, and that "Pipelines in ADF are batch only, but the CDC resource can run continuously." (checked Oct 2026)
- Its [Iceberg format page](https://learn.microsoft.com/en-us/azure/data-factory/format-iceberg) describes an Iceberg sink in the Copy activity (IcebergSink) that writes to Azure Data Lake Storage Gen2 (checked Oct 2026).

**Where it falls short**

- Microsoft says, "If you're new to data integration, start with Fabric Data Factory," on the [Azure Data Factory Iceberg format page](https://learn.microsoft.com/en-us/azure/data-factory/format-iceberg), and new Fabric features "aren't backported to Azure Data Factory or Azure Synapse pipelines," per the [compare page](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) (checked Oct 2026).
- Native CDC covers SAP, Azure SQL, SQL Server, Cosmos DB and Snowflake. On the [CDC page](https://learn.microsoft.com/en-us/azure/data-factory/concepts-change-data-capture), MySQL and PostgreSQL appear only under auto incremental extraction, where "the incremental column is required to identify the changes," and, per the [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/), the CDC resource is billed at General Purpose rates for four cores during the public preview of CDC (checked Oct 2026).
- The [Iceberg format page](https://learn.microsoft.com/en-us/azure/data-factory/format-iceberg) lists Azure Data Lake Storage Gen2 as the only connector and shows no catalog setting and no update, delete or merge setting (checked Oct 2026).
- Data flows have an 8 vCore minimum and also bill for the managed disk and blob storage they use. Copying data out of an Azure datacenter adds a separate outbound transfer line, per the [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) (checked Oct 2026).
- The [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) FAQ says an inactive pipeline, one with zero runs in a month, is charged after one month of zero runs (checked Oct 2026).
- Text copies of the [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) show "$-" until the rates load, so check your region's numbers yourself.

#### 3. Fabric mirroring: free, read-only copies of databases

**At a glance**
- Kind: managed replication into OneLake, not a general ETL tool
- Sources listed: Azure SQL Database, Azure SQL Managed Instance, Azure Database for PostgreSQL, Azure Cosmos DB, Azure Database for MySQL (preview), SQL Server, Oracle, Snowflake and more, per the [mirroring overview](https://learn.microsoft.com/en-us/fabric/mirroring/overview) (checked Oct 2026)
- Billing: replication compute is free, and storage is free up to 1 TB per capacity unit you buy, per the [mirroring overview](https://learn.microsoft.com/en-us/fabric/mirroring/overview) (checked Oct 2026)

Mirroring keeps copying a database into OneLake as Delta tables, an open table format built on Parquet files. [Microsoft says](https://learn.microsoft.com/en-us/fabric/mirroring/overview) changes "can be published as fast as every 15 seconds," a figure we did not test (checked Oct 2026). Its [data movement guide](https://learn.microsoft.com/en-us/fabric/data-factory/decision-guide-data-movement) calls mirroring the simplest choice for processed (gold) data you only need to report on.

**Where it fits**

- Microsoft's [docs](https://learn.microsoft.com/en-us/fabric/mirroring/overview) describe setup as a connection and a table choice, with no pipelines to build or schedule. We did not try it.
- Background replication compute "is free and doesn't consume capacity," per Microsoft's [overview](https://learn.microsoft.com/en-us/fabric/mirroring/overview) (checked Oct 2026).
- The [overview](https://learn.microsoft.com/en-us/fabric/mirroring/overview) also says the free storage allowance is one terabyte for every capacity unit you buy, so an F64 capacity gets 64 free terabytes used only for mirroring (checked Oct 2026).
- The [overview table](https://learn.microsoft.com/en-us/fabric/mirroring/overview) lists database mirroring for Azure Cosmos DB, Azure Database for PostgreSQL, Azure SQL Database, Oracle, Google BigQuery, SAP, Snowflake and SQL Server, metadata mirroring for Azure Databricks, and an open mirroring option.
- Microsoft's [OneLake page](https://learn.microsoft.com/en-us/fabric/onelake/onelake-iceberg-tables) says Delta Lake tables now include virtual Iceberg metadata, so Iceberg readers can open them, and that generating the metadata can take between 5 seconds and 2 minutes (checked Oct 2026).

**Where it falls short**

- A running Fabric capacity is required, and storage beyond the free limit is billed, per the [mirroring overview](https://learn.microsoft.com/en-us/fabric/mirroring/overview) (checked Oct 2026).
- Mirroring writes to "a single, read-only destination in OneLake," per the [data movement guide](https://learn.microsoft.com/en-us/fabric/data-factory/decision-guide-data-movement), and Microsoft's comparison table shows no custom scheduling or table and column management for it (checked Oct 2026).
- On SQL Server 2016 to 2022, a schema change makes mirroring fail until you disable and re-enable CDC on that table, per Microsoft's [SQL Server limitations page](https://learn.microsoft.com/en-us/fabric/mirroring/sql-server-limitations) (checked Oct 2026).
- SQL Server mirroring copies up to 1,000 tables and does not replicate tables above that limit, per the [same page](https://learn.microsoft.com/en-us/fabric/mirroring/sql-server-limitations). Microsoft's [Azure PostgreSQL mirroring limitations page](https://learn.microsoft.com/en-us/fabric/mirroring/azure-database-postgresql-limitations) sets the same 1,000-table cap and allows one Fabric item per database (checked Oct 2026).
- On Azure Database for PostgreSQL, DDL changes and TRUNCATE TABLE on mirrored tables are not supported, and stopping mirroring and starting it again reseeds all the tables, per the [Azure PostgreSQL limitations page](https://learn.microsoft.com/en-us/fabric/mirroring/azure-database-postgresql-limitations) (checked Oct 2026).
- The same [PostgreSQL page](https://learn.microsoft.com/en-us/fabric/mirroring/azure-database-postgresql-limitations) says columns of several data types, including inet, json, jsonb and xml, cannot be mirrored, and views, materialized views and partitioned tables are not supported (checked Oct 2026).

Before you rely on it, check how fresh your tables stay under load, because Microsoft's refresh figure is not a guarantee.

#### 4. Azure Synapse pipelines: teams already in a Synapse workspace

**At a glance**
- Kind: the pipeline feature inside Azure Synapse Analytics
- Sources: [Microsoft's overview](https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is) lists ingestion from 90+ data sources
- Billing: the [Synapse pricing page](https://azure.microsoft.com/en-us/pricing/details/synapse-analytics/) text shows "$-" for pipeline, serverless and dedicated pool rates (checked Oct 2026)

Microsoft's [compare page](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) names Azure Data Factory and Azure Synapse pipelines together when it describes what Fabric changes.

**Where it fits**

- Microsoft's [Synapse overview](https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is) describes one workspace that combines SQL, Spark, Data Explorer and pipelines, with both serverless and dedicated SQL resource models.
- The [same page](https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is) advises creating dedicated SQL pools "for predictable performance and cost" and using the serverless SQL endpoint for unplanned or bursty workloads.

**Where it falls short**

- [Microsoft says](https://learn.microsoft.com/en-us/fabric/data-factory/compare-fabric-data-factory-and-azure-data-factory) new Fabric Data Factory features "aren't backported to Azure Data Factory or Azure Synapse pipelines," and that Fabric replaces Azure Synapse Link with mirroring (checked Oct 2026).
- We couldn't read a dollar rate for pipelines from that [pricing page](https://azure.microsoft.com/en-us/pricing/details/synapse-analytics/).
- Microsoft hasn't published a retirement notice on the pages we read, so we don't call Synapse retired. The [overview page](https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is) itself shows "Last updated on 2024-07-12".
- The [overview](https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is) names Delta Lake support for Spark, but it does not state Iceberg output or change data capture for pipelines.

### Databricks on Azure

#### 5. Azure Databricks Lakeflow Connect: databases into Databricks

**At a glance**
- Kind: managed connectors inside Azure Databricks
- Databases with CDC: MySQL, PostgreSQL, Microsoft SQL Server, and Oracle (through LogMiner), per the [Azure Databricks database connectors page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/cdc-overview) (checked Oct 2026)
- Billing: Databricks Units (DBUs) per second, per the [Databricks pricing page](https://www.databricks.com/product/pricing) (checked Oct 2026). Azure rates were not captured for this post

Microsoft's [Azure Databricks docs](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/cdc-overview) (last updated 2026-09-11) describe connectors that track changes and apply them to Delta tables. Other connector types cover SaaS apps, files, message buses and plain queries, per the [ingestion overview](https://learn.microsoft.com/en-us/azure/databricks/ingestion/overview).

**Where it fits**

- One connector family lists change data capture for four popular databases. Microsoft's [MySQL connector page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/mysql) says the MySQL connector is in Public Preview and access is by request through your Azure Databricks account team (checked Oct 2026).
- Governance comes from Unity Catalog, Databricks' own catalog.
- Changes land in a staging volume first, so the [docs](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/cdc-overview) say you can run the ingestion pipeline "at whatever schedule you'd like" while the gateway keeps capturing changes, and the pipeline itself runs on serverless compute.
- Cross-cloud connectivity is supported: the [database connector page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/cdc-overview) gives an Azure Databricks workspace ingesting from an AWS Aurora PostgreSQL database as an example, if the network path exists.
- The [MySQL connector page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/mysql) lists SCD type 2, API-based column selection and automated handling of new and deleted columns as supported (checked Oct 2026).

**Where it falls short**

- The ingestion gateway "runs continuously" on classic compute, and per the [database connector page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/cdc-overview), "you provision and pay for its classic compute even when your ingestion pipeline is idle." The same page warns the initial snapshot can fail on undersized compute (checked Oct 2026).
- Destination tables are streaming tables, "which are Delta tables" with extra support for incremental processing. MongoDB is not in the [database connector list](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/cdc-overview) (checked Oct 2026).
- On the [MySQL page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/mysql), a pipeline can hold at most 250 tables, and automated schema evolution of data type changes is not supported (checked Oct 2026).
- Authentication for MySQL is username and password only. OAuth U2M, OAuth M2M and OAuth with a manual refresh token are all listed as not supported on the [same page](https://learn.microsoft.com/en-us/azure/databricks/ingestion/lakeflow-connect/mysql) (checked Oct 2026).

### Outside tools that run on Azure

#### 6. OLake Go: best for Azure databases into Iceberg on your own storage

<img src="/img/logo/olake-blue-with-text.svg" alt="OLake" height="32" style={{display: 'block', margin: '2px 0 14px'}} />

**At a glance**

- Kind: open-source database replication, licensed [Apache 2.0](https://github.com/datazip-inc/olake)
- Docs: [Iceberg on Azure](/docs/writers/iceberg/azure/), [Postgres connector](/docs/connectors/postgres/) and [MySQL connector](/docs/connectors/mysql/)
- Runs: on your own infrastructure
- Support: [contact the OLake team](/contact/)

OLake Go captures changes from Postgres, MySQL/MariaDB, MongoDB and SQL Server ([Postgres](/docs/connectors/postgres/), [MySQL](/docs/connectors/mysql/), [MongoDB](/docs/connectors/mongodb/), [SQL Server](/docs/connectors/mssql/)), and it writes Apache Iceberg or Parquet. You run it yourself with [Docker](/docs/install/docker-cli/), [Helm on Kubernetes](/docs/install/kubernetes/) or the [OLake UI](/docs/install/olake-ui/).

**What's good**

- Our [Iceberg on Azure guide](/docs/writers/iceberg/azure/) shows OLake Go writing Iceberg-compatible Parquet files directly to Azure Data Lake Storage (ADLS) Gen2 and updating the catalog, with Lakekeeper as the open-source REST catalog.
- Lakekeeper is one of eleven catalog types on the [catalog compatibility page](/docs/understanding/compatibility-catalogs/), so the Azure route is not tied to one catalog.
- Our [Postgres connector docs](/docs/connectors/postgres/) cover change capture with the native `pgoutput` plugin, a replication slot and a publication, and list a guide for Azure Database for PostgreSQL.
- Our [MySQL connector docs](/docs/connectors/mysql/) cover the binary log settings (ROW format) that change capture needs, and list a guide for Azure Database for MySQL.

#### 7. Fivetran: many connectors with no servers

**At a glance**
- Kind: managed ELT service
- Free plan: up to 500,000 monthly active rows (MAR) for connections, per Fivetran's [pricing page](https://www.fivetran.com/pricing) (checked Oct 2026)
- Pay as you go: $5 base charge per connection using 1 to 1M MAR, per Fivetran's [pricing page](https://www.fivetran.com/pricing) (checked Oct 2026)

Fivetran's [docs](https://fivetran.com/docs/destinations/managed-data-lake-service) describe a Managed Data Lake Service that writes to Azure Data Lake Storage. Its [database docs](https://fivetran.com/docs/connectors/databases) name SQL Server CDC and Change Tracking, MySQL binary logs and Azure Cosmos DB change feed as capture methods.

**Where it fits**

- Fivetran says it runs the pipelines for you (we did not test that), and its [free plan](https://www.fivetran.com/pricing) covers up to the row limit (checked Oct 2026).
- Per its [Managed Data Lake Service docs](https://fivetran.com/docs/destinations/managed-data-lake-service), the service supports Azure Data Lake Storage, writes Parquet files to your own storage and always creates Iceberg table metadata for them.
- Its [database connector docs](https://fivetran.com/docs/connectors/databases) say database connectors sync new and modified data every 15 minutes by default, applied to the destination in batches with a merge operation. They list PostgreSQL logical replication and MongoDB change streams as further capture methods (checked Oct 2026).
- Its [catalog docs](https://fivetran.com/docs/destinations/managed-data-lake-service/metadata-catalogs) say Fivetran Catalog is built on Apache Polaris and implements the Iceberg OpenAPI specification, so a compatible Iceberg REST client can connect. With Delta Lake metadata turned on, Fivetran publishes the Delta metadata to OneLake.
- Its [usage docs](https://fivetran.com/docs/usage-based-pricing) say a row is counted once a month however many times it syncs, and some re-syncs, such as historical data after you add a column, are free (checked Oct 2026).

**Where it falls short**

- Per its [data lake docs](https://fivetran.com/docs/destinations/managed-data-lake-service), there is no support for Iceberg position deletes, and decimal values beyond precision 38 or scale 10 are converted to DECIMAL(38,10) (checked Oct 2026).
- The OneLake catalog route applies only to tables with Delta Lake metadata, which Fivetran creates only if you turn it on, per its [catalog docs](https://fivetran.com/docs/destinations/managed-data-lake-service/metadata-catalogs) (checked Oct 2026).
- The pricing page prints no per-row rate, but Fivetran's [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) (checked Oct 2026) does. Standard starts at $495 per million MAR plus a $5 base per connection, list price before discounts (version 10, effective February 1, 2026). Deletes count as paid rows, per the [usage docs](https://fivetran.com/docs/usage-based-pricing).
- The [database docs](https://fivetran.com/docs/connectors/databases) say schema changes in the source are "the most common trigger for a full table re-sync," and expired change logs require a full source re-sync. If large portions of a table change between syncs, Teleport Sync may be unable to find the changes and re-syncs the entire table (checked Oct 2026).
- The [catalog docs](https://fivetran.com/docs/destinations/managed-data-lake-service/metadata-catalogs) warn that modifying Fivetran-delivered tables directly with write credentials "can corrupt the tables and disrupt downstream workflows."
- Per Fivetran's [usage docs](https://fivetran.com/docs/usage-based-pricing), two connections that sync the same data count separately toward your monthly active rows, and a rollback sync "may fetch additional data from the previous month" that counts as new records (checked Oct 2026).

**At a glance**
- Kind: ELT with a free self-hosted Core and a paid cloud
- Core: free to self-host; you pay for servers and staff ([Airbyte's pricing page](https://airbyte.com/pricing)) (checked Oct 2026)

| Airbyte | [CSV or JSON Lines in Blob Storage](https://docs.airbyte.com/integrations/destinations/azure-blob-storage) | No Iceberg or Parquet on the page (checked Oct 2026) |

## Conclusion

The right tool depends on where your data lands. Before you commit, run one real table through two finalists, then confirm the rates on the vendor's page.

| Test | What to check | Why it matters |
| --- | --- | --- |
| Change a column | Does the pipeline adapt, fail or ignore it? | Mirroring on SQL Server 2016 to 2022 fails until CDC is re-enabled on that table |
| Delete a row | Does the target remove it, mark it, or keep it? | Fivetran counts deletes as paid rows, and its lake service has no Iceberg position deletes |
| Leave it idle for a day | What does the bill show? | Lakeflow Connect's gateway is paid even when idle, and a Fabric capacity must keep running for mirroring |
| Read the output with a second engine | Can another tool open the files? | [Fabric](https://learn.microsoft.com/en-us/fabric/onelake/onelake-iceberg-tables) and Databricks write Delta, and [ADF](https://learn.microsoft.com/en-us/azure/data-factory/format-iceberg), [Fivetran](https://fivetran.com/docs/destinations/managed-data-lake-service) and [OLake Go](/docs/writers/iceberg/azure/) each document Iceberg on ADLS |
