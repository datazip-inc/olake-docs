<TLDR title='Key takeaways'>

There's no single best Oracle replication tool, because the tools answer different questions. Oracle Active Data Guard copies a whole Oracle database to another Oracle database, and Oracle GoldenGate moves changes to other systems for a licence fee.

Qlik Replicate, Striim, Quest SharePlex, Fivetran, AWS Database Migration Service (DMS) and Google Datastream read Oracle for you, and Debezium is the open-source log reader. OLake Go copies Oracle tables into Iceberg or Parquet on a schedule. Before you shortlist anything, check how the tool reads Oracle's logs, whether that route needs a GoldenGate licence, and where your data has to land.

- **How a tool reads Oracle's logs, and one logging setting, decide licence and risk.** LogMiner needs no extra licence unless GoldenGate Supplemental Logging is on, XStream generally needs a GoldenGate licence, and a tool that parses log files itself is called [unsupported by Oracle](https://www.oracle.com/a/ocom/docs/techpaper-goldengate-advantages.pdf).
- **Log retention and large objects bite first.** Archived logs must be kept long enough, and several tools handle large-object columns badly.

</TLDR>

We checked prices and facts in October 2026 against each vendor's own pages.

## How we picked

We included tools that copy data out of Oracle, by reading its logs or by scheduled table reads, are still sold or maintained, and publish documentation we could open. We compared how each tool reads Oracle, the licence rule that follows, the price basis, where data lands, and the documented limits.

Vendor facts come from each vendor's own pages and docs, read in October 2026. We did not run the other tools. Entries are grouped by maker and carry no ranking. This page covers Oracle only; for tools across many databases, see our [best change data capture tools](/compare/best-change-data-capture-tools/) and [best data replication tools](/compare/best-data-replication-tools/) comparisons.

One term you'll see a lot: change data capture (CDC) means finding the inserts, updates and deletes in a database and sending only those on.

## First, pick how the tool reads Oracle

Oracle writes every change to redo logs, which are files where the database records each change in order. When a log fills up, Oracle copies it to an archived redo log.

Log-based tools read these files. How they read them sets the licence rule and the risks.

![LogMiner and XStream read redo logs through Oracle itself, while a direct reader parses log files outside the database](/img/blog/2026/10/oracle-replication-tools-where-readers-run.webp)

| Method | How it reads Oracle | Oracle licence | Limits that Oracle or vendors document |
| --- | --- | --- | --- |
| LogMiner | Oracle's built-in utility reads redo and archived logs through SQL | [Oracle's GoldenGate Advantages paper](https://www.oracle.com/a/ocom/docs/techpaper-goldengate-advantages.pdf) says it is accessible without additional licensing. Oracle's [licensing guide](https://docs.oracle.com/en/database/oracle/oracle-database/26/dblic/Licensing-Information.html) adds one condition, covered below | Needs at least minimal supplemental logging; table and column names over `30` characters are not supported; [Oracle's paper](https://www.oracle.com/a/ocom/docs/techpaper-goldengate-advantages.pdf) says it was designed for diagnostics, not high-volume continuous replication, and is single-threaded |
| XStream | An Oracle programming interface that streams changes out of the redo log | [Oracle's paper](https://www.oracle.com/a/ocom/docs/techpaper-goldengate-advantages.pdf) says use generally needs GoldenGate for Oracle licences on each database where it is used | The tool must track how far it has read (checkpoints) and handle large objects itself |
| GoldenGate Extract | Oracle's own capture process, which writes GoldenGate's own change record, a trail file | A GoldenGate licence | Cost and setup effort |
| Direct log reading | The tool parses redo and archive files itself | [Oracle's paper](https://www.oracle.com/a/ocom/docs/techpaper-goldengate-advantages.pdf) says it does not support this approach, and that its Master Agreement addresses reverse engineering | Oracle's log format is undocumented, per the [OpenLogReplicator project](https://github.com/bersler/OpenLogReplicator) |

Sources: [Oracle's GoldenGate Advantages paper](https://www.oracle.com/a/ocom/docs/techpaper-goldengate-advantages.pdf) (undated, with references accessed in June 2026) and the [LogMiner documentation](https://docs.oracle.com/en/database/oracle/oracle-database/26/sutil/oracle-logminer-utility.html) for Oracle `26ai` (checked Oct 2026).

### One setting can turn a free reader into a licensed one

Oracle's [Licensing Information guide](https://docs.oracle.com/en/database/oracle/oracle-database/26/dblic/Licensing-Information.html) for Oracle `26ai` says LogMiner is available in all offerings. Then it adds that when LogMiner is used with GoldenGate Supplemental Logging turned on, a GoldenGate licence is required.

That logging is on when the database parameter `ENABLE_GOLDENGATE_REPLICATION` is `TRUE`.

For on-premises databases, [the same guide](https://docs.oracle.com/en/database/oracle/oracle-database/26/dblic/Licensing-Information.html) says a GoldenGate licence is required "regardless of which APIs are used for log consumption (e.g., LogMiner, XStream or 3rd party tools)". The setting decides the licence, whatever the tool is called.

We found no vendor page that says whether its setup turns the parameter on, so ask each vendor.

![Oracle's licence follows the GoldenGate logging parameter: off means LogMiner needs no GoldenGate licence, on means any reader needs one](/img/blog/2026/10/oracle-replication-tools-licence-switch.webp)

*Original diagram, drawn from Oracle's Licensing Information guide for Oracle `26ai`, accessed October 2026.*

Caveat: Oracle sells GoldenGate, so its papers are a vendor view. It names no tool, though.

Quick definition: supplemental logging is an Oracle setting that adds extra detail to the redo log so tools can rebuild a full row. LogMiner needs at least the minimal level ([LogMiner docs](https://docs.oracle.com/en/database/oracle/oracle-database/26/sutil/oracle-logminer-utility.html)), and [Debezium's Oracle setup guide](https://debezium.io/documentation/reference/stable/connectors/oracle.html) also asks for all-column logging on captured tables.

Oracle's [LogMiner documentation](https://docs.oracle.com/en/database/oracle/oracle-database/26/sutil/oracle-logminer-utility.html) says the `continuous_mine` option was desupported in Oracle `19c`, and it still documents LogMiner for `26ai`.

## The 11 best Oracle replication tools

Grouped by who makes them. The order carries no ranking.

### Made by Oracle

#### 1. Oracle GoldenGate: for Oracle estates with a licence budget

**At a glance**

- Price: Licensed per processor or Named User Plus on premises, at both the capture and apply ends. [Oracle's price list](https://www.oracle.com/a/ocom/docs/corporate/pricing/technology-price-list-070617.pdf) of 15 September 2026 shows GoldenGate at $17,500 per processor ($350 per Named User Plus) with $3,850 of support for the first year (checked Oct 2026). GoldenGate for Distributed Applications and Analytics is $20,000 per processor ($400 per Named User Plus), counted on the source side only ([price list](https://www.oracle.com/a/ocom/docs/corporate/pricing/technology-price-list-070617.pdf), checked Oct 2026). Oracle Cloud bills per [OCPU per minute](https://docs.oracle.com/en/cloud/paas/goldengate-service/ocigg/ocpu-management-and-billing.html), and [GoldenGate Free](https://docs.oracle.com/en/middleware/goldengate/free/21/uggfe/what-is-goldengate-free.html) costs nothing for databases of 20 GB or smaller (checked Oct 2026)

[Oracle's GoldenGate FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html) says Extract captures changes from the source database's redo or transaction logs and writes them to a trail file. GoldenGate `26ai` supports Oracle Database `19c` to `26ai` and later, and the `19c` and `21c` releases cover Oracle `11.2.0.4` to `21c`.

The [FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html) lists plenty of targets, including MySQL, PostgreSQL, SQL Server, Kafka and Apache Iceberg.

**What's good**

- The [FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html) also names Db2, Hadoop, Snowflake, Parquet, Avro, MongoDB and Cassandra among its supported databases and targets, and Oracle says GoldenGate supports hundreds of sources and targets.
- Per [Oracle's high availability guide](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html), it fits a read/write replica, multimaster and bidirectional replication, subset and many-to-one replication, data transformations, and replication between endian formats or across database major versions.
- The [FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html) lists unidirectional, bidirectional and multi-directional setups. For bidirectional ones it recommends conflict detection and resolution policies and primary or unique keys on every replicated table.
- It runs as Microservices Architecture, managed through Service Manager, on a VM, bare metal or Kubernetes. OCI GoldenGate is a fully managed service where Oracle handles backups, patching and upgrades.
- [Oracle's Apache Iceberg connection docs](https://docs.oracle.com/en/database/goldengate/big-data/26/gadbd/apache-iceberg.html) list Glue, Hadoop, Nessie, Polaris and REST catalogs, with dependency downloaders for Google Cloud Storage, Amazon S3 and Azure Data Lake Storage.

**Where it falls short**

- Iceberg writing lives in a separate product, GoldenGate for Distributed Applications and Analytics, and its [docs](https://docs.oracle.com/en/database/goldengate/big-data/26/gadbd/apache-iceberg.html) sit in Oracle's big-data documentation set, not in the core GoldenGate docs. It has its own line on the [price list](https://www.oracle.com/a/ocom/docs/corporate/pricing/technology-price-list-070617.pdf) (checked Oct 2026).
- The older Classic Architecture is de-supported in `26ai` ([FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html)), so check which one you run.
- The [FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html) says bidirectional setups are more complex than one-way setups and can cause update conflicts, replication loops, data divergence, latency sensitivity and operational complexity.
- The [FAQ](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/ogg-frequently-asked-questions.html) says GoldenGate cannot capture from Salesforce, Teradata or TimesTen.

#### 2. Oracle Active Data Guard: for a standby copy of a whole Oracle database

**At a glance**

- Price: An extra-cost option on Enterprise Edition, per Oracle's [Licensing Information guide](https://docs.oracle.com/en/database/oracle/oracle-database/26/dblic/Licensing-Information.html). [Oracle's price list](https://www.oracle.com/a/ocom/docs/corporate/pricing/technology-price-list-070617.pdf) of 15 September 2026 shows $11,500 per processor, with $2,530 of support for the first year (checked Oct 2026).

[Oracle's best-practice page](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) says to use Active Data Guard when the focus is simplicity, data protection and availability. It calls it the simplest and fastest one-way replication of a complete Oracle database, with all data types and automatic replication of data definition language (DDL) changes, the statements that change table structure.

**What's good**

- [Oracle's page](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) says a synchronized standby can be opened read-only, so your reports can run there and leave the main database alone.
- [It says](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) Active Data Guard detects silent corruptions that can occur on the source or target and automatically repairs corrupt blocks.
- It [lists](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) zero data loss protection at any distance without impacting database performance. That is Oracle's own claim, and we did not test it.
- [It says](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) a Data Guard primary and standby are physically exact copies, so RMAN backups are interchangeable.
- It lists standby-first patching, database rolling upgrades and select platform migrations as ways to cut planned downtime.

**Where it falls short**

- It's all or nothing: a whole Oracle database goes to another Oracle database. [Oracle's page](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) points to GoldenGate for subset replication and for a replica that must be open read/write.
- [The same page](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) sends multimaster and bidirectional replication, many-to-one replication and data transformations to GoldenGate.
- It also sends replication between endian-format platforms, or across database major versions, to GoldenGate ([Oracle's page](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html)).
- The [licensing guide](https://docs.oracle.com/en/database/oracle/oracle-database/26/dblic/Licensing-Information.html) lists it as an extra-cost option on Enterprise Edition and shows it as not available in the Free edition.
- [Oracle's page](https://docs.oracle.com/en/database/oracle/oracle-database/26/haovw/best-practice-oracle-active-data-guard-and-oracle-goldengate.html) describes a copy of a whole Oracle database to another Oracle database, and names no lake or other database engine as a target.

### Commercial and managed tools

#### 3. Qlik Replicate: for mixed legacy sources

**At a glance**

- Price: Not published. Qlik Talend Cloud uses capacity bands based on data volume, job runs and run time. For client-managed Replicate, Qlik tells customers to contact sales (see the [Qlik pricing page](https://www.qlik.com/us/pricing/data-integration-products-pricing) and [Qlik Community](https://community.qlik.com/t5/Qlik-Replicate/How-Qlik-Replicate-licensing-costs-are-calculated/td-p/2524624)) (checked Oct 2026)

Qlik's [Oracle source limits](https://help.qlik.com/en-US/replicate/May2026/Content/Global_Common/Content/SharedReplicateHDD/Oracle/OracleDB_source_limitations.htm) list separate rules for each reader, so read them before you plan. For Oracle `21c`, LogMiner access is not supported, and only the Replicate Log Reader works.

**What's good**

- [Qlik's product page](https://www.qlik.com/us/products/qlik-replicate) describes Replicate as log-based with a zero-footprint design. For Oracle, [Qlik's docs](https://help.qlik.com/en-US/replicate/May2026/Content/Global_Common/Content/SharedReplicateHDD/Oracle/OracleDB_source_limitations.htm) say it reads redo logs with either LogMiner or its own Replicate Log Reader.
- [The same page](https://www.qlik.com/us/products/qlik-replicate) lists IMS/DB, Db2 for z/OS, RMS and VSAM as mainframe sources, and Apache Kafka, Confluent, Azure Event Hubs and AWS Kinesis as streaming platforms.
- On Iceberg, Qlik's [launch release](https://www.qlik.com/us/news/company/press-room/press-releases/qlik-open-lakehouse-now-generally-available) of September 2025 says Qlik Open Lakehouse combines CDC ingestion with automatic Iceberg optimization, runs in the customer's own cloud account with bring-your-own compute, and can be read by Amazon Athena, Snowflake, Spark, Trino and Amazon SageMaker. Replicate's May 2026 [release notes](https://help.qlik.com/en-US/replicate/May2026/Content/Replicate/Main/Release_Notes/features.htm) added a Cloudera Iceberg target.
- Replicate is client managed. [Qlik's page](https://www.qlik.com/us/products/qlik-replicate) says it can be installed on premises or as a virtual machine image in any location you choose.
- Under [Qlik's product descriptions](https://res.cloudinary.com/talend/image/upload/v1713309774/qlik/docs/Legal/terms-and-conditions/product-descriptions-for-qlik-cloud-subscriptions_hxk8re.pdf), the initial full load of a table is not counted in Data Moved, and Qlik waives overage charges incurred in the first six months of an initial subscription.

**Where it falls short**

- [Qlik's pricing page](https://www.qlik.com/us/pricing/data-integration-products-pricing) shows a "Contact Us" button for each of the four Talend Cloud editions (Starter, Standard, Premium and Enterprise) and no dollar figure, so you can't budget without a sales call (checked Oct 2026).
- Log-based CDC first appears in the Standard edition list on [that page](https://www.qlik.com/us/pricing/data-integration-products-pricing). It is not in the Starter list (checked Oct 2026).
- On Oracle `21c`, CDC is not supported if a schema, table or column name is longer than `30` characters ([Qlik's Oracle source limits](https://help.qlik.com/en-US/replicate/May2026/Content/Global_Common/Content/SharedReplicateHDD/Oracle/OracleDB_source_limitations.htm)).
- Capturing from a pluggable database with LogMiner is not supported, and neither is capturing several pluggable databases through the container database. [Qlik's docs](https://help.qlik.com/en-US/replicate/May2026/Content/Global_Common/Content/SharedReplicateHDD/Oracle/OracleDB_source_limitations.htm) also advise against LogMiner on RAC because of unpredictable behavior.
- Open Lakehouse is part of Qlik Talend Cloud, not Replicate alone. The [release notes](https://help.qlik.com/en-US/replicate/May2026/Content/Replicate/Main/Release_Notes/features.htm) describe Replicate landing data on S3 for an Open Lakehouse pipeline to turn into Iceberg tables, plus a Cloudera Iceberg target.
- Data Volume is counted where data lands, so the same data replicated to two targets is counted twice ([Qlik's product descriptions](https://res.cloudinary.com/talend/image/upload/v1713309774/qlik/docs/Legal/terms-and-conditions/product-descriptions-for-qlik-cloud-subscriptions_hxk8re.pdf)).

#### 4. Striim: for high-volume Oracle streaming

**At a glance**

- Price: Developer tier free up to 25 million events a month. Striim Cloud and Striim Platform say "contact us" (see the [Striim pricing page](https://www.striim.com/pricing/)) (checked Oct 2026)

Striim gives you two readers. Its [Oracle CDC documentation](https://www.striim.com/docs/en/oracle-database-cdc.html) describes Oracle Reader, which uses LogMiner, and OJet, a high-performance log mining interface. Both read Oracle `11g` and higher, Oracle clusters (RAC, several servers sharing one database) and pluggable databases.

[Striim's own sizing guidance](https://www.striim.com/docs/en/oracle-database-cdc.html) puts Oracle Reader at 20 GB to 80 GB of change data an hour and OJet at 150 GB or more.

**What's good**

- [Striim's feature table](https://www.striim.com/docs/en/oracle-database-cdc.html) marks Oracle Database `26ai` as supported by both Oracle Reader and OJet.
- Per [Striim's docs](https://www.striim.com/docs/en/oracle-database-cdc.html), a GG Trail Reader can read existing GoldenGate trail files (the page names GoldenGate versions `11g`, `12c`, `18.1` and `19.1`), which matters if you're moving off GoldenGate. We did not test it.
- On Iceberg, Striim's docs describe an [Iceberg Writer](https://www.striim.com/docs/en/iceberg-writer.html) with Merge and Append Only modes that propagates DDL changes, and an [S3 Tables Writer](https://www.striim.com/docs/en/s3-tables-writer.html) with `MERGE` and `APPENDONLY` modes that runs on Amazon EMR with either the S3 Tables catalog or AWS Glue.
- The [Striim Cloud SLA](https://www.striim.com/sla/) sets monthly availability at 99.5% for Striim Cloud Enterprise and 99.9% for Mission Critical (checked Oct 2026). It applies only to customers whose order forms reference it.
- Under the [consumption terms](https://www.striim.com/cloud-consumption-terms/) updated on 17 September 2026, Monthly Plan customers pay monthly in arrears for credits used, with no long-term commitment.

**Where it falls short**

- Iceberg is the catch. [Striim's Iceberg Writer docs](https://www.striim.com/docs/en/iceberg-writer.html) say that in this release Google Cloud Storage is the only supported data lake (S3 Tables has its own writer), and that it needs Google's managed Spark service plus a Lakehouse, Nessie or Polaris catalog. A Hadoop catalog is for development and testing only.
- Iceberg Writer partitioned tables need manual creation, time source types are written as strings, and recovery uses at-least-once processing ([Iceberg Writer docs](https://www.striim.com/docs/en/iceberg-writer.html)).
- The [S3 Tables Writer](https://www.striim.com/docs/en/s3-tables-writer.html) needs lowercase table, namespace and column names, which breaks wildcard mappings against sources with uppercase identifiers.
- Oracle Reader and GG Trail Reader are premium adapters. At the entry tier, premium adapters use 200 credits per million events against 100 for standard ones, and events are counted when they are read and when they are written ([consumption terms](https://www.striim.com/cloud-consumption-terms/), checked Oct 2026).
- Unused credits are forfeited at the end of a Capacity Purchase term ([consumption terms](https://www.striim.com/cloud-consumption-terms/), checked Oct 2026).
- The [SLA](https://www.striim.com/sla/) credit is the sole remedy for a missed service level, and scheduled upgrade or maintenance downtime of up to 24 hours a month is excluded.

#### 5. Quest SharePlex: for Oracle-to-Oracle and Oracle-to-PostgreSQL replication

**At a glance**

[Quest says](https://www.quest.com/products/shareplex) SharePlex operates outside the Oracle database instance and reads from redo logs. Its targets include Oracle, PostgreSQL, SQL Server, Kafka, and Parquet files in cloud storage such as Amazon S3 and Azure Blob. It supports two-way replication with conflict handling.

**What's good**

- [Quest](https://www.quest.com/products/shareplex) lists Oracle-to-Oracle and Oracle-to-PostgreSQL replication, including active-active with conflict resolution, and says the same works between Oracle and Google Cloud SQL for PostgreSQL, AlloyDB and AlloyDB Omni.
- Beyond the targets above, [Quest's page](https://www.quest.com/products/shareplex) lists MySQL (including AWS RDS, Aurora and Azure Database for MySQL), MariaDB, Azure SQL Database, Azure Event Hubs, JMS queues and Snowflake.
- [Quest says](https://www.quest.com/products/shareplex) SharePlex can replicate to an unlimited number of targets. That is a vendor claim, and we did not test it.
- File output can be Parquet, JSON, XML or SQL.
- [The page](https://www.quest.com/products/shareplex) offers a free trial ("Request Free Trial").

**Where it falls short**

- [Quest's page](https://www.quest.com/products/shareplex) describes replication from Oracle and PostgreSQL databases; it lists no other source.
- Quest doesn't say on [its page](https://www.quest.com/products/shareplex) whether it uses LogMiner, XStream or its own parser.
- The [pages we read](https://www.quest.com/products/shareplex) don't list Apache Iceberg as a target. The lake output is Parquet files in object storage.
- [Quest's marketing](https://www.quest.com/products/shareplex) says SharePlex costs a fraction of native tools, but it publishes no figures or method.
- Per-datatype and per-version limits are not on the [pages we read](https://www.quest.com/products/shareplex).

#### 6. Fivetran: for hands-off pipelines into a warehouse

**At a glance**

- Price: Monthly Active Rows (MAR) per connection, meaning the rows changed in a month. Free up to 500,000 MAR ([billing docs](https://fivetran.com/docs/core-concepts/usage-based-pricing/billing-and-plans)), and a $5 base charge per connection with 1 to 1 million MAR from January 2026 (checked Oct 2026). Paid per-MAR rates are in its [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) (first tier, per million MAR: Standard $495, Enterprise $661.67 and Business Critical $1,061.67, each plus a $5 monthly base) (checked Oct 2026)

Fivetran bills by Monthly Active Rows (MAR). Its [Oracle docs](https://fivetran.com/docs/connectors/databases/oracle) list two connectors. The Oracle connector offers Binary Log Reader, Teleport and XStream Out, and the High-Volume Agent (HVA) connector offers Direct Capture and Archive Log Only.

Per [the docs](https://fivetran.com/docs/connectors/databases/oracle), Teleport works differently: it reads tables, doesn't support large objects and is limited to tables under `100 GB`.

**What's good**

- Per [Fivetran's setup docs](https://fivetran.com/docs/connectors/databases/oracle/oracle-connector), Binary Log Reader reads Oracle redo log files directly, with no agent on the source database host. It reads both online and archived redo logs, and access to archived logs is required.
- The [Oracle connector docs](https://fivetran.com/docs/connectors/databases/oracle) list database versions `11g R2` to `21c`.
- [Fivetran's Hybrid Deployment docs](https://fivetran.com/docs/deployment-models/hybrid-deployment) say the pipeline runs in your own environment and only metadata, including MAR information, and logs are sent to Fivetran. It needs the Enterprise or Business Critical plan.
- [Fivetran's docs](https://fivetran.com/docs/destinations/managed-data-lake-service) say its Managed Data Lake Service writes Parquet files to your own Amazon S3, ADLS or GCS bucket and always creates Iceberg metadata, with a default Fivetran Catalog built on Apache Polaris.

**Where it falls short**

- The LogMiner method is sunset. Fivetran ended support for LogMiner connections on April 15, 2026, and said those still on it would stop syncing at the end of May 15, 2026 ([LogMiner migration FAQ](https://fivetran.com/docs/connectors/databases/oracle/troubleshooting/logminer-migration-faq), checked Oct 2026). Its [Oracle docs](https://fivetran.com/docs/connectors/databases/oracle) also say the LogMiner method "is sunset and is no longer available for new Oracle connections".
- Oracle sources, including Oracle RAC and Oracle RDS, and the High-Volume Agent Oracle connector are on the Enterprise and Business Critical plans only, per [Fivetran's billing docs](https://fivetran.com/docs/core-concepts/usage-based-pricing/billing-and-plans). Annual contracts have a $12,000 minimum (checked Oct 2026).
- The [Oracle docs](https://fivetran.com/docs/connectors/databases/oracle) list a `5 TB` limit on the sum of replicated tables and a `200 GB` limit on redo per hour, for both Binary Log Reader and the HVA connector.
- The [Oracle docs'](https://fivetran.com/docs/connectors/databases/oracle) instance table lists a physical standby instance as unsupported for every method, and Binary Log Reader support for an Active Data Guard standby is in Private Preview.
- The [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) defines MAR as distinct primary keys reflecting inserts, updates and deletes, and says MAR cannot be combined across connections to get a better rate.
- [Fivetran says](https://fivetran.com/docs/destinations/managed-data-lake-service) the Managed Data Lake Service does not support position deletes for Iceberg tables. On AWS it does not support the S3 Glacier Flexible Retrieval, Glacier Deep Archive or Intelligent-Tiering archive tiers.

### Open source

#### 7. Debezium: for teams that already run Kafka

**At a glance**

- Price: Free Apache 2.0 licence, per [Debezium's licence page](https://debezium.io/license/) (checked Oct 2026). You pay for servers and staff.

[Debezium's Oracle docs](https://debezium.io/documentation/reference/stable/connectors/oracle.html) say it can read Oracle through LogMiner, XStream or OpenLogReplicator, and you choose with the `database.connection.adapter` setting (`logminer`, `logminer_unbuffered`, `olr` or `xstream`). The docs call XStream "a commercial component of Oracle GoldenGate". Debezium `3.7` lists tested Oracle versions `19c`, `21c`, `23ai` and `26ai` ([release overview](https://debezium.io/releases/)).

Then there's [OpenLogReplicator](https://github.com/bersler/OpenLogReplicator), a separate open-source C++ project that parses Oracle's redo files and sends changes to Kafka, files or a network stream. GitHub lists it under the Affero General Public License (AGPL) version 3. Its stable line is `1.9`, and the `2.0.0` release (shown as 19 Jul on the releases page, with no year) is still called under development on the project page.

**What's good**

- [Debezium's Oracle docs](https://debezium.io/documentation/reference/stable/connectors/oracle.html) let you pick the reader, so you pick the licence route too: LogMiner, or XStream if you own GoldenGate. Check the logging setting described earlier either way.
- [Debezium's exactly-once page](https://debezium.io/documentation/reference/stable/configuration/eos.html) lists Oracle among the connectors that can take part in Kafka Connect's exactly-once delivery. It needs Kafka Connect `3.3.0` or higher in distributed mode, with `exactly.once.source.support=enabled` on every worker.
- The [Debezium Server docs](https://debezium.io/documentation/reference/stable/operations/debezium-server.html) say it streams change events from a source database directly to messaging and storage systems without requiring Apache Kafka. Its sink list includes Kinesis, Pub/Sub, Pulsar, Redis, Kafka, RabbitMQ, Event Hubs and Iceberg.
- The [docs](https://debezium.io/documentation/reference/stable/operations/debezium-server.html) say the Iceberg sink consumes change events from a source Debezium connector and writes Apache Iceberg tables, with upsert and append modes, automatic table creation when event and key schema information is enabled, and automatic schema evolution.
- The [OpenLogReplicator README](https://github.com/bersler/OpenLogReplicator) says it can be used with Debezium as a replacement for the LogMiner reader. For Debezium `2.x` and `3.x` its table gives `1.3.0` as the minimum version and `1.9.0` as the recommended one.

**Where it falls short**

- Watch the first snapshot. [The docs](https://debezium.io/documentation/reference/stable/connectors/oracle.html) say an `ORA-01555` error can occur if the first snapshot outlasts the database's `UNDO_RETENTION` time, `15 minutes` by default.
- Before deploying, [the docs](https://debezium.io/documentation/reference/stable/connectors/oracle.html) say to run the database in archive log mode and enable supplemental logging. For [Debezium Server](https://debezium.io/documentation/reference/stable/operations/debezium-server.html) you also copy the Oracle JDBC driver into its `lib` directory yourself, and each Server instance runs exactly one connector.
- LogMiner has a [memory trade-off](https://debezium.io/documentation/reference/stable/connectors/oracle.html). In the default mode the connector buffers events until a commit or rollback. The `logminer_unbuffered` mode needs much less connector memory but shifts a much greater burden to the source database, and for large transactions it can exceed the database's PGA memory.
- [OpenLogReplicator's README](https://github.com/bersler/OpenLogReplicator) says it is primarily developed and maintained by its author, and that issue reports are handled on a best-effort basis.
- The [Iceberg sink](https://github.com/memiiso/debezium-server-iceberg) is community-maintained in a separate repository. Upsert is off by default, and the [Server docs](https://debezium.io/documentation/reference/stable/operations/debezium-server.html) say upsert and automatic primary key detection depend on the flattened event structure. The [sink's own FAQ](https://memiiso.github.io/debezium-server-iceberg/faq/) says to run periodic table maintenance jobs to compact data and rewrite delete files, especially in upsert mode.
- [The exactly-once page](https://debezium.io/documentation/reference/stable/configuration/eos.html) says Debezium does not implement an internal deduplication layer, and that it is unclear whether Kafka's exactly-once implementation is fully correct or has edge cases.

*OLake home page, October 2026.*

**At a glance**

- Method: Oracle source with Full Refresh and Full Refresh + Incremental sync modes ([Oracle connector docs](/docs/connectors/oracle/))
- Price: Free licence (Apache 2.0, [GitHub](https://github.com/datazip-inc/olake)), you pay for infrastructure

OLake Go reads Oracle tables and writes Apache Iceberg tables or Parquet files to storage you control. ### Cloud services

#### 9. AWS DMS: for moving Oracle into AWS

**At a glance**

- Price: Replication instance hours or Serverless capacity hours, plus any extra log storage. The [AWS DMS pricing page](https://aws.amazon.com/dms/pricing/) lists no separate CDC fee (checked Oct 2026)

AWS's [Oracle source documentation](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html) says DMS uses LogMiner by default and offers Binary Reader, which parses the raw redo files. For a full-load-only task, no extra setup is needed. A CDC task is different: you choose one reader and prepare the source.

**What's good**

- Per [AWS](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html), Binary Reader has a lower impact on source CPU and I/O and better CDC performance on high change volumes. Its feature table lists LogMiner as the easier of the two to configure.
- [AWS lists](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html) self-managed Oracle sources from `10.2` and higher, `11g` up to `12.2`, `18c` and `19c`.
- A CDC task can start from an `SCN` or a timestamp ([AWS docs](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html)). From DMS version `3.5.1` the `openTransactionWindow` endpoint setting covers open transactions on a CDC-only task that starts that way.
- Per [the same page](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html), bidirectional replication is supported on Oracle, SQL Server, MySQL, PostgreSQL and the Aurora editions, as two tasks, one in each direction.
- [AWS's DMS pricing page](https://aws.amazon.com/dms/pricing/) says that Free Tier sign-ups after 15 July 2025 can choose a Free Plan or a Paid Plan with $100 in credits, plus up to $100 more, valid for up to twelve months (checked Oct 2026).

**Where it falls short**

- LogMiner doesn't give large-object support on Oracle `12c`, and it doesn't handle updates that touch only large-object columns ([AWS docs](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html)). Binary Reader does, but it doesn't support table clusters, compression or most encryption options.
- [DMS's CDC setup steps](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html) say it does not support an Oracle Standby as a source. Per the Binary Reader section, a self-managed standby works only if it is an Active Data Guard standby.
- Apache Iceberg is not on [AWS's list of DMS target endpoints](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Introduction.Targets.html) (checked Oct 2026). In an [AWS Big Data blog](https://aws.amazon.com/blogs/big-data/modernize-your-legacy-databases-with-aws-data-lakes-part-2-build-a-data-lake-using-aws-dms-data-on-apache-iceberg/) example, DMS writes files to S3 and a Glue job loads Iceberg tables, and the blog says the job does not process a file when no primary key is set.
- During CDC, DMS skips events for objects whose identifiers are longer than `30` bytes without stopping the task, which can leave data missing on the target ([AWS docs](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html)).
- The [CDC page](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Task.CDC.html) says there are no SLAs for CDC latency, and that latency can rise to several minutes or longer. [AWS's best practices page](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_BestPractices.html) advises against DMS CDC for sub-second or guaranteed low-latency replication.
- Starting a CDC task from an `SCN` or timestamp misses open transactions ([AWS docs](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html)), those that started before the start position and committed after it, unless you use the setting above.

AWS's [Oracle source documentation](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html) compares the two readers in a table. Some of its rows (checked Oct 2026):

| Feature | LogMiner | Binary Reader |
| --- | --- | --- |
| Easy to configure | Yes | No |
| Lower impact on source I/O and CPU | No | Yes |
| Better CDC performance | No | Yes |
| Oracle table clusters | Yes | No |
| LOB columns on Oracle `12c` | No | Yes |
| UPDATE statements that touch only LOB columns | No | Yes |
| All Oracle compression methods | Yes | No |
| XA transactions | No | Yes |
| RAC | Yes, not recommended for performance reasons | Yes, highly recommended |

#### 10. Google Datastream: for Oracle into BigQuery

**At a glance**

- Price: Per GiB processed, and a processed byte is an internal representation that for most use cases can be 2 to 5 times larger than the data itself. Backfill is free for the first 500 GiB a month, then $0.40 per GiB. The free CDC tier covers only AlloyDB and Spanner sources ([Datastream pricing page](https://cloud.google.com/datastream/pricing)) (checked Oct 2026)

Google's [Oracle source page](https://cloud.google.com/datastream/docs/sources-oracle) lists Oracle `11.2.0.4` (LogMiner only), `12c`, `18c`, `19c` and `21c`. It supports RAC, Exadata, Amazon's managed Oracle service and an Active Data Guard standby. Oracle Autonomous Database is not supported, though.

**What's good**

- One difference to know, per [Google's docs](https://cloud.google.com/datastream/docs/sources-oracle): the binary reader sends only committed changes, while LogMiner can also read uncommitted ones and emits the opposite operation after a rollback.
- The binary reader (Preview) falls back to archived log files ([Google's docs](https://cloud.google.com/datastream/docs/sources-oracle)) if there is a read lag on the online logs, and it supports Oracle `VARCHAR2` columns longer than `4000` characters.
- The [pricing page](https://cloud.google.com/datastream/pricing) says an idle stream does not incur any cost, there are no costs for running streams other than data processed, and events read but not written to the destination are not counted. CDC costs are tiered, so the price per GB falls as usage rises.
- Per the [Iceberg destination docs](https://cloud.google.com/datastream/docs/destination-blmt), Iceberg tables in BigQuery store data in customer-owned Cloud Storage buckets in the Iceberg table format and Parquet file format.

**Where it falls short**

- Large-object columns arrive as `NULL` unless you set the `streamLargeObjects` flag ([Google's Oracle source page](https://cloud.google.com/datastream/docs/sources-oracle)). Even then Datastream looks values up in the source, so fast back-to-back changes can be missed.
- Per [Google's docs](https://cloud.google.com/datastream/docs/sources-oracle), columns of types such as `LONG`, `LONG RAW`, `BFILE`, `UROWID`, user-defined types, `VARRAY` and `SDO_GEOMETRY` arrive as `NULL`. Index-organized tables and temporary tables are not supported.
- For a table without a primary key, Datastream [merges on the row's `ROWID`](https://cloud.google.com/datastream/docs/sources-oracle), which might not be unique and can change after an export and import.
- [Google says](https://cloud.google.com/datastream/docs/sources-oracle) not all source schema changes are detected automatically. Dropping a column, adding one in the middle of a table, changing a data type or truncating a table can cause data corruption or failures downstream.
- The binary reader is in [Preview](https://cloud.google.com/datastream/docs/sources-oracle) and does not support Transparent Database Encryption, Hybrid Columnar Compression or Secure files. If a column name is longer than `30` characters, an `UPDATE` makes Oracle silently abort supplemental logging for the row, and unchanged columns arrive as `NULL`.
- With an Active Data Guard standby as the source ([Google's docs](https://cloud.google.com/datastream/docs/sources-oracle)), Datastream waits for the standby to apply each log before it reads it, so a paused standby apply delays your data.

#### 11. Confluent Oracle XStream connector: for Oracle into Kafka without a GoldenGate purchase

**At a glance**

- Price: Not published. Confluent lists its Oracle XStream connector as "contact us" ([Confluent connector pricing](https://www.confluent.io/confluent-cloud/connect-pricing/)) (checked Oct 2026)

Confluent's [connector documentation](https://docs.confluent.io/cloud/current/connectors/cc-oracle-xstream-cdc-source/cc-oracle-xstream-cdc-source-features.md) says the fully managed connector reads the redo log through XStream Out and captures both data and DDL changes. Confluent says it has an agreement with Oracle, so users don't need to buy extra Oracle licences for XStream with this connector. (That's Confluent's claim, so confirm it in writing.)

**What's good**

They also describe downstream capture, where the capture process runs on a separate Oracle database so production isn't hit by capture overhead, and cascading downstream capture through an Active Data Guard standby.
- An [ad hoc blocking snapshot signal](https://docs.confluent.io/cloud/current/connectors/cc-oracle-xstream-cdc-source/cc-oracle-xstream-cdc-source-features.md) can backfill specific tables after the connector has started streaming, and automated retries try up to three times before the connector stops in a failed state.

**Where it falls short**

- The connector writes changes to Kafka topics ([Confluent's docs](https://docs.confluent.io/cloud/current/connectors/cc-oracle-xstream-cdc-source/cc-oracle-xstream-cdc-source-features.md)), so you still need a second step to reach a lake.

If the connector is interrupted during a snapshot it restarts all snapshots from the beginning, and a long snapshot can hit `ORA-01555` unless you raise `UNDO_RETENTION`.
- Per [Confluent's docs](https://docs.confluent.io/cloud/current/connectors/cc-oracle-xstream-cdc-source/cc-oracle-xstream-cdc-source-features.md), each connector instance captures from one pluggable database, and an XStream outbound server supports only one active client session, so every connector needs its own outbound server.
- An unmodified large-object column ([Confluent's docs](https://docs.confluent.io/cloud/current/connectors/cc-oracle-xstream-cdc-source/cc-oracle-xstream-cdc-source-features.md)) is left out of the change event and replaced by a placeholder. Large-object events can also exceed Kafka's maximum message size, in which case Kafka rejects the message.

## What to check before you commit

**1. The licence route.** Ask which reader the tool uses and whether its setup turns on GoldenGate Supplemental Logging (see the licence section above). XStream generally needs GoldenGate licences unless the vendor has its own deal, and a direct reader is outside what Oracle supports.

**2. Log retention.** Archived redo logs must stay on disk through an outage plus the catch-up time, so don't let a cleanup job eat them. Fivetran says Binary Log Reader requires archived redo access ([Fivetran docs](https://fivetran.com/docs/connectors/databases/oracle)), and Datastream's setup includes a retention policy ([Datastream docs](https://cloud.google.com/datastream/docs/sources-oracle)).

**3. The first snapshot.** Tools copy your existing rows before they follow changes. A snapshot that outlasts undo retention can raise `ORA-01555` in Debezium.

**4. Large objects.** A large object (LOB) is a text or binary column that can be huge. Datastream writes them as `NULL` by default ([Datastream docs](https://cloud.google.com/datastream/docs/sources-oracle)), and DMS LogMiner has gaps on Oracle `12c` ([AWS docs](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html)).

**5. Names.** LogMiner needs names of `30` characters or less ([LogMiner docs](https://docs.oracle.com/en/database/oracle/oracle-database/26/sutil/oracle-logminer-utility.html)), Datastream's LogMiner mode has the same limit ([Datastream docs](https://cloud.google.com/datastream/docs/sources-oracle)), and Qlik's `21c` notes say longer names are not replicated ([Qlik docs](https://help.qlik.com/en-US/replicate/May2026/Content/Global_Common/Content/SharedReplicateHDD/Oracle/OracleDB_source_limitations.htm)).

**6. Standby and pluggable databases.** Datastream reads one pluggable database per stream ([Datastream docs](https://cloud.google.com/datastream/docs/sources-oracle)). DMS's [Binary Reader section](https://docs.aws.amazon.com/dms/latest/userguide/CHAP_Source.Oracle.html) says it currently supports only an Active Data Guard Standby, and Fivetran lists no Oracle method on a physical standby ([Fivetran docs](https://fivetran.com/docs/connectors/databases/oracle)).

### A two-week trial

Run the same test on every finalist and compare each tool's own records with the final table.

| Step | Operation | Append-only records | Current-state rows |
| --- | --- | --- | --- |
| 1 | Snapshot of existing keys 1, 2, 3 | Three snapshot records | 1, 2, 3 |
| 2 | Insert key 4 | Insert 4 | 1, 2, 3, 4 |
| 3 | Update key 2 to `a`, then to `b` | Two update records | 1, 2 (`b`), 3, 4 |
| 4 | Delete key 3 | A delete record for 3 | 1, 2 (`b`), 4 |
| 5 | Kill the tool mid-batch, restart, insert key 5 with a large object | Insert 5 | 1, 2 (`b`), 4, 5 |

A missing event is a failure, full stop. Accept a duplicate only if the tool documents at-least-once delivery and your load collapses it by key. Last, stop the tool for your longest expected outage and check that the archived logs it needs are still there.

| GoldenGate with DAA | Not checked | Not checked | Documented | Needs a check on standby and large objects |

If you need current-state Iceberg tables, Datastream drops out. That leaves DMS with Binary Reader plus a Glue step, and three candidates to check.
