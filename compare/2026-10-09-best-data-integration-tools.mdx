## What data integration means, in plain words

Data integration means getting data out of the systems where it's created, such as databases, apps like Salesforce and files, and putting it in a warehouse (a database built for reports) or a data lake (cheap file storage many tools can read).

**ETL** (extract, transform, load) reshapes data before it lands, and **ELT** (extract, load, transform) lands it first. **Change data capture (CDC)** reads a database's log of changes and sends only what changed.

## How to choose

Four questions, asked in order. Stop as soon as you're down to two or three tools.

1. **Who will run it?** If nobody on your team can, look at the vendor-run tools. If you have engineers who will, add Airbyte Core, Meltano, dlt and OLake Go.
2. **What are the sources?** Mostly SaaS apps? Look at Fivetran, Hevo or Airbyte. Databases that need fresh data point to Estuary, Qlik Talend Cloud or Fivetran Enterprise.
3. **Where must the data land?** A warehouse is easy almost everywhere. Iceberg tables on your own catalog shrink the field to the second table above, and each tool there has limits.
4. **Can you price it?** If the meter counts rows, events or credits, price your busiest month, not your average one. If the vendor won't print a rate, ask for a written quote that states your volume.

If your sources include databases, put three more questions to each vendor and ask them to point at a docs page:

- **What happens if the change log is gone before the tool reads it?** Databases keep change records for a limited time. Fivetran's [SQL Server page](https://fivetran.com/docs/connectors/databases/sql-server) says the default window is 3 days and recommends 7.
- **Does it run continuously or on a schedule?** Airbyte's CDC docs say syncs are scheduled, and Hevo's docs say streaming must be enabled through its sales team. Both are linked in their entries below.
- **Which Iceberg features does the writer skip?** Fivetran's Managed Data Lake Service page (linked in the table above) says it does not support position deletes for Iceberg tables. Other tools list their own limits, so read the destination page before you sign.

### Vendor-run tools for databases and apps

#### 1. Fivetran: best for SaaS sources and a hands-off setup

![Fivetran home page showing its headline and main navigation](/img/blog/2026/10/landing-fivetran.webp)

*Fivetran home page, October 2026.*

**At a glance**

- Billing: monthly active rows (MAR) per connection
- Free option: Free plan up to 500,000 MAR

Fivetran runs pre-built connectors that copy data from apps, databases and files into a warehouse or lake. We did not test any of it.

[Fivetran's billing docs](https://fivetran.com/docs/core-concepts/usage-based-pricing/billing-and-plans) say pay-as-you-go adds a $5 base charge to each connection that uses 1 to 1M rows, with a $12,000 minimum for annual contracts. Per-row list rates are in its [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table): Standard starts at $495 per million MAR, then falls to $170 per extra million from 1 million MAR, before discounts.

**What's good**

- [Its pricing page](https://www.fivetran.com/pricing) claims 700+ connectors and 200+ activation destinations (reverse ETL), with 15-minute syncs on Standard and 1-minute syncs on Enterprise. We did not count the connectors or test the sync times, so ask for a trial on your own sources.
- Per its [billing docs](https://fivetran.com/docs/core-concepts/usage-based-pricing/billing-and-plans), the Free plan has all Standard features up to 500,000 connector MAR, 3,500 activation MAR and 5,000 model runs a month, and annual contracts carry a built-in 5% discount.
- Its [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) puts each connection on its own volume curve. Standard list rates run from $495 per million MAR for the smallest connections to $170 per million from 1M MAR, $58 from 4M and $19.70 from 16M, before discounts.
- Its [SQL Server page](https://fivetran.com/docs/connectors/databases/sql-server) lists four incremental sync methods: change tracking, change data capture, Binary Log Reader and Teleport Sync. Teleport Sync compares row hashes between syncs instead of reading the transaction log, and the page suggests it when enabling change tracking or CDC is not feasible.
- Its [Managed Data Lake Service docs](https://fivetran.com/docs/destinations/managed-data-lake-service) say your data stays in your own cloud storage account (Amazon S3, Azure Data Lake Storage or Google Cloud Storage), and that Fivetran always creates Iceberg table metadata and manages the catalogs and maintenance, with snapshot cleanup once a day.

**Where it falls short**

- Per its [billing docs](https://fivetran.com/docs/core-concepts/usage-based-pricing/billing-and-plans), Oracle, SAP and Db2 (Beta) database sources are only on Enterprise and Business Critical, so the free plan can't use them, and its High-Volume Agent connectors for Oracle and SQL Server are listed for those two plans as well.
- The pricing page prints no per-row rate (the list rates are in the Service Consumption Table), and since January 1, 2026 deleted rows count as paid MAR, [per Fivetran's pricing update](https://fivetran.com/docs/core-concepts/usage-based-pricing/pricing-updates/2026-pricing-updates).
- The [Service Consumption Table](https://www.fivetran.com/legal/service-consumption-table) says you cannot combine MAR across connections for a better rate, so each connection pays its own base spend, such as the $500.00 the table lists at the 1M MAR tier on Standard.
- On SQL Server, the [same page](https://fivetran.com/docs/connectors/databases/sql-server) gives a default CDC retention window of 3 days (7 recommended). With CDC on, column type changes carry over, but renamed columns, new tables and new columns do not, and new ones need a new CDC instance.
- Its Managed Data Lake Service page lists no support for position deletes on Iceberg tables, and on AWS lakes none for the S3 Glacier Flexible Retrieval, Glacier Deep Archive and Intelligent-Tiering archive tiers ([docs](https://fivetran.com/docs/destinations/managed-data-lake-service)).
- The same docs say orphan files are moved to an `orphans` folder on the second and fourth Saturday of each month, and that deleting or editing that folder can permanently damage your tables.

**What users say:** A commenter on a [Hacker News thread](https://news.ycombinator.com/item?id=45568842) about the Fivetran and dbt Labs merger wrote in October 2025, "Fivetran is convenient but absurdly expensive."

#### 2. Airbyte: best for a big connector list you can self-host or rent

![Airbyte home page showing its headline and main navigation](/img/blog/2026/10/landing-airbyte.webp)

*Airbyte home page, October 2026.*

**At a glance**

- Billing: credits on Cloud, nothing for Core
- Free option: Core is free; Cloud has a 14-day free trial

Airbyte is one product wearing several hats: Core (self-run), Cloud (Standard, Plus and Pro) and Enterprise Flex (hybrid). On [its pricing page](https://airbyte.com/pricing), Cloud has a 14-day free trial, Standard starts at $20 a month with 5 credits and extra credits at $5 each, and Plus starts at $189 a month for 40 credits. Pro and Enterprise Flex show "Custom".

**What's good**

- Core has no credit meter, so you pay for servers and staff time instead. Cloud is the rented option, billed in credits.
- Per its [licence FAQ](https://docs.airbyte.com/platform/developer-guides/licenses/license-faq), anyone can use Airbyte free of charge and run it at scale on their own infrastructure, with "no limitations exist on volume, number of users, number of connections, etc." for open source users.
- Its [pricing page](https://airbyte.com/pricing) lists 700+ connectors on all four plans, with a maximum sync frequency of 1 hour on Standard, 15 minutes on Plus and 5 minutes on Pro and Enterprise Flex.
- Its [CDC docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) list current support for Postgres, MySQL, SQL Server, MongoDB, Oracle, SAP HANA and IBM Db2.
- Its [S3 Data Lake docs](https://docs.airbyte.com/integrations/destinations/s3-data-lake) say the connector writes Iceberg tables to S3 or S3-compatible storage through a REST, AWS Glue, Nessie or Polaris catalog, and its Append + Deduped mode is merge-on-read on the stream's primary keys.

**Where it falls short**

- [Airbyte's CDC docs](https://docs.airbyte.com/platform/understanding-airbyte/cdc) say "We do not treat CDC sources as infinite streaming sources", so syncs run on a schedule. Its [sync schedules page](https://docs.airbyte.com/platform/using-airbyte/core-concepts/sync-schedules) lists hourly as the shortest, bar 15 minutes on Cloud Plus.
- The same CDC docs say CDC incremental needs primary keys for most sources, changes made by TRUNCATE or ALTER do not appear in the logs and so not in the destination, and a refresh is required after you add a table to a CDC connection.
- Core uses the Elastic License 2.0, which its [licence FAQ](https://docs.airbyte.com/platform/developer-guides/licenses/license-faq) says bars selling a hosted Airbyte service.
- Its [S3 Data Lake docs](https://docs.airbyte.com/integrations/destinations/s3-data-lake) say the connector never rewrites existing Iceberg data files, so it handles only adding or removing a column, widening a column and changing the primary key. Objects and unions are written as serialized JSON strings.
- The same page does not say who handles compaction or snapshot expiry, and it cautions that compaction running during a truncate refresh sync deletes files from the current generation and causes data loss.
- It also warns that Snowflake does not recognize native Iceberg row-level deletes for tables in external catalogs such as Glue, so queries there return all versions of a record.

#### 10. OLake Go: best for database changes into Iceberg or Parquet on your own storage

**Where it falls short**

- Its Copy activity can write Iceberg only to Azure Data Lake Storage Gen2, per its [Iceberg format page](https://learn.microsoft.com/en-us/azure/data-factory/format-iceberg), which shows a dataset type and folder location but no catalog setting and no update, delete or merge setting.
- For auto incremental extraction from databases, the CDC page says an incremental column is required to identify the changes.
- The CDC resource is billed for four cores of General Purpose data flows while data is processed, and the [pricing page](https://azure.microsoft.com/en-us/pricing/details/data-factory/data-pipeline/) ties that rate to the period "during public preview of CDC".
- Data flows have an 8 vCore minimum cluster and also bill for managed disk and blob storage, and copying data out of an Azure datacenter adds a separate outbound transfer line.
