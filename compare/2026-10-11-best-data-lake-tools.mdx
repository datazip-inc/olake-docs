## What data lake tools are, in plain words

A data lake holds raw data in its original form, usually as files on cheap cloud storage. The tools around it fall into six layers.

**Object storage** keeps the files, such as Amazon S3.

**A table format** makes a plain folder of files behave like a database table. It's a set of rules plus small metadata files, and it adds row changes, earlier versions and tracking of which files belong to the table. Apache Iceberg, Delta Lake and Apache Hudi are the three open ones.

**A query engine** reads the tables and answers questions in SQL. It doesn't store your data.

**A catalog and governance layer** lists the tables and controls who gets in. **An ingestion tool** copies data from your databases into the lake. A **platform** bundles several of these layers and sells them as one product.

## How we picked

A tool had to be maintained and publish documentation or pricing we could open. It also had to be one teams meet when building a lake on public cloud or open source.

We read each vendor's own pricing and documentation pages on October 8, 2026, and the page is named beside each claim. We link the pricing pages and the pages behind hard limits.

Licences come from each project's own site or GitHub repository, read the same day. This is a reading of documents, *not* a lab test: claims about speed, scale, ease or savings are the vendors' own.

Where a vendor hides its price, the text says "not published".

Apache Spark, Starburst, Cloudera and MinIO are left out because we didn't read a primary page for them. The order inside each group is not a ranking.

## How data lake tools bill: two meters

Storing the files is the cheap part of a lake. You mostly pay for how much you read and how long compute runs.

![Two lake billing meters: bytes stored and scanned, or compute time in DCUs, DBUs and credits](/img/blog/2026/10/best-data-lake-tools-meters.webp)

Let's do the maths with published numbers only. Store 1,000 GB in S3 Standard at the first-50-TB rate of $0.023 per GB in US East (N. Virginia) and you pay $23.00 a month, before requests and transfer, per the [S3 price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/us-east-1/index.json) (checked Oct 2026).

Now query it. [Athena's own pricing page](https://aws.amazon.com/athena/pricing/) shows a 3 TB table costing $15 to scan once at $5 per TB (checked Oct 2026).

After compressing the file 3 to 1 and converting it to Parquet, a query that reads one column scans 0.25 TB and costs $1.25. The [page](https://aws.amazon.com/athena/pricing/) says this is a 3x saving from compression and a 4x saving from reading one column.

So file layout changes the bill, not only the vendor.

## The 15 best data lake tools

### Object storage

#### 1. Amazon S3: best for the default object store on AWS

**At a glance**
- Layer: object storage
- Price: S3 Standard $0.023 per GB a month for the first 50 TB, then $0.022 and $0.021 at higher volumes, in US East (N. Virginia), per [Amazon's S3 price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/us-east-1/index.json) (checked Oct 2026)

Amazon's [S3 pricing page](https://aws.amazon.com/s3/pricing/) says your rate depends on the size of your objects, how long you store them and the storage class. It also lists S3 Tables, which store Apache Iceberg tables and carry their own storage, request and monitoring charges (checked Oct 2026).

**What's good**

- The same [price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/us-east-1/index.json) shows lower-priced classes such as Standard-Infrequent Access at $0.0125 per GB-month in US East (N. Virginia) (checked Oct 2026).
- The [S3 user guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) says S3 gives strong read-after-write consistency for PUT and DELETE requests in all AWS Regions, and that an update to a single key is atomic.
- A single object can be up to 50 TB when you use the multipart upload API, and one PUT can carry an object up to 5 GB, per the [AWS upload docs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/upload-objects.html) (checked Oct 2026).
- The same [price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/us-east-1/index.json) gives S3 Standard request rates in US East (N. Virginia): $0.005 per 1,000 PUT, COPY, POST or LIST requests and $0.0004 per 1,000 GET requests (checked Oct 2026).

**Where it falls short**

- It stores files, and that's it. Without a table format and an engine, you get no tables.
- The same [user guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) says "There is no way to make atomic updates across keys," so S3 alone cannot commit a change to many files at once. Table formats such as Iceberg (entry 4) add that with an atomic metadata swap.
- Requests and data transfer are billed on top, and the first 100 GB a month of transfer out is free only in aggregate across AWS. The [pricing page](https://aws.amazon.com/s3/pricing/) says request costs depend on the request type and are charged on the quantity of requests (checked Oct 2026).
- S3 Tables, the Iceberg option on the [same page](https://aws.amazon.com/s3/pricing/), bills an object monitoring fee per object stored in table buckets on top of storage and requests (checked Oct 2026).
- The largest file the S3 console can upload is 160 GB, so very large objects go through the multipart upload API, per the [AWS upload docs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/upload-objects.html) (checked Oct 2026).

#### 2. Azure Data Lake Storage: best for Microsoft shops that want folder-style storage

**At a glance**
- Layer: object storage
- Price: priced at Azure Blob Storage levels, per [Microsoft's overview](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) (page updated July 3, 2026), with rates by tier and operation on the [Azure pricing page](https://azure.microsoft.com/en-us/pricing/details/storage/data-lake/#east-us-hierarchical-lrs) (checked Oct 2026)

[Microsoft's overview](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) calls it a set of capabilities built on Azure Blob Storage, switched on by the hierarchical namespace setting. In other words, it isn't a separate service or account type.

**What's good**

- [Microsoft's overview](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) says renaming or deleting a folder is one atomic operation (all or nothing), which it presents as a fit for big analytics jobs. We did not test that.
- Access control supports both Azure role-based access control (RBAC) and POSIX access control lists (ACLs), set at the directory or file level (same overview).
- The [overview](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) says all data is encrypted at rest, with either Microsoft-managed or customer-managed keys.
- [Microsoft says](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) individual files can run from a few KB to hundreds of TB, with no limits on account size, file size or total data (checked Oct 2026).
- Hadoop distributions include the Azure Blob File System (ABFS) driver, and [Microsoft names](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) Apache Spark and Presto as engines that read the data through it.

**Where it falls short**

- Most Blob Storage features work, but [Microsoft says](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) some are preview only and a handful aren't supported (checked Oct 2026).
- The [overview page](https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-introduction) says nothing about Iceberg, so check your engine's docs.
- Turning on the hierarchical namespace cannot be undone. Microsoft's [upgrade guide](https://learn.microsoft.com/en-us/azure/storage/blobs/upgrade-to-data-lake-storage-gen2) says "There's no way to revert your account once you've performed the upgrade." (checked Oct 2026)
- On the [Azure pricing page](https://azure.microsoft.com/en-us/pricing/details/storage/data-lake/#east-us-hierarchical-lrs), the hierarchical namespace adds a charge for the extra metadata that holds the folder structure, shown as an Index meter. Data in Cool, Cold and Archive also carries early deletion periods of 30, 90 and 180 days, and the charge is prorated (checked Oct 2026).
- The [same page](https://azure.microsoft.com/en-us/pricing/details/storage/data-lake/#east-us-hierarchical-lrs) prices operations in 4 MB units: in the East US hierarchical view, Hot-tier writes list at $0.065 and reads at $0.0052 per 10,000 operations, and Archive reads at $6.50 (checked Oct 2026).
- The [same page](https://azure.microsoft.com/en-us/pricing/details/storage/data-lake/#east-us-hierarchical-lrs) lists data retrieval at $0.01 per GB for Cool, $0.03 for Cold and $0.02 for Archive, with Hot free, so reading back from the colder tiers is a separate charge (checked Oct 2026).

#### 3. Google Cloud Storage: best for lakes on Google Cloud with a free starter allowance

**At a glance**
- Layer: object storage
- Price: set per location and storage class; Always Free includes 5 GB-months of Standard storage, counted across US-WEST1, US-CENTRAL1 and US-EAST1, per the [Google Cloud Storage pricing page](https://cloud.google.com/storage/pricing) (checked Oct 2026)

The [pricing page](https://cloud.google.com/storage/pricing) lists Standard, Nearline, Coldline and Archive classes, plus a Rapid storage class. Look at the retrieval table, which shows $0 per gibibyte (GiB) for Standard, $0.01 for Nearline, $0.02 for Coldline and $0.05 for Archive (checked Oct 2026).

**What's good**

- The [retrieval table](https://cloud.google.com/storage/pricing) lists $0 per GiB for Standard storage, and the Always Free allowance is 5 GB-months (checked Oct 2026).
- [Always Free](https://cloud.google.com/storage/pricing) also includes 5,000 Class A operations and 50,000 Class B operations a month, plus 100 GB of data transfer from North America to each Google Cloud data transfer destination (checked Oct 2026).
- Retrieval fees do not apply to objects in a bucket with Autoclass enabled, per the [pricing page](https://cloud.google.com/storage/pricing) (checked Oct 2026).
- The [retrieval table](https://cloud.google.com/storage/pricing) lists $0 per GiB for the Rapid class too (checked Oct 2026).

**Where it falls short**

- [Storage prices](https://cloud.google.com/storage/pricing) change by location and are shown per hour, so there's no single number to quote (checked Oct 2026).
- The [pricing page](https://cloud.google.com/storage/pricing) doesn't state Iceberg support. Google's Iceberg tables live in the BigQuery entry below.
- [Data processing costs](https://cloud.google.com/storage/pricing) include operation charges for all requests, retrieval fees for reading data in some storage classes, and inter-region replication charges for data written to dual-regions and multi-regions (checked Oct 2026).
- Autoclass charges, Storage Intelligence charges and charges for objects with attached contextual information (Objects Contexts) are billed as [data processing costs](https://cloud.google.com/storage/pricing) too (checked Oct 2026).
- The [Always Free quotas](https://cloud.google.com/storage/pricing) apply only to usage in US-WEST1, US-CENTRAL1 and US-EAST1, are counted across those three regions together, and do not apply to the Rapid class (checked Oct 2026).

### Open Table Formats

#### 4. Apache Iceberg: best for one table format many engines can read

**At a glance**
- Layer: table format
- Price: free, [Apache 2.0 licence](https://github.com/apache/iceberg) (checked Oct 2026)

Iceberg's [maintenance docs](https://iceberg.apache.org/docs/latest/maintenance/) say each write creates a new snapshot, snapshots pile up until you expire them, and streaming jobs can leave many small files that need compaction. The [specification](https://iceberg.apache.org/spec/) says versions 1, 2 and 3 are complete, and version 4 is still in development (checked Oct 2026).

**What's good**

- Trino, Athena, Databricks and Snowflake all document Iceberg support, as the entries below show.
- The [specification](https://iceberg.apache.org/spec/) says version 2 adds delete files, so single rows can be deleted or replaced in immutable data files without rewriting those files.
- Version 3 adds row lineage tracking and binary deletion vectors, per the [same specification](https://iceberg.apache.org/spec/).
- Table state lives in metadata files, and each change swaps in a new metadata file atomically. The [specification](https://iceberg.apache.org/spec/) also lists readers that take no locks as a design goal.
- Maintenance tools ship with the project: the [maintenance page](https://iceberg.apache.org/docs/latest/maintenance/) describes an expireSnapshots operation, a Spark rewriteDataFiles action that combines small files in parallel, and a deleteOrphanFiles action.

**Where it falls short**

- It's only a format. You still need storage, a catalog and an engine.
- Upkeep is your job (or your platform's): compaction, snapshot expiry and cleaning of orphan files.
- Snapshots accumulate until they are expired, and expiring a snapshot removes it from time travel queries.
- Small data files add metadata and slow queries, and the [maintenance page](https://iceberg.apache.org/docs/latest/maintenance/) says streaming queries may produce small files that need compaction (checked Oct 2026).
- Old metadata files are kept by default, per the [maintenance page](https://iceberg.apache.org/docs/latest/maintenance/), and tables with frequent commits, such as those written by streaming jobs, may need regular metadata cleanup.
- Engine support differs by version: the Athena entry below creates only v2 tables, Trino lists v3 as experimental, and [Snowflake's docs](https://docs.snowflake.com/en/user-guide/tables-iceberg-externally-managed-writes) say row-level equality deletes are not supported (checked Oct 2026).

#### 5. Delta Lake: best for teams already on Databricks or Fabric

**At a glance**
- Layer: table format
- Price: free, Apache 2.0 licence, per [delta-io/delta on GitHub](https://github.com/delta-io/delta) (checked Oct 2026)

[Delta Lake's site](https://delta.io/) calls it an open-source storage framework for a lakehouse and says no single company controls it, with oversight from the Linux Foundation. It lists Spark, Flink, Trino, Hive, Snowflake, BigQuery, Athena, Redshift and Databricks among supported engines.

**What's good**

- [Delta's UniForm page](https://docs.delta.io/latest/delta-uniform.html) says Delta Universal Format, called UniForm, lets Iceberg and Hudi clients read Delta tables. It labels the Hudi part a preview.
- [Delta's home page](https://delta.io/) lists ACID transactions (serializability, the strongest isolation level) and scalable metadata for petabyte-scale tables as key features.
- [Delta's site](https://delta.io/) says it is platform agnostic: use it with any query engine, on any cloud, on-premises or locally.
- [Delta's site](https://delta.io/) says the project has more than 190 developers from over 70 organizations and is used in over 10,000 production environments. Both figures are the project's own and undated.

**Where it falls short**

- Fair warning: the [UniForm page](https://docs.delta.io/latest/delta-uniform.html) says UniForm generates its Iceberg metadata asynchronously and is read-only from an Iceberg and Hudi perspective (checked Oct 2026).
- [UniForm does not work](https://docs.delta.io/latest/delta-uniform.html) on tables with deletion vectors enabled, and you run REORG when enabling UniForm Iceberg on such a table (checked Oct 2026).
- The [same page](https://docs.delta.io/latest/delta-uniform.html) says that if an external writer (not Delta Lake) writes to a UniForm Iceberg or Hudi table, it may destroy the Delta table and cause data loss (checked Oct 2026).
- Change Data Feed and Delta Sharing work for Delta clients when UniForm is on, but have [no support in Iceberg](https://docs.delta.io/latest/delta-uniform.html) (checked Oct 2026).
- Microsoft Fabric [stores its tables in Delta Parquet](https://learn.microsoft.com/en-us/fabric/onelake/onelake-overview), so Delta is the home format there and Iceberg is a bridge.

#### 6. Apache Hudi: best for tables that take frequent updates and deletes

**At a glance**
- Layer: table format
- Price: free, Apache 2.0 licence, per [Hudi's docs overview](https://hudi.apache.org/docs/overview) (checked Oct 2026)

[Hudi's overview](https://hudi.apache.org/docs/overview) calls it an open table format built for high-performance writes on incremental data pipelines. It lists upserts (an update or an insert in one step), deletes, indexes, clustering, compaction and concurrency control, and two table types, copy-on-write and merge-on-read.

**What's good**

- The [overview](https://hudi.apache.org/docs/overview) lists Spark, Flink, Presto, Trino and Hive as query engines.
- The [overview](https://hudi.apache.org/docs/overview) lists three query types: Snapshot Queries, Incremental Queries and Read-Optimized Queries.
- The [overview](https://hudi.apache.org/docs/overview) says Hudi-rs is a native Rust implementation of Hudi that also provides bindings to Python, for use outside the JVM.
- The [overview](https://hudi.apache.org/docs/overview) names Uber, Amazon, ByteDance and Robinhood among those transforming their production data lakes with Hudi. That is Hudi's own list and we did not check it.
- The [overview](https://hudi.apache.org/docs/overview) offers quick start guides for Spark, Flink and Python/Rust, and a Docker demo that runs Hudi with Kafka, Spark, Hive and Presto.

**Where it falls short**

- The [overview](https://hudi.apache.org/docs/overview) doesn't state Iceberg compatibility, so confirm your engine reads Hudi before you commit.
- Cross-table interoperability between Hudi, Delta Lake and Iceberg is the job of Apache XTable, which [says it is incubating](https://xtable.apache.org/) in the Apache Software Foundation and was recently renamed from OneTable.

### Query engines

#### 7. Trino: best for open-source SQL across many sources

**At a glance**
- Layer: query engine
- Price: open source, with the Apache 2.0 licence listed in [Trino's GitHub repository](https://raw.githubusercontent.com/trinodb/trino/master/LICENSE); no vendor price is listed (checked Oct 2026)

[Trino's Iceberg connector page](https://trino.io/docs/current/connector/iceberg.html) says it supports Iceberg spec versions 1 and 2, with version 3 experimental (checked Oct 2026). It reads Parquet, Optimized Row Columnar (ORC) and Avro files, and works with catalogs such as Hive Metastore and AWS Glue.

**What's good**

- Its [docs](https://trino.io/docs/current/connector/iceberg.html) list INSERT, UPDATE, DELETE, TRUNCATE and MERGE on Iceberg tables, so it isn't read-only. We did not test them.
- The [connector page](https://trino.io/docs/current/connector/iceberg.html) lists these catalogs: Hive Metastore, AWS Glue, JDBC, REST, Nessie and Snowflake.
- New tables can use Iceberg format version 1, 2 or 3 and default to 2, and the connector supports CREATE TABLE AS with SELECT syntax, per the [connector page](https://trino.io/docs/current/connector/iceberg.html) (checked Oct 2026).
- The [table_changes function](https://trino.io/docs/current/connector/iceberg.html) reads row-level changes between two versions (snapshots) of an Iceberg table.

**Where it falls short**

- It is a query engine only. [Trino's overview](https://trino.io/docs/current/overview.html) describes a distributed SQL query engine for data held in other sources, and the docs we read describe software you run yourself, with no hosted service (checked Oct 2026).
- Version 2 is required for row-level deletes, and the [docs](https://trino.io/docs/current/connector/iceberg.html) say version 3 support is experimental: row-level updates, deletes and OPTIMIZE are not supported on v3 tables (checked Oct 2026).
- Tables with v3 features such as column default values and encryption are not supported, and the [docs](https://trino.io/docs/current/connector/iceberg.html) say writing to encrypted tables is not supported (checked Oct 2026).
- The [table_changes function](https://trino.io/docs/current/connector/iceberg.html) does not support tables with delete files, which row-level operations typically produce (checked Oct 2026).

#### 8. Amazon Athena: best for occasional SQL over files in S3

**At a glance**
- Layer: query engine
- Price: $5.00 per TB of data scanned in US East (Ohio), per [AWS's Athena price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonAthena/current/us-east-2/index.json) (checked Oct 2026)

[Athena's Iceberg docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html) say it can read, write, run table-changing commands called data definition language (DDL) and time-travel on Iceberg tables. The same [price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonAthena/current/us-east-2/index.json) adds a catch: it applies a 10 MB minimum to each successful or canceled query (checked Oct 2026).

**What's good**

- AWS positions it as serverless, so there are no servers to run, and it bills per query.
- The [Athena pricing page](https://aws.amazon.com/athena/pricing/) says you can use SQL or Apache Spark with no infrastructure to set up or manage, and that Athena queries data directly in Amazon S3 with no additional storage charges for querying (checked Oct 2026).
- The [price list](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonAthena/current/us-east-2/index.json) shows DDL statements, failed queries and statements that create or load partitions as free query types (checked Oct 2026).
- Beyond per-TB billing, the [pricing page's](https://aws.amazon.com/athena/pricing/) examples price Capacity Reservations at $0.30 per DPU-hour and Spark at $0.35 per DPU-hour (checked Oct 2026).
- Athena engine version 3 supports the Iceberg file formats Parquet, ORC and Avro, per the [Athena Iceberg docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html) (checked Oct 2026).

**Where it falls short**

- The [docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html) list Iceberg version 1.4.2 and say Athena creates and operates only on Iceberg v2 tables (checked Oct 2026).
- Only tables created against the AWS Glue catalog work. Athena supports Glue optimistic locking only, and the [docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html) warn that modifying an Iceberg table with any other lock implementation will cause potential data loss and break transactions (checked Oct 2026).
- Timestamps keep millisecond precision in reads and writes, although Iceberg supports microsecond precision ([Athena Iceberg docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html)) (checked Oct 2026).
- DDL isn't supported on Iceberg tables registered with Lake Formation ([Athena Iceberg docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html)) (checked Oct 2026).
- The [docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html) say Athena does not support ALTER TABLE SET LOCATION on Iceberg tables, or partitioning them by nested fields (checked Oct 2026).
- If you use the AWS Glue Data Catalog with Athena, you are charged standard Data Catalog rates on top of the query price, per the [pricing page](https://aws.amazon.com/athena/pricing/) (checked Oct 2026).

### Governance

#### 9. AWS Lake Formation: best for fine-grained access rules on AWS lakes

**At a glance**
- Layer: governance and catalog
- Price: permissions and their use by integrated services are at no charge; underlying services bill normally, per the [Lake Formation pricing page](https://aws.amazon.com/lake-formation/pricing/) (checked Oct 2026)

The [Lake Formation docs](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html) say it manages access to data on S3 and its metadata in the AWS Glue Data Catalog. Its rules can apply at database, table, column, row and cell level, and are enforced across AWS services such as Athena and AWS Glue.

**What's good**

- AWS documents tag-based access control, so rules can be set by label rather than table by table. We did not test how well that scales. The [docs](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html) say the tags (LF-Tags) attach to databases, tables or columns.
- The [docs](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html) say permissions are enforced with column, row and cell-level controls across Amazon Athena, Amazon Quick, Amazon Redshift Spectrum, Amazon EMR and AWS Glue.
- Lake Formation provides audit logs through CloudTrail to monitor access.
- It can import data from MySQL, PostgreSQL, SQL Server, MariaDB and Oracle databases running in Amazon RDS or hosted on Amazon EC2, and the [docs](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html) say both bulk and incremental loading are supported.
- Amazon S3 Tables can be published and cataloged as Data Catalog objects, with the catalog registered as a Lake Formation data location.

**Where it falls short**

- It governs data but doesn't store or query it. The [Lake Formation pricing page](https://aws.amazon.com/lake-formation/pricing/) also says the Storage API, Governed Tables and the Storage Optimizer bill separately (checked Oct 2026).
- The Storage API is charged for bytes scanned, rounded up to the next megabyte with a 10 MB minimum, and Governed Tables are charged for the number of files tracked plus API calls that read or change that metadata, per the same [pricing page](https://aws.amazon.com/lake-formation/pricing/) (checked Oct 2026).
- It's an AWS tool, and as the Athena entry above shows, there's a limit on Iceberg tables registered with it.
- [Athena's docs](https://docs.aws.amazon.com/athena/latest/ug/querying-iceberg.html) say Lake Formation can manage read access for Iceberg, Hudi and Delta Lake tables, but not permissions for VACUUM, MERGE, UPDATE or OPTIMIZE on them (checked Oct 2026).
- For databases other than the five it lists, the [docs](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html) say to create custom ETL jobs with AWS Glue.

### Ingestion

#### 10. OLake Go: best for getting database changes into an Iceberg lake

<img src="/img/logo/olake-blue-with-text.svg" alt="OLake" height="32" style={{display: 'block', margin: '2px 0 14px'}} />

![OLake home page showing its headline and main navigation](/img/blog/2026/10/landing-olake.webp)

*OLake home page, October 2026.*

**At a glance**
- Layer: ingestion
- Price: free, Apache 2.0 licence ([OLake on GitHub](https://github.com/datazip-inc/olake)) (checked Oct 2026); you run it on your own servers
- Support: [contact the OLake team](/contact/)

A lake stays empty until something loads it. OLake Go is an open-source tool that copies database tables into [Apache Iceberg tables in storage you choose](/docs/writers/iceberg/catalog/rest/) or into [Parquet files](/docs/writers/parquet/config/). It captures changes from [PostgreSQL](/docs/connectors/postgres/), [MySQL and MariaDB](/docs/connectors/mysql/), [MongoDB](/docs/connectors/mongodb/) and [SQL Server](/docs/connectors/mssql/).

**What's good**

- It has four sync modes, Full Refresh, Full Refresh + Incremental, Full Refresh + CDC and CDC Only, so one tool does the first load and then keeps the copy current ([docs](/docs/)).
- [Oracle](/docs/connectors/oracle/), [Db2](/docs/connectors/db2/), [S3](/docs/connectors/s3/) and [Kafka](/docs/connectors/kafka/) also work as sources, without database change capture.
- It writes Iceberg tables to catalogs such as [AWS Glue](/docs/writers/iceberg/catalog/glue/), with eleven catalog types listed on the [catalog compatibility page](/docs/understanding/compatibility-catalogs/), so Trino, Athena and the other engines above can read them.
- Syncs are stateful and resumable: after a crash, a network failure or a pause they resume from the last checkpoint instead of starting over ([docs](/docs/)).
- Schema discovery runs at the start of every sync, and a new source column is added to the Iceberg schema automatically ([schema evolution docs](/docs/features/schema/)).
- You run it yourself with [Docker](/docs/install/docker-cli/), [Helm on Kubernetes](/docs/install/kubernetes/) or the [OLake UI](/docs/install/olake-ui/).

### Platforms

#### 11. Databricks: best for Spark, SQL and machine learning in one workspace

**At a glance**
- Layer: platform
- Price: pay as you go, billed in Databricks Units (DBUs); on the Premium plan on AWS US East, SQL Serverless was $0.70, SQL Pro $0.55 and SQL Classic $0.22 per DBU, per the [Databricks SQL pricing page](https://www.databricks.com/product/pricing/databricks-sql) (checked Oct 2026)

[Databricks' Iceberg docs](https://docs.databricks.com/aws/en/iceberg/) say it supports Iceberg tables in Parquet, using versions 1, 2 and 3 of the specification, with Unity Catalog managing the tables (checked Oct 2026).

**What's good**

- Its [docs](https://docs.databricks.com/aws/en/iceberg/) say it supports managed Iceberg tables and can read other catalogs such as AWS Glue and Snowflake Horizon.
- Managed Iceberg tables can be created with Databricks Runtime, Databricks SQL, or external Iceberg-compatible engines that support the Iceberg REST Catalog API ([Iceberg docs](https://docs.databricks.com/aws/en/iceberg/)).
- Databricks' [external access page](https://docs.databricks.com/aws/en/external-access/iceberg) says the Iceberg REST catalog lets clients such as Apache Spark, Apache Flink and Trino read from and write to Unity Catalog Iceberg tables.
- Serverless SQL warehouses typically start in 2 to 6 seconds, per the [Databricks warehouse types page](https://docs.databricks.com/aws/en/compute/sql-warehouse/warehouse-types) (checked Oct 2026).

**Where it falls short**

- Managed Iceberg tables need Unity Catalog, Databricks Runtime 16.4 LTS or newer, and serverless compute, and that serverless compute must have network connectivity to the storage account behind the table ([Databricks Iceberg docs](https://docs.databricks.com/aws/en/iceberg/)) (checked Oct 2026).
- Foreign Iceberg tables, the ones managed in another catalog, are read-only in Databricks and have limited platform support ([Databricks Iceberg docs](https://docs.databricks.com/aws/en/iceberg/)) (checked Oct 2026).
- Through the REST catalog, external Iceberg clients can't access views and can't run table maintenance such as expiring snapshots and removing orphan files, per the [external access page](https://docs.databricks.com/aws/en/external-access/iceberg) (checked Oct 2026).
- Partition evolution on managed Iceberg tables works through external Iceberg engines using the REST catalog, but not through Databricks SQL ([Databricks Iceberg docs](https://docs.databricks.com/aws/en/iceberg/)) (checked Oct 2026).
- Pro and Classic SQL warehouses take typically about 4 minutes to start, and a Classic warehouse's compute runs in your own AWS account, per the [warehouse types page](https://docs.databricks.com/aws/en/compute/sql-warehouse/warehouse-types) (checked Oct 2026).
- Heads up: the per-DBU price may not be the full bill. The [pricing page](https://www.databricks.com/product/pricing/databricks-sql) says SQL Serverless includes cloud instance cost, but the Classic and Pro cards describe self-managed warehouses and carry no such note, so check cloud charges (checked Oct 2026).

#### 12. Snowflake: best for SQL teams that want Iceberg on storage they control

**At a glance**
- Layer: platform
- Price: credits; on-demand $2.00 per credit on Standard, AWS US East, per the [Snowflake Service Consumption Table](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf) (checked Oct 2026), effective October 2, 2026

[Snowflake's Iceberg docs](https://docs.snowflake.com/en/user-guide/tables-iceberg) say Iceberg tables combine Snowflake's performance with external cloud storage that you manage. It supports Parquet files, and writes to externally managed tables through a remote Iceberg catalog that uses the Representational State Transfer (REST) interface. Row-level deletes use position deletes on v2 tables and deletion vectors on v3 tables (checked Oct 2026).

**What's good**

- Per its [docs](https://docs.snowflake.com/en/user-guide/tables-iceberg), you can use Snowflake as the catalog, or an external catalog such as AWS Glue or Snowflake Open Catalog.
- The [docs](https://docs.snowflake.com/en/user-guide/tables-iceberg) say your files stay in storage you manage.
- An Iceberg table that uses Snowflake as its catalog gets [full Snowflake platform support](https://docs.snowflake.com/en/user-guide/tables-iceberg) with read and write access.
- Snowflake's [externally managed writes page](https://docs.snowflake.com/en/user-guide/tables-iceberg-externally-managed-writes) says it can run INSERT, UPDATE, DELETE, MERGE, TRUNCATE TABLE and COPY INTO on externally managed Iceberg tables.
- The credit table lists a Standard warehouse at 1 credit an hour for X-Small, 2 for Small and 4 for Medium, doubling at each size up to 512 for 6XL, per the [Snowflake credit table](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf) (checked Oct 2026), effective October 2, 2026.

**Where it falls short**

- If your account and storage sit in different regions, the [docs](https://docs.snowflake.com/en/user-guide/tables-iceberg) say egress costs apply when you query, and Snowflake bills cross-region transfer for its managed Iceberg tables (checked Oct 2026).
- It's a proprietary managed service, and we found no self-hosted option on the pages read. Credit prices vary by edition and region, so $2.00 is one row in a table, not a promise: the [same table](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf) lists Enterprise at $3.00 in AWS US East and Standard in AWS EU Frankfurt at $2.60 (checked Oct 2026).
- An Iceberg table that uses an external catalog "provides limited Snowflake platform support", and the [docs](https://docs.snowflake.com/en/user-guide/tables-iceberg) say row-level deletes with equality delete files aren't supported (checked Oct 2026).
- Writes to externally managed tables allow autocommit transactions only (no multi-statement transactions), and CREATE ICEBERG TABLE ... AS SELECT isn't supported when the remote catalog is AWS Glue or Databricks Unity Catalog, per the [externally managed writes page](https://docs.snowflake.com/en/user-guide/tables-iceberg-externally-managed-writes) (checked Oct 2026).
- For the AWS Glue Data Catalog, dropping an externally managed table through Snowflake does not delete the underlying table files, per the [same page](https://docs.snowflake.com/en/user-guide/tables-iceberg-externally-managed-writes) (checked Oct 2026).
- For Iceberg tables created from Iceberg metadata files in object storage, the [docs](https://docs.snowflake.com/en/user-guide/tables-iceberg) say Snowflake does not assume any life-cycle management on the table (checked Oct 2026).

## How to choose data lake tools

Don't start with brand names. Start from the cloud you already pay for and the skills on your team, then ask where you want to be free to switch.

| If this is true | Start with | Why | Watch out for |
| --- | --- | --- | --- |
| You are on AWS and want pay-per-query | S3 plus Athena, add Lake Formation for access rules | Nothing to run | Iceberg v2 only, Glue catalog only |
| You are on Azure and use Power BI | ADLS or Fabric OneLake | One lake, one identity system | Delta is the home format |
| You have engineers and want no platform fee | Object storage, Iceberg and Trino | Open parts, free software | Engine setup and upkeep are yours |
| You want one vendor for Spark and machine learning | Databricks | Many workloads in one place | Unity Catalog needed for managed Iceberg |
| Your team writes SQL and wants a managed engine | Snowflake, BigQuery or Dremio Cloud | Little to operate | Egress charges, BigQuery's limit of one mutating statement per table, or Dremio Enterprise (self-managed) with no published price |
| Your data starts in Postgres, MySQL, MongoDB or SQL Server | <img src="/img/logo/olake-blue.svg" alt="" height="20" style={{verticalAlign: 'middle', marginRight: '6px'}} />OLake Go | Open source, copies database tables into Iceberg tables | Pair it with a catalog and an engine from the entries above |
| Your tables get many updates | Hudi or Iceberg, check engine support | Built for row-level changes | Table upkeep is yours |

The short read: with engineers to spare, the open parts give you the most room to move. Without them, a pay-per-query service or a bundled platform means less to look after.

## Six questions to ask before you buy

1. **Which cloud do you already pay for?** Moving data across clouds or regions adds transfer charges.
2. **Which table format does your engine write?** "Supports Iceberg" can mean read only.
3. **Who does the upkeep?** Compaction and snapshot expiry are yours unless a platform does them.
4. **Which meter do you pay?** Bytes scanned, compute units or flat capacity.
5. **Who needs row or column rules?** Price a governance layer early, not at the end.
6. **How will data get in?** The tools above store, organize and query data. Loading your databases into the lake is a separate job (entry 10).

Ask any vendor for a worked bill on your own data volume. Claims such as the automatic scaling that [Dremio's pricing page](https://www.dremio.com/pricing/) describes are the vendor's own words.

## So where does that leave you?

Choose layers first and brand names second. A cloud object store, an open table format and one engine cover many teams, while Databricks, Snowflake, Dremio and Fabric trade some choice for less upkeep. Whichever you pick, store data in Parquet and an open table format: file layout cuts the bill, and open formats ease an exit, though engine support differs.
