# Docker (CLI)

Docker CLI can be installed and executed using the official Docker images. Each supported source driver has a dedicated image available on the [OLake Go Docker Hub page](https://hub.docker.com/u/olakego).

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) installed and running on the host system
- Internet access to pull Docker images  

In the subsequent commands, replace `[SOURCE-TYPE]` with the value corresponding to the required driver.

| MSSQL       | `mssql`       |

## Discover Command {/* #discover-command */}

<StreamsFormatNotice />

Discover reads your source and lists every stream (table or collection) it finds.

```bash title="discover command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-[SOURCE-TYPE]:latest \
discover \
--config /mnt/config/source.json
```

This command writes three files in the config folder:

- `selected_streams.json`: It lists the streams to sync and their settings. This is the file you edit.
- `available_streams.json`: It lists every stream OLake Go finds after running the discover command. This file is not supposed to be edited.
- `streams.json`: Single file with your stream selections and per-stream settings. See [Streams v1 reference](/docs/core/configs/streams-legacy).

On a first run, OLake Go selects every discovered stream.

### Re-discover and keep your edits

Pass both existing files to refresh them from the source. OLake Go keeps your `selected_streams.json` entries.

```bash title="re-discover command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-[SOURCE-TYPE]:latest \
discover \
--config /mnt/config/source.json \
--selected-streams /mnt/config/selected_streams.json \
--available-streams /mnt/config/available_streams.json
```

New tables are not selected automatically. Add them to `selected_streams.json` by hand.

## Streams Config {/* #streams-config */}

Two files describe your streams. Discover writes both.

- **`selected_streams.json`**: It lists the streams to sync and their settings. This is the file you edit.
- **`available_streams.json`**: It lists every stream OLake Go finds after running the discover command. This file is not supposed to be edited.
- **`streams.json`**: Single file with your stream selections and per-stream settings. This `streams.json` has been **deprecated**. See [Streams v1 reference](/docs/core/configs/streams-legacy).

### 1. Selected Streams

The top-level key is `selected_streams`. It maps each namespace (database or schema name) to a list of stream entries.

```json title="selected_streams.json"
{
  "selected_streams": {
    "public": [
      {
        "stream_name": "orders",
        "sync_mode": "incremental",
        "cursor_field": "updated_at",
        "partition_regex": "/{created_at,year}",
        "normalization": true,
        "update_type": "eq",
        "append_mode": false,
        "destination_database": "analytics",
        "destination_table": "orders_raw",
        "filter_config": {
          "logical_operator": "and",
          "conditions": [
            { "column": "status", "operator": "=", "value": "active" }
          ]
        },
        "selected_columns": {
          "columns": ["id", "status", "updated_at", "created_at"],
          "sync_new_columns": true
        }
      },
      {
        "stream_name": "customers",
        "sync_mode": "cdc",
        "partition_regex": ""
      }
    ]
  }
}
```

#### Details about all the fields mentioned in selected streams

| Field | Type | Required | Description | 
|---|---|---|---|
| `stream_name` | string | Yes | Identifier for the stream. Must match the stream name defined in the `Streams` configurations. | 
| `sync_mode` | `full_refresh`, `incremental`, `cdc`, or `strict_cdc` | No | Indicates the active sync mode. Possible values are defined in supported_sync_modes in `available_streams.json`. | 
| `cursor_field` | string, `primary` or `primary:secondary` | Only for `incremental` | Defines the cursor field used to track incremental sync. To read more about how this works, refer to the [Sync Modes](docs/understanding/terminologies/olake/#2-sync-modes) | 
| `destination_database` | string | No | Specifies the destination database name where data will be stored. By default, the driver name is used as the prefix, but you can override it using the [`--destination-database-prefix`](/docs/community/commands-and-flags#7-destination-database-prefix) flag. The source namespace is always appended to the database name. All special characters and spaces are replaced with (`_`), and the database is automatically created if it doesn’t exist. | 
| `destination_table` | string | No | Specifies the name of the destination table where the data will be stored. The table name is derived from the source stream name and normalized by replacing special characters and spaces with underscores (_). | 
| `partition_regex` | string | No (discover writes `""`) | A pattern defining how to partition the data. To read more, refer the [Partition Regex for S3](/docs/writers/parquet/partitioning#partition-regex-attributes) or [Partition Regex for iceberg](/docs/writers/iceberg/partitioning#how-iceberg-handles-partitions) | 
| `normalization` | boolean | No | Converts top-level JSON fields into columns, while nested JSON objects are stored as string values. | 
| `append_mode` | boolean | No | Disables upserts in Iceberg when set to `true`. (In upsert mode dedupe happens via equality delete) | 
| `update_type` | `eq`, `pos`, or `dv` | No | Specifies the format in which delete files are written during sync. <br/> `"eq"` writes equality delete files. <br/> `"pos"` writes positional delete files. <br/> `"dv"` writes deletion vector files.  | 
| `use_source_column_names` | boolean | No | Controls destination column naming. When `false`, OLake Go lowercases names and replaces any non-alphanumeric character with `_` (for example `UserID` → `userid`, `First-Name` → `first_name`). When `true`, names are copied from the source as-is, including case, spaces, and hyphens. Use `true` only when queries or tools require exact source names; otherwise keep `false` for normalized, destination-safe identifiers.  | 
| `filter_config` | object: `logical_operator`, `conditions[]` of `column`, `operator`, `value` | No | Ensures that only data matching the specified condition is synced. | 
| `selected_columns` | object: `columns` (list), `sync_new_columns` (boolean) | No | List of columns to be included in the sync for each stream. | 

### 2. Available Streams

The top-level key is `streams`: a list of objects, each with one `stream` that describes a table OLake Go found from the source. Discover writes and refreshes this file. This file is not supposed to be edited.

```json title="available_streams.json"
{
  "streams": [
    {
      "stream": {
        "name": "orders",
        "namespace": "public",
        "type_schema": { "properties": { "...": "..." } },
        "supported_sync_modes": ["cdc", "full_refresh", "incremental", "strict_cdc"],
        "source_defined_primary_key": ["id"],
        "available_cursor_fields": ["id", "updated_at", "created_at"],
        "available_update_types": ["eq", "pos", "dv"],
        "sync_mode": "cdc",
        "destination_database": "postgres_mydb:public",
        "destination_table": "orders",
        "selectable_columns": ["_olake_id", "_olake_timestamp", "id", "status", "updated_at", "created_at"],
        "default_stream_properties": {
          "normalization": true,
          "append_mode": false,
          "update_type": "eq"
        }
      }
    }
  ]
}
```

#### Details about all the fields mentioned in available streams

| Field | Meaning |
|---|---|
| `name` | Unique identifier for the stream. Each stream must have a unique name. |
| `namespace` | Database name that the stream belongs to. |
| `type_schema` | Defines the columns in streams or tables, including the destination column name. Includes destination column names and olake generated columns. |
| `supported_sync_modes` | Sync modes this stream supports. Includes `"full_refresh"`, `"cdc"`, `"strict_cdc"` and `"incremental"`. To read more about this refer to the [Sync Modes](docs/understanding/terminologies/olake/#2-sync-modes) |
| `source_defined_primary_key` | Specifies the field(s) that is set as a primary key in the source. |
| `available_cursor_fields` | Lists fields that can be used as cursor fileds (to track synchronization progress) in `incremental` sync mode. |
| `available_update_types` | Values you can use as `update_type`. |
| `sync_mode`, `cursor_field`, `destination_database`, `destination_table` | Discovered defaults. Override them in `selected_streams.json`. |
| `selectable_columns` | Columns you can list in `selected_columns.columns`. |
| `default_stream_properties` | Defaults for `normalization`, `append_mode`, and `update_type`. |

If `available_streams.json` has no streams, OLake Go fails with code `catalog.available_streams_empty`.

## Sync

The Sync section describes how to start the sync process using the configuration files. It also explains how to run sync with a state file when operating in Incremental (Bookmark/cursor) or CDC mode.

<StreamsFormatNotice />

### Sync command {/* #sync-command */}

Run this command for a Full Refresh sync or a first sync, before a state file exists.

```bash title="sync command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-[SOURCE-TYPE]:latest \
sync \
--config /mnt/config/source.json \
--selected-streams /mnt/config/selected_streams.json \
--available-streams /mnt/config/available_streams.json \
--destination /mnt/config/destination.json
```

Pass `--selected-streams` and `--available-streams` together, or use `--streams` with `streams.json` instead.

## Stats {/* #stats */}

The `stats.json` file is created as soon as the sync starts. The file looks like this:

```json title="stats.json"
{
  "Writer Threads": 21,
  "Synced Records": 14236868,
  "Bytes Read": 9876543210,
  "Speed": "76542.20 rps",
  "Seconds Elapsed": "186.00",
  "Estimated Remaining Time": "1642.00 s",
  "Memory Usage Bytes": 2335248384,
  "CPU Utilization": 0.9348
}
```

| Componenet                   | Example Value  | Description                                                                     |
|------------------------------|----------------|---------------------------------------------------------------------------------|
| **Estimated Remaining Time** | `1642.00`      | A rough estimation in seconds, indicating when the sync is expected to complete |
| **Memory Usage Bytes**       | `2335248384`   | System memory currently in use, reported in bytes                               |
| **Writer Threads**           | `21`           | Number of parallel writer threads actively syncing data                         |
| **Seconds Elapsed**          | `186.00`       | Time in seconds elapsed since the sync started                                  |
| **Speed**                    | `76542.20 rps` | How many rows per second are being synced in this sync.                         |
| **Synced Records**           | `14236868`     | Total number of records which have been synced since the sync started.          |
| **Bytes Read**               | `9876543210`   | Total source bytes read and committed to the destination since the sync started |
| **CPU Utilization**          | `0.9348`       | CPU usage during the sync, reported as a decimal ratio (for example, `0.9348` is about 93.48%) |


The `stats.json` file remains available after sync completion. 

***What's Next***: Similarly logs get saved for every command that is executed. And those can be reviewed for additional information.

## Logs

During a sync, OLake Go automatically creates an olake.log file inside a folder named `sync_<TIMESTAMP_IN_UTC>` (for example: sync_2025-02-17_11-41-40).
This folder is created in the same directory as the configuration files.

- The olake.log file contains a complete record of all logs generated while the command is running.

![VS Code window displaying OLake Go logs for MongoDB sync and schema production events](/img/docs/features/olake-logs.webp)

- Console logs are displayed in real time with color formatting for easier identification.

![The log shows a fatal error: "snappy: corrupt input" occurred while reading Parquet records, indicating a decompression or data corruption issue](/img/docs/features/logs-console.webp)

