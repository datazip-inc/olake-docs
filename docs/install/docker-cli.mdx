# Docker (CLI)

Docker CLI can be installed and executed using the official Docker images. Each supported source driver has a dedicated image available on the [OLake DockerHub page](https://hub.docker.com/u/olakego).

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) installed and running on the host system
- Internet access to pull Docker images  

In the subsequent commands, replace `[SOURCE-TYPE]` with the value corresponding to the required driver.

## Discover Command {/* #discover-command */}

<StreamsFormatNotice />

Discover reads your source and lists every stream (table or collection) it finds.

```bash title="discover command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-[SOURCE-TYPE]:latest \
discover \
--config /mnt/config/source.json
```

This command writes three files in the config folder:

- `selected_streams.json`: the streams to sync and their settings. This is the file you edit.
- `available_streams.json`: every stream OLake found, with schema and metadata. Do not edit it.
- `streams.json`: Streams v1, the legacy single-file format. See [Streams v1 reference](/docs/core/configs/streams-legacy).

On a first run, OLake selects every discovered stream.

### Re-discover and keep your edits

Pass both existing files to refresh them from the source. OLake keeps your `selected_streams.json` entries.

```bash title="re-discover command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-[SOURCE-TYPE]:latest \
discover \
--config /mnt/config/source.json \
--selected-streams /mnt/config/selected_streams.json \
--available-streams /mnt/config/available_streams.json
```

New tables are not selected automatically. Add them to `selected_streams.json` by hand.

***What's Next*** : Edit `selected_streams.json` to choose streams and set their options.

## Streams Config {/* #streams-config */}

Two files describe your streams. Discover writes both.

- **`selected_streams.json`**: you edit this file. It lists the streams to sync and every per-stream setting.
- **`available_streams.json`**: read-only. It holds the schema, sync modes, keys, and defaults OLake found.

A stream syncs only if it appears in `selected_streams.json`. Here is a small example:

```json title="selected_streams.json"
{
  "selected_streams": {
    "public": [
      {
        "stream_name": "orders",
        "sync_mode": "incremental",
        "cursor_field": "updated_at",
        "partition_regex": "/{created_at,year}",
        "normalization": true,
        "append_mode": false
      },
      {
        "stream_name": "customers",
        "sync_mode": "cdc",
        "partition_regex": ""
      }
    ]
  }
}
```

- [Streams configuration reference](/docs/core/configs/streams/#field-reference-for-selected_streamsjson): every field, with examples.
- [Migrate from `streams.json`](/docs/core/configs/streams-migration): convert your existing file.
- [Streams v1 (`streams.json`)](/docs/core/configs/streams-legacy): the deprecated single-file format.

## Sync

The Sync section describes how to start the sync process using the configuration files. It also explains how to run sync with a state file when operating in Incremental (Bookmark/cursor) or CDC mode.

### Sync command {/* #sync-command */}

Run this command for a Full Refresh sync or a first sync, before a state file exists.

```bash title="sync command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-[SOURCE-TYPE]:latest \
sync \
--config /mnt/config/source.json \
--selected-streams /mnt/config/selected_streams.json \
--available-streams /mnt/config/available_streams.json \
--destination /mnt/config/destination.json
```

Pass `--selected-streams` and `--available-streams` together.

## Stats {/* #stats */}

The `stats.json` file is created as soon as the sync starts. The file looks like this:

```json title="stats.json"
{
  "Writer Threads": 21,
  "Synced Records": 14236868,
  "Bytes Read": 9876543210,
  "Speed": "76542.20 rps",
  "Seconds Elapsed": "186.00",
  "Estimated Remaining Time": "1642.00 s",
  "Memory Usage Bytes": 2335248384,
  "CPU Utilization": 0.9348
}
```

| Componenet                   | Example Value  | Description                                                                     |
|------------------------------|----------------|---------------------------------------------------------------------------------|
| **Estimated Remaining Time** | `1642.00`      | A rough estimation in seconds, indicating when the sync is expected to complete |
| **Memory Usage Bytes**       | `2335248384`   | System memory currently in use, reported in bytes                               |
| **Writer Threads**           | `21`           | Number of parallel writer threads actively syncing data                         |
| **Seconds Elapsed**          | `186.00`       | Time in seconds elapsed since the sync started                                  |
| **Speed**                    | `76542.20 rps` | How many rows per second are being synced in this sync.                         |
| **Synced Records**           | `14236868`     | Total number of records which have been synced since the sync started.          |
| **Bytes Read**               | `9876543210`   | Total source bytes read and committed to the destination since the sync started |
| **CPU Utilization**          | `0.9348`       | CPU usage during the sync, reported as a decimal ratio (for example, `0.9348` is about 93.48%) |


The `stats.json` file remains available after sync completion. 

***What's Next***: Similarly logs get saved for every command that is executed. And those can be reviewed for additional information.

## Logs

During a sync, OLake Go automatically creates an olake.log file inside a folder named `sync_<TIMESTAMP_IN_UTC>` (for example: sync_2025-02-17_11-41-40).
This folder is created in the same directory as the configuration files.

- The olake.log file contains a complete record of all logs generated while the command is running.

![VS Code window displaying OLake Go logs for MongoDB sync and schema production events](/img/docs/features/olake-logs.webp)

- Console logs are displayed in real time with color formatting for easier identification.

![The log shows a fatal error: "snappy: corrupt input" occurred while reading Parquet records, indicating a decompression or data corruption issue](/img/docs/features/logs-console.webp)
