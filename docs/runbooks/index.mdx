These runbooks cover the problems people hit most when they move data out of a database with change data capture (CDC) and into Apache Iceberg tables. Each one explains a mechanism once, then lists the exact messages it produces in each tool and version.

Every page is backed by a lab in the [docs repository](https://github.com/datazip-inc/olake-docs/tree/master/labs/runbooks). The failure was reproduced there before the page was written, and the page quotes the output the lab captured, with the date and the versions of the run.

The fixes are for the tool or database the page is about. None of them needs OLake Go, and where OLake Go has the same limit the page says so.

## PostgreSQL

- [Replication slot is filling the disk](/docs/runbooks/postgres/replication-slot-filling-disk/): find the slot that holds the write-ahead log (WAL), get its consumer confirming again or drop it safely, and cap it with `max_slot_wal_keep_size`. Run on PostgreSQL 12 to 18 and the 19 release candidate.
- [Enable logical replication for CDC](/docs/runbooks/postgres/enable-logical-replication/): the six prerequisites on a self-hosted server with the error each gives when it is missing, then what Amazon RDS, Aurora, Cloud SQL and Azure change.
- [REPLICA IDENTITY FULL and `__debezium_unavailable_value`](/docs/runbooks/postgres/replica-identity-toast-columns/): what a CDC reader receives for an update or a delete under each replica identity, why a large value that an update leaves alone arrives as a placeholder, and what `REPLICA IDENTITY FULL` costs. Run on PostgreSQL 13, 18 and 19 with Debezium 1.9 and 3.7.

## MySQL

- [MySQL purge binary logs: retention and error 1236](/docs/runbooks/mysql/binlog-retention-error-1236/): how long to keep binary logs, how to purge them safely, and how to recover a replica or a Debezium connector whose position was purged.

## SQL Server

- [Enable CDC in SQL Server and fix empty change tables](/docs/runbooks/sql-server/enable-cdc-change-tables-empty/): the two procedure calls, the errors when enabling, why change tables stay empty without SQL Server Agent, Msg 313 and schema changes.

## Debezium

- [Connector is RUNNING but captures nothing](/docs/runbooks/debezium/connector-running-captures-nothing/): five causes on MySQL and PostgreSQL with the command that proves each one: include lists, snapshot mode, topic creation, the publication, and a connector with no task.
- [The db history topic is missing](/docs/runbooks/debezium/schema-history-topic-missing/): the schema history topic is lost while the offsets survive. Recovery mode, when it is not safe, and the related "schema isn't known to this connector" error.

## Kafka Connect

- [Failed to find any class that implements Connector](/docs/runbooks/kafka-connect/connector-class-not-found/): where `plugin.path` must point, half-installed plug-ins, Debezium and Confluent Hub archives, and plug-in discovery from Kafka Connect 3.6.
- [Task is being killed and will not recover until manually restarted](/docs/runbooks/kafka-connect/task-failed-will-not-recover/): how to read the cause under the wrapper, the restart calls by version, `errors.tolerance` and the dead letter queue, and what they do not cover.

## Apache Iceberg

The [Iceberg runbooks](/docs/runbooks/iceberg/) are grouped by where the problem shows up: writes, maintenance and query engines.

- [Iceberg schema evolution errors](/docs/runbooks/iceberg/schema-evolution-errors/): type changes, missing and extra columns, `mergeSchema`, renames, required columns and case, with the messages from Spark 3.3 to 4.0, PyIceberg and Trino.
- [Iceberg compaction: when rewrite_data_files rewrites nothing](/docs/runbooks/iceberg/compaction-rewrite-data-files-rewrites-nothing/): the thresholds that skip files, what compaction leaves in storage and manifests, and how it fails against a concurrent delete, on Iceberg 1.4 and 1.12.
- [Spark cannot find Iceberg](/docs/runbooks/iceberg/spark-cannot-find-iceberg/): the runtime jar, the catalog and the SQL extensions, with the error each missing piece gives on Spark 3.3, 3.5 and 4.0, and how to see what a session loaded.
