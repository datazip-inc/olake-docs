These runbooks cover the problems people hit most with Apache Iceberg tables. They are grouped by where the problem shows up: writing to a table, maintaining it, or reading it from an engine.

Each page explains one mechanism across the engines that share it, such as Spark, Trino and PyIceberg, and lists the exact message each version prints. Every page is backed by a lab in the [docs repository](https://github.com/datazip-inc/olake-docs/tree/master/labs/runbooks/iceberg), which was run before the page was written.

## Ingestion and writes

- [Iceberg schema evolution errors](/docs/runbooks/iceberg/schema-evolution-errors/): changing a column's data type, missing and extra columns (and Spark's `mergeSchema` write operation), renaming or reordering columns, required (`NOT NULL`) columns, column names that differ only in case. With the messages from Spark 3.3 to 4.0, PyIceberg and Trino.

## Table maintenance

- [Iceberg compaction: when rewrite_data_files rewrites nothing](/docs/runbooks/iceberg/compaction-rewrite-data-files-rewrites-nothing/): the thresholds that skip files, what compaction leaves in storage and manifests, and how it fails against a concurrent delete, on Iceberg 1.4 and 1.12.
- [Iceberg storage not freed: expire_snapshots and orphan files](/docs/runbooks/iceberg/expire-snapshots-remove-orphan-files/): why snapshot expiry and orphan-file removal delete nothing (the defaults, table properties, tags, deletes and `gc.enabled`), how `.metadata.json` files pile up, and what the orphan listing needs on S3, measured on Iceberg 1.4 and 1.12.

## Query engines

- [Spark cannot find Iceberg](/docs/runbooks/iceberg/spark-cannot-find-iceberg/): the runtime jar, the catalog and the SQL extensions, with the error each missing piece gives on Spark 3.3 to 4.0, and how to see what a session loaded.
