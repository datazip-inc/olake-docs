Amazon S3 Tables is a managed Iceberg catalog. AWS runs **compaction and snapshot cleanup** on the tables for you.

**Short answer.** To write Iceberg tables to S3 Tables, create an OLake Go destination with `catalog_type: s3tables` and an IAM (Identity and Access Management) access key. OLake Go signs requests with AWS Signature Version 4 (SigV4). Athena reads the tables through its S3 Tables integration, Redshift through a Glue resource link, and Trino, Spark, DuckDB and Doris over REST (representational state transfer).

<TLDR title='Key takeaways'>

- Amazon S3 Tables is a managed Iceberg catalog where AWS runs compaction and snapshot cleanup for you.
- OLake Go signs requests with SigV4, and [Athena](/docs/integrations/athena/), Redshift, Trino, Spark, DuckDB and Doris read the tables.
- Spark on [EMR](/docs/integrations/emr/) reads the S3 Tables catalog from EMR 7.5.

</TLDR>

## How OLake Go writes to Amazon S3 Tables

OLake Go uses **change data capture (CDC)** where the source has it. It commits Iceberg tables to an S3 table bucket. AWS then handles table maintenance that you would otherwise schedule yourself.

No guide on this site uses S3 Tables yet. The [S3 Tables setup page](/docs/writers/iceberg/catalog/rest/?rest-catalog=s3-tables) holds the destination reference, and the [Glue catalog page](/docs/integrations/catalogs/glue/) covers the other AWS route.

## When to use it

- You want AWS to run compaction and snapshot cleanup.
- Athena, Redshift or Spark on EMR will read the tables.

## When not to use it

- Athena is a reader and table names have upper-case letters. The Athena integration takes lowercase names only.
- Spark on EMR runs a release before 7.5. The S3 Tables catalog needs EMR 7.5 or later.
