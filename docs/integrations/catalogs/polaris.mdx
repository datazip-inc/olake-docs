Apache Polaris is an open-source Iceberg REST (representational state transfer) catalog that several engines can share, with **its own access control**.

**Short answer.** To write Iceberg tables to Polaris, create an OLake Go destination with `catalog_type: polaris`, the Polaris REST endpoint, and OAuth2 client credentials or a token. Trino, Spark, DuckDB, ClickHouse, Doris and StarRocks read Polaris as a REST catalog. Snowflake reads it through a read-only catalog integration.

## How OLake Go writes to Apache Polaris

OLake Go uses **change data capture (CDC)** where the source has it. It commits Iceberg tables to Polaris over the Iceberg REST protocol. You host Polaris yourself, next to the object storage it points at.

Fourteen guides ran end to end on Polaris: six for [Apache Iceberg](/docs/integrations/iceberg/), six for [ClickHouse](/docs/integrations/clickhouse/) and two for [DuckDB](/docs/integrations/duckdb/). The [Polaris post](/blog/apache-polaris-lakehouse/) and the [Polaris IAM setup page](/docs/writers/iceberg/polaris-iam-setup/) cover the catalog side.

## When to use it

- Several engines should share one open catalog with access control.
- You can run the catalog yourself, in Docker or Kubernetes.

## When not to use it

- You want a managed catalog with no server to run. AWS Glue and the vendor catalogs are managed.
- Redshift is a reader. It reaches Polaris only through Lake Formation catalog federation.
