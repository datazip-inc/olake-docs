MinIO AIStor Tables is an Iceberg REST (representational state transfer) catalog built **into the object store itself**. The files and the catalog live in one system.

**Short answer.** To write Iceberg tables to AIStor Tables, create an OLake Go destination with `catalog_type: rest` and the AIStor endpoint with the `/_iceberg` path. Add the warehouse name and turn on **SigV4 signing** under the `s3tables` service name. Spark, Trino, Starburst and DuckDB read AIStor Tables with SigV4; ClickHouse reads it with an OAuth2 bearer token.

<TLDR title='Key takeaways'>

- AIStor Tables serves the Iceberg REST catalog from the MinIO AIStor S3 port, with no separate catalog server or metastore.
- OLake Go writes to it as a Generic REST catalog with Signature Version 4 (SigV4) and the signing name `s3tables`.
- The [Postgres to MinIO AIStor guide](/docs/integrations/postgres-to-aistor/) ran end to end, with Spark, DuckDB and Trino reading the same tables.

</TLDR>

## How OLake Go writes to AIStor Tables

OLake Go uses **change data capture (CDC)** where the source has it. Each sync uploads the Parquet data and delete files through AIStor's S3 API. It then commits the snapshot to the catalog at `/_iceberg` on the same host and port. Both requests are signed with the same access key.

Tables live in a *warehouse*, created once with `mc table warehouse create`. OLake Go puts the warehouse name in `iceberg_s3_path`, and every engine passes it as the catalog warehouse ([MinIO: connecting query engines to AIStor Tables](https://docs.min.io/aistor/developers/aistor-tables/connect-query-engines/), checked Nov 2026).

MinIO documents AIStor Tables as supporting the Iceberg v3 REST catalog API, including deletion vectors ([MinIO blog](https://www.min.io/blog/embedded-vs-external-iceberg-catalogs-how-the-catalog-layer-works-in-a-data-lakehouse), checked Nov 2026). OLake Go picks the delete format from the target query engines on the job.

## When to use it

- Your data already lives in MinIO AIStor, on premises or in your own cloud account.
- You want one system for the files, the catalog and the access keys, with no catalog service to run.

## When not to use it

- You run the open source MinIO server. AIStor Tables is part of the licensed AIStor product; pair open source MinIO with [Apache Polaris](/docs/integrations/catalogs/polaris/) or [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) instead.
- A reader cannot sign Iceberg REST requests with SigV4 or use an OAuth2 bearer token. AIStor Tables accepts only those two.
