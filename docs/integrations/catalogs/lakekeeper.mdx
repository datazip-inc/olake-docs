Lakekeeper is a self-hosted Iceberg REST (representational state transfer) catalog. It runs in Docker or Kubernetes, on S3, MinIO or Azure storage.

**Short answer.** To write Iceberg tables to Lakekeeper, create an OLake Go destination with `catalog_type: lakekeeper`, the Lakekeeper REST endpoint, and OAuth2 client credentials or a token. Trino, Spark, DuckDB, ClickHouse, Presto, Doris and StarRocks read it as a REST catalog. Microsoft Fabric reads tables on Azure storage through OneLake shortcuts.

_Last reviewed October 2026._

## How OLake Go writes to Lakekeeper

OLake Go uses change data capture (CDC) where the source has it. It commits Iceberg tables to Lakekeeper over the Iceberg REST protocol. Lakekeeper runs next to your own storage, including MinIO on premises.

No guide on this site uses Lakekeeper yet. The [REST catalog page](/docs/writers/iceberg/catalog/rest/?rest-catalog=lakekeeper) holds the destination fields, and the [Lakekeeper and Trino post](/blog/building-modern-data-lakehouse-with-olake-iceberg-lakekeeper-trino/) is a full walkthrough.

## When to use it

- You run your own catalog on S3, MinIO or Azure storage.
- Open-source engines such as Trino, Spark and DuckDB are the readers.

## When not to use it

- Databricks, BigQuery, Athena or Redshift is the main reader. Their docs do not list Lakekeeper as a catalog they read.
- You use Starburst Galaxy with S3 storage. Galaxy supports Lakekeeper on Azure storage only.
