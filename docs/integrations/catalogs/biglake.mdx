BigLake, also called Google Cloud Lakehouse, is the Iceberg REST (representational state transfer) catalog that BigQuery reads natively.

**Short answer.** To write Iceberg tables to BigLake, create an OLake Go destination with `catalog_type: biglake`, a Google Cloud Storage bucket for the data, and a **service account JSON key**. Each catalog namespace maps to a BigQuery dataset. Spark on Dataproc, Trino, Spark and DuckDB read the same catalog over REST with Google authentication.

<TLDR title='Key takeaways'>

- OLake Go writes Iceberg tables to BigLake with a service account JSON key and keeps the data in Google Cloud Storage.
- Each catalog namespace maps to a BigQuery dataset, so [BigQuery](/docs/integrations/bigquery/) reads the tables with no extra registration.
- Spark on [Dataproc](/docs/integrations/dataproc/), Trino, Spark and DuckDB read the same catalog over REST.

</TLDR>

## How OLake Go writes to BigLake

OLake Go uses **change data capture (CDC)** where the source has it. It writes data files to Google Cloud Storage and commits each table to BigLake. BigQuery sees the tables with no extra registration.

The nine [BigQuery](/docs/integrations/bigquery/) guides ran end to end on BigLake. The [BigLake setup post](/blog/biglake-iceberg-rest-catalog-olake-go-setup/) and the [REST catalog page](/docs/writers/iceberg/catalog/rest/?rest-catalog=biglake) cover the catalog side.

## When to use it

- BigQuery or Dataproc will read the tables and the data lives in Google Cloud Storage.
- You want a managed catalog on Google Cloud.

## When not to use it

- You need deletion vectors that BigQuery reads in production. They are a BigQuery preview feature.
- Snowflake is the main reader. It reads BigLake through a catalog integration that no guide here has tested.
