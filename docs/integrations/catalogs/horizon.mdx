Snowflake Horizon Catalog takes writes from external engines over the Iceberg REST (representational state transfer) API. External writes became **generally available on 2026-05-26**.

**Short answer.** To write Iceberg tables to Horizon, create an OLake Go destination with `catalog_type: horizon` and one of four sign-in methods: a programmatic access token, a key-pair JWT (JSON Web Token), external OAuth, or workload identity federation. The tables become Snowflake-managed Iceberg tables. Spark, DuckDB, Trino and ClickHouse read them through the Horizon REST endpoint.

<TLDR title='Key takeaways'>

- OLake Go writes Snowflake-managed Iceberg tables through the Horizon Catalog Iceberg REST API.
- [Snowflake](/docs/integrations/snowflake/) sees the tables with no extra registration, and Spark, [DuckDB](/docs/integrations/duckdb/), Trino and ClickHouse read them over REST.
- Nine guides ran end to end on Horizon, for example [Postgres to Snowflake](/docs/integrations/postgres-to-snowflake/).

</TLDR>

## How OLake Go writes to Snowflake Horizon

OLake Go uses **change data capture (CDC)** where the source has it. It commits Iceberg tables through Horizon. Snowflake sees them with no extra registration, and other engines read the same tables over REST.

The nine [Snowflake](/docs/integrations/snowflake/) guides ran end to end on Horizon. The [REST catalog page](/docs/writers/iceberg/catalog/rest/?rest-catalog=horizon) holds the destination fields.

## When to use it

- Snowflake is the main reader and the tables should appear there with no extra registration.
- Spark, DuckDB or Trino should read the same tables.

## When not to use it

- The job writes equality deletes. Snowflake does not read them.
- Redshift is a reader. It reaches Horizon only through Lake Formation catalog federation.
