The AWS Glue Data Catalog is the Iceberg catalog that Athena, Redshift and Spark on EMR read natively.

**Short answer.** To write Iceberg tables to AWS Glue, create an OLake Go destination with `catalog_type: glue` and an Amazon S3 path. It signs in with an IAM (Identity and Access Management) access key or IAM role. Athena, Redshift, Spark on EMR, Trino and DuckDB then read the same tables.

_Last reviewed October 2026._

## How OLake Go writes to AWS Glue

OLake Go uses change data capture (CDC) where the source has it. It writes data files to S3 and registers each table in Glue. Glue itself is managed by AWS, so there is no catalog server to run.

The nine [Redshift](/docs/integrations/redshift/) guides ran end to end on Glue. The [Glue writer page](/docs/writers/iceberg/catalog/glue/) holds the destination reference, and the [Glue post](/blog/postgres-to-iceberg-using-glue/) is a longer walkthrough.

## When to use it

- The data is on S3 and Athena, Redshift or EMR will read it.
- You want a managed catalog with AWS access control.

## When not to use it

- Databricks is the main reader. It reads Glue tables only as read-only foreign tables through catalog federation.
- BigQuery is the main reader. Only BigQuery Omni federated datasets reach Glue.
