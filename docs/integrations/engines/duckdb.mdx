DuckDB attaches Iceberg REST (representational state transfer) catalogs from a single process. It is a quick way to query the tables OLake Go writes.

**Short answer.** To query a replicated database in DuckDB, run OLake Go with an Iceberg REST catalog such as Polaris, Lakekeeper, Unity Catalog or Horizon, or with AWS Glue. Then attach that catalog in DuckDB with the iceberg extension. Add DuckDB as a target query engine and OLake Go writes positional deletes, which DuckDB reads.

_Last reviewed October 2026._

## How OLake Go gets data into DuckDB

OLake Go uses change data capture (CDC) where the source has it. It commits Iceberg tables to the catalog. DuckDB reads [Polaris](/docs/integrations/catalogs/polaris/), [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) and the vendor REST catalogs, and Glue through its own endpoint type.

Two guides end in DuckDB, and many more use it as the cross-check reader. The [MySQL query engines post](/blog/mysql-to-iceberg-query-engines/) compares DuckDB with other readers.

## When to use it

- You want to inspect replicated tables from a laptop or a notebook.
- The catalog speaks the Iceberg REST protocol.

## When not to use it

- The catalog is Hive Metastore or JDBC. DuckDB attaches REST catalogs only.
- DuckDB is the main reader and the job uses equality deletes. The DuckDB docs do not cover equality delete reads, so prefer positional deletes.
