Snowflake queries Apache Iceberg tables in place. A database that OLake Go replicates into Iceberg shows up in Snowflake with no load job.

**Short answer.** To replicate Postgres, MySQL, MongoDB or another database to Snowflake, run OLake Go with Snowflake Horizon as the Iceberg catalog. The tables appear as Snowflake-managed Iceberg tables. Add Snowflake as a target query engine and OLake Go writes deletion vectors, which Snowflake reads.

_Last reviewed October 2026._

## How OLake Go gets data into Snowflake

OLake Go is an open-source replication tool. It copies a source database into Iceberg tables, with change data capture (CDC) where the source has it. Snowflake reads them through [Horizon](/docs/integrations/catalogs/horizon/), or through a read-only catalog integration for [AWS Glue](/docs/integrations/catalogs/glue/) and the other REST (representational state transfer) catalogs.

Each guide below ran end to end on Horizon. The same pages document Glue as a second option. Source setup lives on the connector pages, for example [Postgres](/docs/connectors/postgres/) and [MongoDB](/docs/connectors/mongodb/).

## When to use it

- Snowflake is the main reader, and Spark, DuckDB or Trino should open the same copy of the data.
- You want CDC from Postgres, MySQL, MariaDB, MongoDB or SQL Server into Snowflake with no load job.

## When not to use it

- The source is Oracle, DB2 or S3 and you need row-level CDC. OLake Go reads those sources incrementally.
- The catalog is Hive Metastore or JDBC. Snowflake has no catalog integration for either one.
