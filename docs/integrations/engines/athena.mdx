Amazon Athena queries Apache Iceberg tables registered in the AWS Glue Data Catalog. There is no cluster to run.

**Short answer.** To query a replicated database in Athena, run OLake Go with AWS Glue as the Iceberg catalog and the data on Amazon S3. Athena sees the Glue databases directly. Add Athena as a target query engine on the job: Athena reads v2 equality and positional deletes but no v3 tables, so OLake Go never writes deletion vectors.

_Last reviewed October 2026._

## How OLake Go gets data into Amazon Athena

OLake Go uses change data capture (CDC) where the source has it. It commits each sync to [AWS Glue](/docs/integrations/catalogs/glue/). Athena engine v3 reads those tables, and so do [Redshift](/docs/integrations/redshift/) and Spark on [EMR](/docs/integrations/emr/).

No guide ends in Athena yet. The nine Redshift guides query the same Glue tables from Athena, so they cover the full path. The [Athena post](/blog/olake-iceberg-athena/) shows a longer walkthrough.

## When to use it

- You want serverless SQL over replicated tables on S3, billed per query.
- Redshift, EMR or Trino should read the same Glue tables.

## When not to use it

- Another engine on the job reads only deletion vectors, such as Databricks under Unity Catalog. No delete format works for both engines.
- You use Amazon S3 Tables with upper-case table names. The Athena integration for S3 Tables takes lowercase names only.
