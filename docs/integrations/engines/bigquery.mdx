BigQuery reads Apache Iceberg tables registered in the BigLake catalog. Each catalog namespace maps to a BigQuery dataset.

**Short answer.** To replicate a database to BigQuery, run OLake Go with the BigLake Iceberg REST (representational state transfer) catalog as the destination. Keep the data in Google Cloud Storage. Add BigQuery as a target query engine on the job and OLake Go writes a v2 delete format that BigQuery reads.

_Last reviewed October 2026._

## How OLake Go gets data into BigQuery

OLake Go uses change data capture (CDC) where the source has it. It commits Iceberg tables to [BigLake](/docs/integrations/catalogs/biglake/), also called Google Cloud Lakehouse. BigQuery reads them with no extra registration. Spark on [Dataproc](/docs/integrations/dataproc/) reads the same catalog.

The nine guides below each ran end to end on BigLake. The [BigLake setup post](/blog/biglake-iceberg-rest-catalog-olake-go-setup/) walks through the catalog side in more depth.

## When to use it

- BigQuery is the main reader and the data can live in Google Cloud Storage.
- You want CDC from [Postgres](/docs/connectors/postgres/) or [MySQL](/docs/connectors/mysql/) into BigQuery without a load job.

## When not to use it

- You need deletion vectors. On v3 tables they are a BigQuery preview feature with per-query limits.
- The tables are in AWS Glue. BigQuery reaches Glue only through BigQuery Omni federated datasets.
