Starburst runs on Trino. It reads the Iceberg tables OLake Go writes with the same delete-format rules.

**Short answer.** To query replicated data in Starburst, run OLake Go with AWS Glue, Polaris or Amazon S3 Tables as the Iceberg catalog, and add that catalog in Starburst Galaxy or Starburst Enterprise. Positional and equality deletes work on every release. Deletion vectors need a release based on Trino 480 or later.

_Last reviewed October 2026._

## How OLake Go gets data into Starburst

OLake Go uses change data capture (CDC) where the source has it. It commits Iceberg tables to the catalog. Starburst reads [AWS Glue](/docs/integrations/catalogs/glue/) directly, and [Polaris](/docs/integrations/catalogs/polaris/) and S3 Tables as public preview catalogs in Galaxy.

No guide on this site runs Starburst yet. The [Trino page](/docs/integrations/trino/) lists runs that use the same connector rules.

## When to use it

- Your team already queries through Starburst Galaxy or Starburst Enterprise.
- The tables are on AWS and registered in Glue.

## When not to use it

- You run Lakekeeper on S3 and use Galaxy. Galaxy supports Lakekeeper on Azure storage only.
- You need Polaris or S3 Tables in Galaxy for production. Both are public preview there.
