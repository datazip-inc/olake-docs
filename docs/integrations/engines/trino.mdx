The Trino Iceberg connector reads **ten catalog types**. It can query OLake Go tables wherever they are registered.

**Short answer.** To query a replicated database in Trino, run OLake Go with a catalog the Trino Iceberg connector reads, such as AWS Glue, Polaris or Lakekeeper. Point a Trino Iceberg catalog at it. Trino reads v2 positional and equality deletes, and deletion vectors as an experimental feature from Trino 480.

<TLDR title='Key takeaways'>

- The Trino Iceberg connector reads ten catalog types, so it queries OLake Go tables wherever they are registered.
- Trino reads v2 positional and equality deletes, and deletion vectors as an experimental feature from Trino 480.
- Trino read the same [Polaris](/docs/integrations/catalogs/polaris/) tables in the ClickHouse, DuckDB and Apache Iceberg guides.

</TLDR>

## How OLake Go gets data into Trino

OLake Go uses **change data capture (CDC)** where the source has it and commits Iceberg tables to the catalog. Trino reads [Polaris](/docs/integrations/catalogs/polaris/) and [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) over REST (representational state transfer). It reads Glue natively.

No guide ends in Trino yet. Trino queried the same Polaris tables in the ClickHouse, DuckDB and Apache Iceberg guides listed below. The [Lakekeeper and Trino post](/blog/building-modern-data-lakehouse-with-olake-iceberg-lakekeeper-trino/) is a longer walkthrough.

## When to use it

- You run Trino as a shared SQL layer over several catalogs.
- The tables should stay readable by Spark, DuckDB or ClickHouse too.

## When not to use it

- You need deletion vectors in production. The Trino docs label them experimental.
- You use a JDBC catalog under a different catalog name. Trino must use the same catalog name as OLake Go.
