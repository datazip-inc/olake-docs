Microsoft Fabric reads Iceberg tables by converting their metadata to Delta Lake. It finds them through a **OneLake shortcut** to the table folder.

**Short answer.** OLake Go has no OneLake writer. To read replicated tables in Fabric, have OLake Go write to Lakekeeper with Azure storage, then add a OneLake shortcut to the table folder, or go through Azure Databricks Unity Catalog. Use positional deletes or deletion vectors, because equality deletes fail the Fabric conversion.

<TLDR title='Key takeaways'>

- Fabric reads OLake Go tables through a OneLake shortcut to [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) tables on Azure storage.
- Fabric converts Iceberg metadata to Delta Lake, so positional deletes and deletion vectors work.
- [Azure Databricks](/docs/integrations/databricks/) with [Unity Catalog](/docs/integrations/catalogs/unity/) is the other route into Fabric.

</TLDR>

## How OLake Go gets data into Microsoft Fabric

OLake Go uses **change data capture (CDC)** where the source has it. It commits Iceberg tables to [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) on Azure storage. Fabric reads them through the OneLake Iceberg table APIs, which are in preview.

No guide on this site runs Fabric yet. The [Azure storage page](/docs/writers/iceberg/azure/) covers the OLake Go side of the setup.

## When to use it

- Fabric is the reader and the data can live on Azure storage.
- You already run Azure Databricks with Unity Catalog.

## When not to use it

- The job writes equality deletes. They fail the Fabric conversion to Delta Lake.
- You need a generally available path. The OneLake Iceberg table APIs are in preview.
