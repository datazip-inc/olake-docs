ClickHouse reads Iceberg tables in place through its **DataLakeCatalog database engine**. You can query the copied data with no insert job.

**Short answer.** To query a replicated database in ClickHouse, run OLake Go with a catalog ClickHouse reads, such as Polaris, Lakekeeper or AWS Glue. Then create a DataLakeCatalog database for it. Add ClickHouse as a target query engine and OLake Go preselects equality deletes, which ClickHouse reads from 25.8, including the 26.8 long-term support (LTS) release.

## How OLake Go gets data into ClickHouse

OLake Go uses **change data capture (CDC)** where the source has it and commits Iceberg tables to the catalog. ClickHouse reads [Polaris](/docs/integrations/catalogs/polaris/) and Lakekeeper as REST (representational state transfer) catalogs. Glue, Horizon and Unity Catalog have their own catalog types.

The six guides below ran end to end on Polaris, with Trino and DuckDB reading the same tables. The [ClickHouse lakehouse post](/blog/build-data-lakehouse-iceberg-clickhouse-olake/) is a longer walkthrough.

## When to use it

- ClickHouse should query live database tables without a second copy.
- You want CDC from [Postgres](/docs/connectors/postgres/), [MySQL](/docs/connectors/mysql/) or MongoDB into ClickHouse.

## When not to use it

- You need deletion vectors on the 26.8 LTS release. ClickHouse reads them from 26.10, as an experimental feature.
- You use a JDBC catalog. ClickHouse has no JDBC catalog support.
