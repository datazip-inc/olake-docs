Presto reads Iceberg tables through its Iceberg connector. What it can read depends on whether the workers are Java or **native C++**.

**Short answer.** To query replicated data in Presto, run OLake Go with AWS Glue, Polaris, Lakekeeper, Hive Metastore or Nessie as the Iceberg catalog, and configure the Presto Iceberg connector for it. Positional deletes work on both worker types. Add Presto as a target query engine and OLake Go writes positional deletes.

<TLDR title='Key takeaways'>

- Presto reads OLake Go tables through its Iceberg connector on Glue, [Polaris](/docs/integrations/catalogs/polaris/), Lakekeeper, Hive Metastore or Nessie.
- With Presto as a target query engine, OLake Go writes positional deletes, which Java and native C++ workers both read.
- The [Presto lakehouse post](/blog/building-open-data-lakehouse-with-olake-presto/) shows an earlier end-to-end setup.

</TLDR>

## How OLake Go gets data into Presto

OLake Go uses **change data capture (CDC)** where the source has it. It commits Iceberg tables to the catalog. Presto reads [Polaris](/docs/integrations/catalogs/polaris/) and [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) as REST (representational state transfer) catalogs, and Glue through the Hive catalog type.

No guide ends in Presto yet. The [Presto lakehouse post](/blog/building-open-data-lakehouse-with-olake-presto/) shows an earlier end-to-end setup.

## When to use it

- You already run Presto and want replicated tables beside your existing data.
- The tables are in Glue, Polaris, Lakekeeper, Hive Metastore or Nessie.

## When not to use it

- The cluster runs native C++ workers and the tables use equality deletes. Those need Java workers.
- You need deletion vectors on Java workers. Only Presto C++ 0.299 and later reads them.
