Amazon Redshift queries Apache Iceberg tables through an **external schema** on the AWS Glue Data Catalog. No `COPY` step is involved.

**Short answer.** To replicate a database to Redshift, run OLake Go with AWS Glue as the Iceberg catalog and the data on Amazon S3. Create an external schema in Redshift that points at the Glue database. Add Redshift as a target query engine on the job and OLake Go writes positional deletes, the format Redshift reads on v2 tables.

<TLDR title='Key takeaways'>

- Redshift queries OLake Go tables through an external schema on the [AWS Glue](/docs/integrations/catalogs/glue/) Data Catalog, with no COPY step.
- With Redshift as a target query engine, OLake Go writes positional deletes, the format Redshift reads on v2 tables.
- Nine guides ran end to end on Glue, and each also queries the tables from [Athena](/docs/integrations/athena/).

</TLDR>

## How OLake Go gets data into Redshift

OLake Go uses **change data capture (CDC)** where the source has it and commits each sync to [AWS Glue](/docs/integrations/catalogs/glue/). Redshift and [Athena](/docs/integrations/athena/) both read those tables. Amazon S3 Tables works too, through a Glue resource link.

The nine guides below ran end to end on Glue, and each one also queries the tables from Athena. The [Glue writer page](/docs/writers/iceberg/catalog/glue/) holds the destination reference.

## When to use it

- Redshift or Athena is the main reader and the data is on S3.
- You want one copy of the data in Glue that Spark on EMR can also process.

## When not to use it

- You plan to use deletion vectors on a small Redshift Serverless workgroup. They need more than 4 Redshift Processing Units (RPU) or an RG-type cluster.
- The tables live in Unity Catalog, Polaris or Snowflake Horizon. Redshift reaches those only through Lake Formation catalog federation.
