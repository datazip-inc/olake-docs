OLake Go writes Apache Iceberg tables. The destination is an open table format and a catalog, not a single warehouse.

**Short answer.** To replicate a database to Apache Iceberg, run OLake Go with a source connector and an Iceberg catalog such as AWS Glue, Polaris or Lakekeeper. It writes data and delete files to object storage and commits each sync to the catalog. List every engine that will read the tables, and OLake Go picks a delete format they all read.

_Last reviewed October 2026._

## How OLake Go writes Apache Iceberg

Postgres, MySQL, MariaDB, MongoDB and SQL Server sync with change data capture (CDC). Kafka syncs as a stream, and Oracle, DB2 and S3 sync incrementally. Tables are Iceberg v2 or v3, and the [catalog compatibility page](/docs/understanding/compatibility-catalogs/) lists every catalog.

The Iceberg spec defines three delete formats: equality deletes and positional deletes in v2, and deletion vectors in v3. Each engine reads its own subset. The [delete formats post](/blog/iceberg-delete-formats-interoperability-olake-go/) explains the trade-offs.

## When to use it

- Several engines should read one copy of the replicated data.
- You want the tables in an open format that no single vendor controls.

## When not to use it

- You need the data in a warehouse's own storage format. OLake Go writes Iceberg and Parquet only.
- The source is Oracle, DB2 or S3 and you need row-level CDC. OLake Go reads those sources incrementally.
