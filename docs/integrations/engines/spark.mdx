Apache Spark with the Iceberg runtime reads every catalog OLake Go writes to. It also reads every Iceberg delete format.

**Short answer.** To read replicated tables in Spark, run OLake Go with any Iceberg catalog, then configure a Spark catalog of the matching type, such as `type=glue` or `type=rest`. Spark reads equality deletes, positional deletes and, with **Iceberg 1.8 or later** on the classpath, deletion vectors.

<TLDR title='Key takeaways'>

- Spark with the Iceberg runtime reads every catalog OLake Go writes to, such as [AWS Glue](/docs/integrations/catalogs/glue/) and [Polaris](/docs/integrations/catalogs/polaris/).
- It reads equality deletes, positional deletes and, with Iceberg 1.8 or later, deletion vectors.
- Spark is the cross-check reader on many guides, for example [Postgres to Iceberg](/docs/integrations/postgres-to-iceberg/).

</TLDR>

## How OLake Go gets data into Apache Spark

OLake Go uses **change data capture (CDC)** where the source has it and commits Iceberg tables to the catalog. Spark then reads them for batch jobs, joins or checks. On this site, Spark is the cross-check reader on many guides.

The guides below show Spark reading the tables of each run. The [interoperability post](/blog/iceberg-query-engine-interoperability-spark-databricks/) compares Spark and Databricks on the same tables.

## When to use it

- Spark jobs should transform or join tables that a warehouse also reads.
- You need one reader that opens every catalog and delete format.

## When not to use it

- Spark runs an Iceberg runtime older than 1.8 and the tables use deletion vectors.
- You only need ad hoc SQL on a laptop. [DuckDB](/docs/integrations/duckdb/) attaches the same REST (representational state transfer) catalogs from a single process.
