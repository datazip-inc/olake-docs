Spark on Amazon EMR reads every Iceberg delete format. It can process the tables that OLake Go keeps in sync with an operational database.

**Short answer.** To read replicated tables on EMR, run OLake Go with AWS Glue as the Iceberg catalog, or with Amazon S3 Tables, Polaris, Lakekeeper or Hive Metastore. Point Spark on EMR at the same catalog. Deletion vectors need EMR 7.12 or later, which ships Iceberg 1.10.

_Last reviewed October 2026._

## How OLake Go gets data into Spark on Amazon EMR

OLake Go uses change data capture (CDC) where the source has it. It commits Iceberg tables to the catalog. Spark on EMR reads [AWS Glue](/docs/integrations/catalogs/glue/) natively. [S3 Tables](/docs/integrations/catalogs/s3tables/) works from EMR 7.5, and Polaris and Lakekeeper connect as REST (representational state transfer) catalogs.

No guide on this site runs EMR yet. The open-source [Spark page](/docs/integrations/spark/) covers the same catalog settings, and the [Glue writer page](/docs/writers/iceberg/catalog/glue/) covers the destination.

## When to use it

- Spark jobs on AWS should transform or join the replicated tables.
- You already run EMR and want one copy of the data in Glue that Athena can also query.

## When not to use it

- You only need SQL over the tables. [Athena](/docs/integrations/athena/) reads the same Glue tables with no cluster.
- The cluster runs a release before EMR 7.5 and the tables are in S3 Tables. The S3 Tables catalog needs EMR 7.5 or later.
