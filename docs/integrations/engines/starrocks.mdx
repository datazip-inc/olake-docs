StarRocks reads Iceberg tables through an external Iceberg catalog. Positional deletes are the format every StarRocks release reads.

**Short answer.** To query replicated data in StarRocks, run OLake Go with AWS Glue, Polaris, Lakekeeper, Hive Metastore or a Java Database Connectivity (JDBC) catalog, then create an Iceberg catalog in StarRocks for it. Add StarRocks as a target query engine and OLake Go writes positional deletes, because no released StarRocks version reads deletion vectors.

_Last reviewed October 2026._

## How OLake Go gets data into StarRocks

OLake Go uses change data capture (CDC) where the source has it. It commits Iceberg tables to the catalog. StarRocks reads [Polaris](/docs/integrations/catalogs/polaris/) and [Lakekeeper](/docs/integrations/catalogs/lakekeeper/) as REST (representational state transfer) catalogs and [AWS Glue](/docs/integrations/catalogs/glue/) directly.

No guide ends in StarRocks yet. The [compatibility matrix](/docs/understanding/compatibility-engines/) compares it with the other engines.

## When to use it

- You run StarRocks for analytics and want replicated tables beside its internal tables.
- The catalog is Glue, Polaris, Lakekeeper, Hive Metastore or JDBC.

## When not to use it

- Another engine on the job reads only deletion vectors, such as Databricks under Unity Catalog.
- You run StarRocks before 3.5.19 and the tables use equality deletes with NULL keys. A bug there was fixed in 3.5.19.
