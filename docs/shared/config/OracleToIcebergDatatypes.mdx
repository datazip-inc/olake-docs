:::info[Oracle NUMBER limits]
- `NUMBER(p,0)` lands as `int` up to 9 digits and as `bigint` above. A value past 9,223,372,036,854,775,807, which `NUMBER(19-38,0)`, `INTEGER` and `NUMBER(*,0)` can hold, fails the sync.
- `NUMBER(p,-1)` stays `double`. The Oracle driver reports its scale with the same byte it uses for `FLOAT` and an unconstrained `NUMBER`, so a read can't tell them apart.
:::

:::info[timestamptz timezone]
OLake Go always ingests timestamp data in UTC format, independent of the source timezone.
:::
