:::info Binary column types (MySQL only)
From **state version 8** (OLake Go **v0.10.2** and above), MySQL binary columns map to `binary` or `fixed_binary(n)` as shown above. Pipelines whose state was written by an older build keep binary columns mapped to **string**; upgrading OLake alone does **not** change destination columns that already exist as string.

Other sources are unchanged: Postgres `bytea`, SQL Server `binary` / `varbinary` / `image`, Oracle `RAW` and `BLOB`, Db2 `BLOB`, MongoDB binary, and S3 byte columns still map to **string**.

At the destination, OLake types map to Iceberg and Parquet as follows:

| OLake type        | Iceberg              | Parquet                    |
| ----------------- | -------------------- | -------------------------- |
| `binary`          | `binary`             | `BYTE_ARRAY`               |
| `fixed_binary(n)` | `fixed[n]`           | `FIXED_LEN_BYTE_ARRAY(n)`  |
:::

:::info `VARBINARY(n)` vs `BINARY(n)`
Only **`BINARY(n)`** uses `fixed_binary(n)` because `n` is a fixed width. **`VARBINARY(n)`** maps to **`binary`** (variable length), because `n` is a maximum length, not a fixed width.
:::

:::info `fixed_binary(n)` read and write behavior
Values **shorter than `n`** are right-padded with zero bytes (same as MySQL `BINARY(n)` storage), so full refresh and CDC produce identical bytes. Values **longer than `n`** are rejected with an error; they are not truncated.
:::

:::caution `fixed_binary(n)` and schema evolution
Iceberg cannot promote `fixed[n]` to `binary`, or to a different fixed width. If a source column changes from `BINARY(16)` to `BINARY(32)`, or to `VARBINARY`, the destination table must be **recreated**. There is no in-place evolution for this type.
:::

:::info Binary columns in the primary key
If a binary column is part of the primary key, its value is **hex-encoded** in `_olake_id` from state version 8 onward. `_olake_id` values for such tables therefore differ from those produced by older builds.
:::

:::info INT UNSIGNED mapping change
From OLake Go version `0.4.1` and above, `INT UNSIGNED` maps to `bigint` in the destination. In versions earlier than `0.4.1`, it maps to `int`.
:::

:::info timestamptz timezone
OLake Go always ingests timestamp data in UTC format, independent of the source timezone.
:::
