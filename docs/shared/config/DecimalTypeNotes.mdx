:::info[Decimal columns]
- **New jobs:** jobs created on OLake Go **v1.2.0 and above** land these columns as `decimal(p,s)`. In OLake UI this needs no extra step. In the CLI, run the first `sync` without `--state`: a hand-made `{}` state file runs in legacy mode and lands these columns as `double`.
- **Existing jobs:** jobs created on an older version keep these columns as `double`. Upgrading OLake Go alone does not convert a column that already lands as `double`. To switch them to `decimal(p,s)` on OLake Go v1.2.0 or later:
  - **OLake UI:** run [Clear Destination](/docs/getting-started/job-level-properties/#8-clear-destination).
  - **CLI:** run `clear-destination` for all of the job's streams, then run the next `sync` without `--state` (or delete `state.json` first). `clear-destination` keeps the old state version, so a sync that reuses that state file still writes `double`.
- A destination decimal holds at most 38 digits, because Iceberg and Spark hold no wider decimal. {props.source === 'oracle'
  ? <>A scale of 0 does not map to a decimal: <code>NUMBER(p,0)</code> lands as <code>int</code> or <code>bigint</code>.</>
  : props.source === 's3'
  ? <>A scale of 0 still maps to a decimal, so a Parquet <code>DECIMAL(10,0)</code> becomes <code>decimal(10,0)</code>.</>
  : <>A scale of 0 still maps to a decimal, so <code>NUMERIC(10)</code> becomes <code>decimal(10,0)</code>.</>}
- Columns that land as `double` keep about 17 significant digits, so wider values round.
- If a `double` column is part of the primary key, keys that differ only past about 17 significant digits get the same `_olake_id` and replace each other in upsert mode.
- Decimal columns keep every digit when used as a [cursor field](/docs/understanding/terminologies/olake/#2-sync-modes), in a [data filter](/docs/understanding/terminologies/olake/#3-data-filter) or in the primary key's [`_olake_id`](/docs/understanding/terminologies/general/#3-record-identification-_olake_id).
:::
