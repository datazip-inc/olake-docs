BigLake is the Iceberg REST catalog built into Google Cloud's Lakehouse. OLake Go talks to it at `https://biglake.googleapis.com/iceberg/v1/restcatalog`, the table files land in a Cloud Storage bucket you own, and BigQuery reads the tables without any registration step. Writing to BigLake needs OLake Go 0.9.1 or later.

Everything below happens in the Google Cloud console, in the project that will hold the tables.

1. **Enable the API.** Open **APIs and services**, then **Enable APIs and services**, and enable the **BigLake API**. BigQuery and Cloud Storage are on by default in most projects.
2. **Create a bucket.** In **Cloud Storage**, create a bucket in the region where BigQuery will run the queries (`us-central1` on this page). The bucket name becomes the catalog name in BigQuery, so pick one you are happy to type in SQL.
3. **Create a service account for OLake Go.** In **IAM and Admin**, **Service Accounts**, create one (for example `olake-biglake`). Then grant it two roles: **BigLake Editor** on the project (**IAM**, **Grant access**, the service account as principal) and **Storage Object User** on the bucket (the bucket's **Permissions** tab).
4. **Download a JSON key.** On the service account's **Keys** tab, **Add key**, **Create new key**, **JSON**. The file downloads once; OLake Go asks for its contents.

There is no catalog to create. BigLake creates a single-bucket catalog named after the bucket the first time OLake Go calls the endpoint with `gs://<bucket>` as the catalog path, in the default **end-user** credential mode, where every client brings its own storage credentials. The catalog shows up under **BigLake**, **Catalogs** after the first connection test.

Two things to know before the first sync:

- The service account's **BigLake Editor** role is what lets OLake Go create namespaces and commit tables. **Storage Object User** on the bucket is what lets it write the Parquet and metadata files. Missing either one fails the connection test with a `403` from `biglake.googleapis.com` or from `storage.googleapis.com`, which tells you which grant is missing.
- Leave the catalog in end-user mode. OLake Go 1.1.0 does not send the `X-Iceberg-Access-Delegation` header, so a catalog switched to **vended credentials** rejects its commits (see troubleshooting). Readers that want short-lived tokens from the catalog can switch the mode later with `gcloud beta biglake iceberg catalogs update <bucket> --credential-mode=vended-credentials`, after setting `rest_access_delegation` in a CLI config.
