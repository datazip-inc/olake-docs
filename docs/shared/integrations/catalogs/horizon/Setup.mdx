Snowflake Horizon is the catalog built into every Snowflake account. OLake Go talks to it through the Iceberg REST endpoint at `https://<account_identifier>.snowflakecomputing.com/polaris/api/catalog`, and the tables it creates are Snowflake-managed Iceberg tables. External writes through this endpoint are generally available since 2026-05-26 and need OLake Go 0.11.0 or later.

Run the following once in a Snowsight worksheet as `ACCOUNTADMIN`. It creates a database for the tables, a role OLake Go writes as, a service user that holds the token, and the authentication policy the token needs.

```sql title="Snowflake, once per account"
USE ROLE ACCOUNTADMIN;

-- A small warehouse for your own queries, and the database OLake Go writes into.
CREATE WAREHOUSE IF NOT EXISTS OLAKE_WH WAREHOUSE_SIZE = XSMALL AUTO_SUSPEND = 60 AUTO_RESUME = TRUE;
CREATE DATABASE IF NOT EXISTS OLAKE_DEMO;
ALTER DATABASE OLAKE_DEMO SET CATALOG = 'SNOWFLAKE';
ALTER DATABASE OLAKE_DEMO SET EXTERNAL_VOLUME = 'SNOWFLAKE_MANAGED';

-- The role OLake Go uses. It needs to create schemas; tables are created inside them.
CREATE ROLE IF NOT EXISTS OLAKE_ROLE;
GRANT USAGE, CREATE SCHEMA ON DATABASE OLAKE_DEMO TO ROLE OLAKE_ROLE;
GRANT USAGE ON WAREHOUSE OLAKE_WH TO ROLE OLAKE_ROLE;
GRANT ROLE OLAKE_ROLE TO ROLE SYSADMIN;

-- A service user (no password, no UI login) that owns the programmatic access token.
CREATE USER IF NOT EXISTS OLAKE_SVC TYPE = SERVICE DEFAULT_ROLE = OLAKE_ROLE;
GRANT ROLE OLAKE_ROLE TO USER OLAKE_SVC;

-- Service users need a network policy to use a token, unless the authentication policy says otherwise.
CREATE AUTHENTICATION POLICY IF NOT EXISTS OLAKE_DEMO.PUBLIC.OLAKE_PAT_POLICY
  PAT_POLICY = (NETWORK_POLICY_EVALUATION = ENFORCED_NOT_REQUIRED);
ALTER USER OLAKE_SVC SET AUTHENTICATION POLICY OLAKE_DEMO.PUBLIC.OLAKE_PAT_POLICY;

-- The two values OLake Go asks for.
SELECT CURRENT_ORGANIZATION_NAME() || '-' || CURRENT_ACCOUNT_NAME() AS account_identifier,
       CURRENT_REGION() AS region;

-- The token. Snowflake shows the secret once; copy it straight into OLake Go.
ALTER USER OLAKE_SVC ADD PROGRAMMATIC ACCESS TOKEN OLAKE_PAT
  ROLE_RESTRICTION = 'OLAKE_ROLE' DAYS_TO_EXPIRY = 30;
```

What each line is for:

- `CATALOG = 'SNOWFLAKE'` and `EXTERNAL_VOLUME = 'SNOWFLAKE_MANAGED'` on the database make every table OLake Go creates a Snowflake-managed Iceberg table on Snowflake's own storage. No S3 bucket, IAM role or external volume on your side. To keep the files in your own bucket, create an external volume and name it here instead.
- `TYPE = SERVICE` creates a user that cannot log in to Snowsight. It only carries the token.
- The authentication policy is the step people miss. By default a service user must sit under a network policy before a programmatic access token (PAT) works; `ENFORCED_NOT_REQUIRED` lifts that requirement for a test. In production, attach a network policy that allows OLake Go's egress IP instead.
- `ROLE_RESTRICTION` pins the token to `OLAKE_ROLE`, so a leaked token cannot act as `ACCOUNTADMIN`. Tokens expire after `DAYS_TO_EXPIRY` (15 by default, 365 at most). Rotate it before then or the sync fails with an authentication error.

You can check the token outside OLake Go by exchanging it for a session token, the same call OLake Go makes on every sync:

```bash title="Token check"
curl -s -X POST "https://<account_identifier>.snowflakecomputing.com/polaris/api/catalog/v1/oauth/tokens" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode grant_type=client_credentials \
  --data-urlencode scope=session:role:OLAKE_ROLE \
  --data-urlencode client_secret=<your PAT>
```

A good token returns a JSON object with an `access_token`. The other authentication methods (key-pair JWT, External OAuth, workload identity federation) are on the [Horizon catalog page](/docs/writers/iceberg/catalog/rest/?rest-catalog=horizon).
