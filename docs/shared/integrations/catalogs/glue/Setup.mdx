AWS Glue Data Catalog is the default catalog in OLake Go. The tables live as Parquet and metadata files in an S3 bucket you own, and Glue holds the pointer to the current metadata file. Athena, Redshift, EMR, Spark and DuckDB read the same tables through Glue, which is why it is the catalog to pick when more than one AWS engine will read the data.

You need:

- An S3 bucket for the table files, in the region where your engines run.
- An IAM user or role for OLake Go with Glue and S3 permissions. The exact policy is on the [AWS Glue catalog page](/docs/writers/iceberg/catalog/glue/#2-aws-iam-permissions).
- No Glue database in advance: OLake Go creates one per job, named after the source database and schema (for example `pg_to_snowflake_shop_public`).

Glue has no built-in compaction for tables written by external engines, so plan on [OLake Fusion](/docs/fusion/getting-started/overview/) or Spark for maintenance once the change volume grows.
