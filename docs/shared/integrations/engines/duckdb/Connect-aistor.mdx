DuckDB attaches AIStor Tables as an Iceberg REST catalog and signs every catalog request with SigV4. One S3 secret does both jobs: it signs the catalog calls under the `s3tables` service and reads the data files from AIStor.

<CodeBlock language="sql" title="DuckDB 1.5.5">{`INSTALL iceberg; LOAD iceberg;

CREATE SECRET aistor_s3 (
  TYPE S3,
  KEY_ID '<access-key>', SECRET '<secret-key>',
  ENDPOINT '<aistor-host>:9000',   -- host and port only, no scheme
  URL_STYLE 'path', USE_SSL 0, REGION 'local'
);

ATTACH 'olake' AS aistor (
  TYPE ICEBERG,
  ENDPOINT 'http://<aistor-host>:9000/_iceberg',
  AUTHORIZATION_TYPE 'sigv4',
  SIGV4_SERVICE 's3tables',
  SIGV4_REGION 'local',
  SECRET aistor_s3
);

SHOW ALL TABLES;
SELECT ${props.idCol ?? 'id'}, name, city, tier FROM aistor.${props.schema ?? 'postgres_to_aistor_shop_public'}.customers ORDER BY ${props.idCol ?? 'id'};`}</CodeBlock>

Set `USE_SSL 1` when AIStor serves HTTPS. MinIO documents DuckDB 1.5 or later for AIStor Tables and asks for single-level namespaces in warehouses DuckDB reads, which is what OLake Go creates.
