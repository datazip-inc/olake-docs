DuckDB reads an Iceberg table from its current metadata file, which Glue holds as the table's `metadata_location`. Ask Glue for it, then scan: no catalog to configure, and the same S3 keys you gave OLake Go are enough.

```bash title="The current metadata file, from Glue"
aws glue get-table --database-name <glue database> --name customers \
  --query 'Table.Parameters.metadata_location' --output text
```

<CodeBlock language="sql" title="DuckDB 1.5.5">{`INSTALL iceberg; LOAD iceberg;
INSTALL httpfs;  LOAD httpfs;

CREATE SECRET lake (TYPE s3, KEY_ID '<access key>', SECRET '<secret key>', REGION '<region>');

SELECT ${props.idCol ?? 'id'}, name, city, tier
FROM iceberg_scan('s3://<bucket>/lakehouse/${props.schema ?? 'postgres_to_redshift_shop_public'}.db/customers/metadata/<latest>.metadata.json')
ORDER BY ${props.idCol ?? 'id'};`}</CodeBlock>

Each sync writes a new metadata file, so fetch the location again before a fresh read, or wrap the two steps in a script. DuckDB can also attach the Glue Data Catalog as an Iceberg REST catalog (`ATTACH '<account id>' AS glue (TYPE iceberg, ENDPOINT_TYPE 'glue')`), which needs Lake Formation permissions on the catalog; that path is not covered on this page. DuckDB reads positional deletes, and deletion vectors from duckdb-iceberg 1.5.3.
