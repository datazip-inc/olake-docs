DuckDB attaches Horizon as an Iceberg REST catalog. It wants a bearer token rather than the raw PAT, so exchange the PAT first (the `curl` call from the catalog setup), then attach:

<CodeBlock language="sql" title="DuckDB 1.5.5">{`INSTALL iceberg; LOAD iceberg;
INSTALL httpfs;  LOAD httpfs;

CREATE SECRET horizon_secret (TYPE iceberg, TOKEN '<access_token from /v1/oauth/tokens>');

ATTACH 'OLAKE_DEMO' AS horizon (
  TYPE iceberg,
  ENDPOINT 'https://<account_identifier>.snowflakecomputing.com/polaris/api/catalog',
  SECRET horizon_secret,
  ACCESS_DELEGATION_MODE 'vended_credentials'
);

SHOW ALL TABLES;
SELECT ${props.idCol ?? 'id'}, name, city, tier FROM horizon.${props.schema ?? 'pg_to_snowflake_shop_public'}.customers ORDER BY ${props.idCol ?? 'id'};`}</CodeBlock>

The session token lives about an hour; re-run the exchange and `CREATE OR REPLACE SECRET` when a query fails with an authorization error. DuckDB reads deletion vectors from duckdb-iceberg 1.5.3 onward, and only attaches REST catalogs backed by S3, S3 Tables or Google Cloud Storage, so pick an AWS- or GCP-hosted Snowflake account for this path.
