DuckDB attaches the Unity Catalog catalog as an Iceberg REST catalog with the same token. With `vended_credentials`, Unity Catalog hands DuckDB short-lived storage credentials per table, so no cloud keys are configured on the DuckDB side.

<CodeBlock language="sql" title="DuckDB 1.5.5">{`INSTALL iceberg; LOAD iceberg;
INSTALL httpfs;  LOAD httpfs;
CREATE SECRET unity (TYPE iceberg, TOKEN '<personal access token>');
ATTACH '${props.catalog ?? 'lakehouse'}' AS uc (
  TYPE iceberg,
  ENDPOINT 'https://<workspace-url>/api/2.1/unity-catalog/iceberg-rest',
  SECRET unity,
  ACCESS_DELEGATION_MODE 'vended_credentials'
);
SELECT ${props.key ?? 'id'}, name, city, tier
FROM uc.${props.schema ?? 'postgres_to_databricks_shop_public'}.customers
ORDER BY ${props.key ?? 'id'};`}</CodeBlock>

DuckDB reads Iceberg v3 deletion vectors from duckdb-iceberg 1.5.3, so the rows match Databricks after every sync. The principal behind the token needs `EXTERNAL USE SCHEMA`, the same as OLake Go.
