Spark reaches BigLake as a plain Iceberg REST catalog with Google's auth manager from the `iceberg-gcp-bundle`. The same service account key OLake Go uses works for both the catalog calls and the file reads, so point `GOOGLE_APPLICATION_CREDENTIALS` at it before starting Spark.

```bash title="spark-sql against BigLake"
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json
spark-sql \
  --packages org.apache.iceberg:iceberg-spark-runtime-4.0_2.13:1.10.0,org.apache.iceberg:iceberg-gcp-bundle:1.10.0 \
  --conf spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions \
  --conf spark.sql.catalog.biglake=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.biglake.type=rest \
  --conf spark.sql.catalog.biglake.uri=https://biglake.googleapis.com/iceberg/v1/restcatalog \
  --conf spark.sql.catalog.biglake.warehouse=gs://<bucket> \
  --conf spark.sql.catalog.biglake.rest.auth.type=org.apache.iceberg.gcp.auth.GoogleAuthManager \
  --conf spark.sql.catalog.biglake.header.x-goog-user-project=<project-id> \
  --conf spark.sql.catalog.biglake.io-impl=org.apache.iceberg.gcp.gcs.GCSFileIO
```

Use the Spark 4.0 runtime with Iceberg 1.10 or later; Spark 3.5 builds of Iceberg do not run on Java 21. Spark reads positional deletes with any Iceberg version, so no table setting changes when the job's delete format stays positional.
