Spark reaches Horizon as a plain Iceberg REST catalog. The token is the same PAT OLake Go uses; `scope` picks the Snowflake role and the `X-Iceberg-Access-Delegation` header asks Horizon for short-lived storage credentials, so Spark never needs S3 keys.

```bash title="spark-sql against Horizon"
spark-sql \
  --packages org.apache.iceberg:iceberg-spark-runtime-3.5_2.12:1.10.0,org.apache.iceberg:iceberg-aws-bundle:1.10.0 \
  --conf spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions \
  --conf spark.sql.catalog.horizon=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.horizon.type=rest \
  --conf spark.sql.catalog.horizon.uri=https://<account_identifier>.snowflakecomputing.com/polaris/api/catalog \
  --conf spark.sql.catalog.horizon.warehouse=OLAKE_DEMO \
  --conf spark.sql.catalog.horizon.credential=<your PAT> \
  --conf spark.sql.catalog.horizon.scope=session:role:OLAKE_ROLE \
  --conf spark.sql.catalog.horizon.header.X-Iceberg-Access-Delegation=vended-credentials
```

SELECT id, name, city, tier FROM horizon.${props.schema ?? 'pg_to_snowflake_shop_public'}.customers ORDER BY id;`}</CodeBlock>

Use Iceberg 1.8 or later on the classpath when the tables carry deletion vectors; 1.10.0 is what this page was tested with. The `AWS_REGION` environment variable must be set to the region of the Snowflake account's storage (for example `ap-south-1` for `AWS_AP_SOUTH_1`) or the vended credentials are rejected.
