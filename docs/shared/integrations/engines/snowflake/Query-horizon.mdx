There is no registration step. The schema and tables OLake Go committed through Horizon are already Snowflake-managed Iceberg tables in the database you configured. One thing to know before the first query: OLake Go creates them with quoted, lowercase names, so Snowflake needs the double quotes.

```sql title="Snowsight"
-- What OLake Go created (schema = <job name>_<source database>_<source schema>)
SHOW ICEBERG TABLES IN SCHEMA OLAKE_DEMO."pg_to_snowflake_shop_public";

-- Quoted identifiers: the names are lowercase, as they were in Postgres.
-- Rows deleted in Postgres stay as tombstones (_op_type = 'd'), so filter them out.
SELECT "id", "name", "city", "tier"
FROM OLAKE_DEMO."pg_to_snowflake_shop_public"."customers"
WHERE "_op_type" <> 'd'
ORDER BY "id";
```

`SHOW ICEBERG TABLES` reports `catalog_name = SNOWFLAKE`, `iceberg_table_type = MANAGED` and `external_volume_name = SNOWFLAKE_MANAGED`: Snowflake treats them as its own managed Iceberg tables, not as external tables that need a refresh.

OLake Go adds four columns to every table: `_olake_id` (a hash of the primary key), `_op_type` (`r` for the snapshot, `c`, `u`, `d` for later changes), `_olake_timestamp` and `_cdc_timestamp`. Filter them out of dashboards, or use them to audit when a row last changed.
