There is no registration step. The schema and tables OLake Go committed through Horizon are already Snowflake-managed Iceberg tables in the database you configured. One thing to know before the first query: OLake Go creates them with quoted, lowercase names, so Snowflake needs the double quotes.

<CodeBlock language="sql" title="Snowsight">{`-- What OLake Go created (schema = <job name>_<source database>[_<source schema>])
SHOW ICEBERG TABLES IN SCHEMA OLAKE_DEMO."${props.schema ?? 'pg_to_snowflake_shop_public'}";

-- Quoted identifiers: the names are lowercase, as they were in the source
SELECT "id", "name", "city", "tier"
FROM OLAKE_DEMO."${props.schema ?? 'pg_to_snowflake_shop_public'}"."customers"
ORDER BY "id";`}</CodeBlock>

`SHOW ICEBERG TABLES` reports `catalog_name = SNOWFLAKE`, `iceberg_table_type = MANAGED` and `external_volume_name = SNOWFLAKE_MANAGED`: Snowflake treats them as its own managed Iceberg tables, not as external tables that need a refresh.

OLake Go adds four columns to every table: `_olake_id` (a hash of the primary key), `_op_type`, `_olake_timestamp` and `_cdc_timestamp`. `_op_type` is `r` for a row from the first snapshot, `c` for an insert, `u` for an update and `d` for a delete. Filter them out of dashboards, or use them to see when a row last changed.
