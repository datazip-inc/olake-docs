Redshift reads the Glue Data Catalog through an *external schema*: one statement maps a Glue database onto a schema name in your Redshift database, and every Iceberg table OLake Go commits there is queryable at once, with no refresh. Redshift Serverless and RA3 clusters both do this; the IAM role attached to the namespace or cluster needs read access to Glue and to the bucket.

<CodeBlock language="sql" title="Redshift query editor v2">{`-- Once: map the Glue database OLake Go created (schema = <job name>_<source database>_<source schema>)
CREATE EXTERNAL SCHEMA lakehouse
FROM DATA CATALOG
DATABASE '${props.schema ?? 'postgres_to_redshift_shop_public'}'
IAM_ROLE default;

-- Then query the Iceberg tables like any other schema
SELECT ${props.key ?? 'id'}, name, city, tier FROM lakehouse.customers ORDER BY ${props.key ?? 'id'};
SELECT status, count(*) AS n, ${props.amount ?? 'round(sum(amount), 2)'} AS total
FROM lakehouse.orders GROUP BY status ORDER BY status;`}</CodeBlock>

`IAM_ROLE default` uses the default role of the namespace (Serverless) or cluster; name a role ARN instead when you keep several. Redshift reads Iceberg v2 tables with positional deletes, which is why the job on this page uses that upsert type. The external schema is read-only: OLake Go is the writer, and `INSERT` or `DELETE` on these tables fails.

OLake Go adds four columns to every table: `_olake_id` (a hash of the primary key), `_op_type`, `_olake_timestamp` and `_cdc_timestamp`. `_op_type` is `r` for a row from the first snapshot, `c` for an insert, `u` for an update and `d` for a delete. Filter them out of dashboards, or use them to see when a row last changed.
