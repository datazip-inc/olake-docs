Trino reaches AIStor Tables through its Iceberg connector in REST mode, with SigV4 signing under the `s3tables` service. One catalog properties file does it; the same keys sign catalog requests and read the files.

```properties title="etc/catalog/aistor.properties"
connector.name=iceberg
iceberg.catalog.type=rest
iceberg.rest-catalog.uri=http://<aistor-host>:9000/_iceberg
iceberg.rest-catalog.warehouse=olake
iceberg.rest-catalog.security=SIGV4
iceberg.rest-catalog.signing-name=s3tables
iceberg.unique-table-location=true
fs.native-s3.enabled=true
s3.region=local
s3.endpoint=http://<aistor-host>:9000
s3.path-style-access=true
s3.aws-access-key=<access-key>
s3.aws-secret-key=<secret-key>
```

SELECT ${props.idCol ?? 'id'}, name, city, tier FROM aistor.${props.schema ?? 'postgres_to_aistor_shop_public'}.customers ORDER BY ${props.idCol ?? 'id'};`}</CodeBlock>

Trino 477 and later take `iceberg.rest-catalog.security=SIGV4`; on Trino 476 and earlier use `iceberg.rest-catalog.sigv4-enabled=true` instead. The run on this page used Trino 484.
