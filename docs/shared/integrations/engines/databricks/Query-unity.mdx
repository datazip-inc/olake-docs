There is no registration step. The schema and tables OLake Go committed through Unity Catalog are managed Iceberg tables in the catalog you configured, and the Databricks SQL editor or a notebook reads them by their three-part name.

<CodeBlock language="sql" title="Databricks SQL editor">{`-- What OLake Go created (schema = <job name>_<source database>[_<source schema>])
SHOW TABLES IN ${props.catalog ?? 'lakehouse'}.${props.schema ?? 'postgres_to_databricks_shop_public'};

SELECT ${props.idCol ?? 'id'}, name, city, tier
FROM ${props.catalog ?? 'lakehouse'}.${props.schema ?? 'postgres_to_databricks_shop_public'}.customers
ORDER BY ${props.idCol ?? 'id'};

SELECT status, count(*) AS n, ${props.amount ?? 'round(sum(amount), 2)'} AS total
FROM ${props.catalog ?? 'lakehouse'}.${props.schema ?? 'postgres_to_databricks_shop_public'}.orders
GROUP BY status ORDER BY status;`}</CodeBlock>

Any SQL warehouse or cluster on a recent Databricks Runtime reads them; a 2X-Small serverless warehouse is enough for checks. `DESCRIBE EXTENDED` on a table shows the Iceberg provider and the deletion vectors in its properties.

OLake Go adds four columns to every table: `_olake_id` (a hash of the primary key), `_op_type`, `_olake_timestamp` and `_cdc_timestamp`. `_op_type` is `r` for a row from the first snapshot, `c` for an insert, `u` for an update and `d` for a delete. Filter them out of dashboards, or use them to see when a row last changed.
