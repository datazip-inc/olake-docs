<TabItem value="ui" label="OLake UI" default>

1. In the OLake UI, open **Sources** and click **Create Source**. Pick **Kafka** as the connector, give the source a name and keep the OLake Go version on the latest release.
2. The **Enable CDC** toggle under **Change data capture (CDC)** reads *not supported* for Kafka and stays off. That is expected: the topic is the change stream, and the job's **CDC Only** sync mode reads it.
3. Under **Connection details**, fill in **Bootstrap Servers** (`host:port`, comma-separated for several brokers), a **Consumer Group ID** for this job only, and a **Topic Pattern** regular expression that matches only the topics you want. Pick the **Security Protocol** the cluster uses: `PLAINTEXT`, `SASL_PLAINTEXT` or `SASL_SSL`, with the SASL mechanism and credentials when needed. Turn on **Use Schema Registry** only for Avro topics.
4. Leave **Additional configuration** at its defaults, or set **Max Threads** to the number of partitions you want read in parallel.
5. Click **Set up source**. OLake Go pings the brokers. Topics are matched against the pattern at discovery, when the job is created; if the pattern matches nothing, the Streams page comes up empty and the sync log names every topic it skipped.

{props.children}

The full field reference, including SASL and schema-registry options, is on the [Kafka connector page](/docs/connectors/kafka/#configuration).

</TabItem>
<TabItem value="cli" label="OLake CLI">

Create `source.json` in your config folder. `bootstrap_servers`, `protocol` and `consumer_group_id` are the fields that matter; `topic_pattern` keeps discovery to the topics you want:

<KafkaSourceConfig />

Then confirm OLake Go can reach the brokers:

```bash title="check command"
docker run --pull=always \
  -v "$PWD/config:/mnt/config" \
  olakego/source-kafka:latest \
  check --config /mnt/config/source.json
```

A working setup returns `"status": "SUCCEEDED"`. A wrong address returns `failed to ping kafka brokers: unable to dial`, which means the container cannot reach the port, not that the credentials are wrong. Every field is described on the [Kafka connector page](/docs/connectors/kafka/?config-type=olake-cli#configuration).
