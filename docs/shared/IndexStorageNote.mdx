:::info[Index storage for positional deletes and deletion vectors]
An upsert stream that writes positional deletes or deletion vectors, picked directly or through [Target Query Engines](/docs/getting-started/job-level-properties/#target-query-engines), keeps a row index on local disk between runs. {props.source === 'kafka'
  ? <>Kafka upserts can only use these two formats, so they always need the index.</>
  : props.source === 'postgres'
  ? <>A source with <strong>Preserve TOAST Values</strong> on always needs the index, because its streams can only use these two formats and OLake Go recovers the unchanged values through it.</>
  : null}

Without persistent storage, each sync rebuilds the index by scanning the whole Iceberg table. Set it up for [Docker Compose](/docs/install/olake-ui/#index-db-setup-for-positional-delete-deletion-vector-writes), [Kubernetes (Helm)](/docs/install/kubernetes/#index-storage-for-positional-delete-deletion-vector-writes) or the [Docker CLI](/docs/install/docker-cli/#index-storage).
:::
