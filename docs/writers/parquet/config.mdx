# S3 Parquet

OLake Go writes Parquet through the Amazon S3 connector. **Storage Type** selects S3-compatible storage (AWS S3, GCS, or MinIO) or Azure. Before proceeding, review the [Getting Started](/docs/getting-started/quickstart) and [Installation](/docs/install/olake-ui) sections.

## Prerequisites
- Before setting up the destination, make sure you have successfully set up the [`source`](/docs/getting-started/creating-first-pipeline#2-configure-source).
- **AWS S3:** Review the minimum required [IAM Permissions for S3 Parquet Writer](/docs/writers/parquet/permission).
- **GCS:** Review [GCP IAM Permission](/docs/writers/parquet/permission#2-gcs-google-cloud-storage-iam-policy) for role-based access, and create HMAC keys for your service account to use as S3 credentials. See [Creation of HMAC Keys](https://docs.cloud.google.com/storage/docs/authentication/hmackeys) below.

- The identity must be able to list, read, write, and delete blobs in the container.

## Configuration

Configure the following fields to write Parquet files to Azure.

### Authentication

It supports multiple authentication types. Select the authentication mechanism your storage account uses.

<Tabs queryString="azure-auth-type" groupId="parquet-azure-auth">

<TabItem value="connection-string" label="Connection String" default>

To use **Connection String** authentication, pass one connection string to OLake Go. The key can be an account key or a SAS key.

- The string must contain `AccountName` or `BlobEndpoint`, and `AccountKey` or `SharedAccessSignature`.
- When the string contains an `AccountKey`, OLake Go pulls that key out and signs each Blob request with it.
- A string with `SharedAccessSignature` is not signed with an `AccountKey`.
- `UseDevelopmentStorage=true` is rejected unless `AccountName`, `AccountKey`, and `BlobEndpoint` are all set.

Follow the steps in the [Manage storage account access keys](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage?tabs=azure-portal) documentation to access the key.

<Tabs queryString="tab">

<TabItem value="azure-ui" label="OLake UI" default>

![OLake S3 destination config fields and reference guide.](/img/docs/s3/azure-conn-string.webp)

**Connection String Configuration Parameters:**

| Parameter | Sample Value | Description |
|-----------|--------------|-------------|
| **Storage Type** | `Azure` | Storage backend OLake Go uses to write Parquet files. Set to Azure to write to Azure Blob Storage. |
| **Azure Auth Type** <br/> `required` | `Connection String` | Authentication method OLake Go uses for Azure Blob requests. Set to match your storage account's authentication requirement. |
| **Azure Storage Container Name** <br/> `required` | `olake-data` | Name of an existing Azure storage container with permission to store output files. |
| **Azure Path** | `/data` | Path inside the container where data files are written. |
| **Azure Connection String** <br/> `required` | `DefaultEndpointsProtocol=https;AccountName=<ACCOUNT_NAME>;AccountKey=<ACCOUNT_KEY>;EndpointSuffix=core.windows.net` | Connection string OLake Go uses to authenticate Blob requests. The key inside it can be an Account key or a SAS key. |
| **Max File Size (MB)** | A positive number (integers e.g. `512`, `128` or fractional e.g. `0.1` for `100KB`) | Rolls a partition into a new parquet file once the current file reaches this size in MB. Fractional values are allowed. Defaults to 512 when unset. |

</TabItem>

<TabItem value="shared-key" label="Shared Key">

To use **Shared Key** authentication, copy a storage account access key in Azure and give OLake Go the raw key and the account name as separate fields. OLake Go uses the key to sign each Blob request, and Azure checks the signature. Follow the steps in the [Manage storage account access keys](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage?tabs=azure-portal) documentation to access the key.

<TabItem value="sas-token" label="SAS Token">

To use **SAS Token** authentication, generate a shared access signature for your container in Azure and give OLake Go the token and the account name as separate fields. The token limits what OLake Go can do: it is scoped to a container, and its permissions can be set directly on the token or through a stored access policy. OLake Go appends the token to each Blob request, and Azure checks the signature and the permissions before allowing the request.

- The token must be the query string (`sv=...&sig=...`), with or without a leading `?`. It must not be the full blob URL.
- The expiry is whatever was set when the SAS was created.

Follow the steps in the [Grant limited access to Azure Storage](https://learn.microsoft.com/en-us/azure/storage/common/storage-sas-overview) resources using shared access signatures (SAS) documentation to create the token.
