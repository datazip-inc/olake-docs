# OLake Fusion (v0.2.2)
Nov 12, 2026 – Nov 24, 2026

:::warning[Iceberg format version 3 tables]
Fusion v0.2.2 does not run compaction or snapshot expiry on Iceberg **format version 3** tables. Each scheduled run on such a table is recorded as **Failed** with the reason `Iceberg format version 3 is not supported right now`.

OLake Go creates a table at format version 3, or upgrades an existing table to it, when the stream writes deletion vectors. Format versions 1 and 2 are supported. To see which delete format OLake Go writes, check [Target Query Engines](/docs/getting-started/job-level-properties/#target-query-engines) and [Delete Format Support by Query Engine](/docs/understanding/compatibility-engines/#delete-format-support-by-query-engine).
:::

## 🎯 What's New

### Logs

1. **Added Run Logs in S3 -** <br/> When the deployment stores logs in S3 (`OLAKE_STORAGE_MODE=s3`, set by the Helm chart when `global.logFileStorageMode` is `s3`), Fusion uploads the logs of each run to the bucket as one object when the run completes, then deletes the local copy. The Logs page in OLake UI reads the object back from S3. For setup, see [S3 Log File Storage Configuration](/docs/fusion/install/kubernetes-compaction/#s3-log-file-storage-configuration).
    - Compaction runs: `<prefix>/fusion/logs/optimization/<processId>.log`
    - Cleanup runs: `<prefix>/fusion/logs/cleanup/<processId>.log`
    :::important[Compatibility]
    S3 log storage for Fusion needs Helm chart **olake-0.0.37 or later**.
    :::

2. **Removed the Shared Log Volume Between Fusion and the Optimizer -** <br/> The Spark optimizer and its executors now send their logs to Fusion over Thrift, and Fusion is the only process that writes run logs. In S3 mode, the Fusion, optimizer and executor pods no longer mount the shared NFS volume.

### Compaction

1. **Added Executor Memory Hints -** <br/> Before a compaction task loads its equality deletes, the task's sub-task log states how much executor memory it may need. The message is a WARN when the estimate is above 80% of the executor memory (`Executor memory may be nearly full for this task`) or above all of it (`Executor memory may be too small for this task`).
    - On Kubernetes, the optimizer also logs a WARN (`Memory overhead may be too low`) when `spark.executor.memoryOverhead` is below the recommended value: 15% of the executor memory for executors of 6 GB or less, 10% above that, and at least 512 MB.
    - For how to read and fix these, see [Compaction Out of Memory](/docs/fusion/maintenance/troubleshooting/out-of-memory/).

### Telemetry

1. **Added Failure Telemetry -** <br/> Fusion now reports failures as anonymous `Failure - Fusion` events. These cover catalog and table sync, optimizer start and registration, compaction planning, execution and commit, table refresh, health score evaluation and snapshot expiry.
    - Each event carries the failed operation, a failure category, and the Fusion and optimizer versions. No error messages, hosts or catalog names are sent.
    - To turn telemetry off, set `TELEMETRY_DISABLED=true` for Fusion.

## 🔧 Bug Fixes & Stability

1. **Runs on Iceberg Format Version 3 Tables Now Fail Visibly -** <br/> Compaction and cleanup now check the table's Iceberg format version when their cron fires. On a table above format version 2, Fusion records a **Failed** run with the reason `Iceberg format version 3 is not supported right now` without starting it, and leaves the table unchanged. The failed run appears in Run History.

2. **Updated README Links -** <br/> The README now links to the `datazip-inc/olake-go` repository.
