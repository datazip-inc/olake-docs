# What is a Run?

A **run** is one execution of a compaction (Lite, Medium, or Full) or a cleanup (snapshot expiry) on a specific Iceberg table.

Each time a scheduled compaction or cleanup starts for a table, OLake Fusion creates a new run entry. This entry tracks:

- The **table** being maintained
- The **run type** (Lite, Medium, Full, or **Expire** for a cleanup run)
- The **current status** of the run
- The **start time and duration**
- The **logs** for that execution
- The **Metrics** of that execution

Runs help you understand what has been compacted or cleaned up, when it happened, and whether it completed successfully.

## Run Lifecycle

Every run goes through a few simple states from start to finish:

| State   | Description |
|---------|-------------|
| Running | The run is currently in progress for the table. |
| Success | The run finished successfully without errors. |
| Failed  | The run stopped due to an error. Check the logs for details. |
| Closed  | The run was cancelled with **Cancel Run** or stopped by Fusion. |
| Skipped | The cron fired, but the table's snapshot had not changed since the last compaction, so there was no new data to process. |

### Cancelling a Run

To stop a compaction run that is in progress, open the table's **Actions** menu (three dots) on the **Tables** page and click **Cancel Run**. The option is available only while a Lite, Medium or Full run is running. The cancelled run then shows as **Closed**.

## Viewing Runs

You can see all runs for a table from the **Tables** page:

1. Go to the **Tables** page in the OLake UI.
2. In the row for the table you are interested in, click the **Actions** menu (three dots).
3. Click **View Logs & Runs**.

![View Runs Button](/img/docs/iceberg-maintenance/runs-and-logs/view-logs-and-runs-button.webp)

This opens the **Runs** view for that table. It has these columns:

- **Run ID**
- **Status** of each run
- **Type**: Lite, Medium, Full, or Expire (cleanup)
- **Start Time** and **Duration**
- **Metrics**: click **View** to see the metrics of a compaction run
- **Logs**: click **View** to inspect the logs of a run

![Runs Page](/img/docs/iceberg-maintenance/runs-and-logs/runs-page.webp)

### Filtering Runs

Two filters narrow the list. The selected filters stay in the page URL (`?type=` and `?status=`), so they survive a reload.

- **Type**: **All Types**, **Optimization** (Lite, Medium and Full runs) or **Cleanup** (Expire runs)
- **Status**: **All Runs** or **Failed Runs**

## Viewing Logs

From the **Runs** view, you can open detailed logs for a specific run:

1. Locate the run you want to inspect.
2. In the **Logs** column for that run, click the **View** button.

![View Logs Button](/img/docs/iceberg-maintenance/runs-and-logs/view-logs-button.webp)

This opens the **Logs** page for that run. For a compaction run, the Logs page is split into:

- **Driver Logs**: high-level logs for the overall compaction run.
- **Subtasks**: detailed logs for each sub-task that the run is broken into. Use **Search Subtasks** to find one.

A cleanup run has a single **Cleanup Logs** panel and no sub-tasks.

The **Driver Logs** section gives you an overview of how the run progressed from start to finish.

![Logs Page](/img/docs/iceberg-maintenance/runs-and-logs/logs-page.webp)

The **Subtasks** list shows separate logs for each sub-task within the run, so you can pinpoint issues in specific parts of the process.

![Sub tasks logs view](/img/docs/iceberg-maintenance/runs-and-logs/sub-tasks.webp)

### Downloading Logs

- **Download Logs**, above the log panel, downloads the log that is open: the driver log, one sub-task log or the cleanup log.
- On a compaction run, the **Logs** button with the download icon, under the run ID, downloads the driver and sub-task logs together as one archive.

## Where Logs Are Stored

Where run logs are stored depends on the log file storage mode of the deployment:

- **S3 mode:** While a run is in progress, Fusion writes its logs to a local volume in the Fusion pod. When the run completes, Fusion uploads the logs to the configured S3 bucket as one object per run. When the Logs page opens, Fusion reads the run's object back from S3.
- **NFS mode (Helm):** Logs are written to the shared NFS volume.
- **Docker Compose (default):** Logs are written to the `amoro-logs` folder in the directory where you run `docker compose`.

For Kubernetes setup details, see [S3 Log File Storage Configuration](/docs/fusion/install/kubernetes-compaction/#s3-log-file-storage-configuration).
