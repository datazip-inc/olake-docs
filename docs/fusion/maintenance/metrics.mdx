# Overview

The Metrics view helps you understand both the **current health of an Iceberg table** and the **impact of compaction runs**.

There are two types of metrics:

- **Table Metrics** – always available for a table, showing its current state.
- **Run Metrics** – measurements for a single compaction run: input vs output data and delete files (counts and sizes) for that run.

## Table Metrics

You can see table-level metrics from the **Tables** page by clicking the **View Metrics** button for a table.

![Table metrics button](/img/docs/iceberg-maintenance/metrics/view-table-metrics-button.webp)

These metrics describe the current layout and size of the Iceberg table:

![Table metrics view](/img/docs/iceberg-maintenance/metrics/table-metrics.webp)

| Metric             | Description                                                                 |
|--------------------|-----------------------------------------------------------------------------|
| File Count         | Total number of data and delete files that currently make up the table.    |
| Total Size         | Combined on-disk size of all files that belong to the table.               |
| Average File Size  | Average size of files; useful to see if the table has many small files.    |
| Last Commit Time   | Time of the last successful Iceberg commit for the table.                  |
| Data Files         | Number of data files that store actual table rows.                         |
| Delete Files       | Number of delete files (equality and position) that track removed or filtered-out rows.            |
| Health Score       | Combined score based on Small Files Score, Eq Delete Score, and Pos Delete Score. |

<details>
<summary><strong>Health Score</strong> appears in the <strong>Tables</strong> page, not in the <strong>View Metrics</strong> modal.</summary>

![Health Score column on the Tables page](/img/docs/iceberg-maintenance/metrics/health-score.webp)

</details>

## Run Metrics

Run Metrics describe what one compaction run did to the table: how many data and delete files went in, and how many data and delete files came out. Open them from the **Runs** page via the **View Metrics** action for the run you want to inspect.

![Run metrics view](/img/docs/iceberg-maintenance/metrics/view-run-metrics-button.webp)

These metrics help you see how much a specific run improved the table:

![Run metrics view](/img/docs/iceberg-maintenance/metrics/run-metrics.webp)

:::info[Size units]

**Table metrics** show sizes with units, for example `1.25GB`. **Run metrics** show sizes in **bytes**.

:::

| Metric                          | Description |
|---------------------------------|-------------|
| Input Data Files(rewrite)       | Count of input data files rewritten by the run |
| Input Data Size(rewrite)        | Total size of input data files rewritten by the run |
| Input Data Files(read-only)     | Count of data files read but not rewritten. Shown only when not zero. |
| Input Data Size(read-only)      | Total size of data files read but not rewritten. Shown only when not zero. |
| Input Data Records(read-only)   | Rows in data files read but not rewritten. Shown only when not zero. |
| Input Equality Delete Files     | Count of input equality delete files (Count of equality delete files in the current snapshot * No.of sub-tasks). Shown only when not zero. |
| Input Equality Delete Size      | Total size of input equality delete files. Shown only when not zero. |
| Input Position Delete Files     | Count of input position delete files (Count of position delete files in the current snapshot * No.of sub-tasks). Shown only when not zero. |
| Input Position Delete Size      | Total size of input position delete files. Shown only when not zero. |
| Output Data Files               | Count of output data files produced |
| Output Data Size                | Total size of output data files produced |
| Output Delete Files             | Count of output delete files produced. Shown only when not zero. |
| Output Delete Size              | Total size of output delete files produced. Shown only when not zero. |


## Interpreting Metrics

- A high **Delete Files** count or very low **Average File Size** can indicate fragmentation and metadata overhead.
- After a successful compaction run, compare **Input** vs **Output**.
- A smaller **Output delete size** (and/or fewer **Output** delete files) typically indicates the run reduced delete-file fragmentation.
- Changes in **Input**/**Output** data file counts and data size show how much data was rewritten/compacted for that run’s scope.
