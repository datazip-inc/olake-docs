# Docker Compose (OLake UI)

OLake UI provides a complete Docker Compose stack for running the replication sync using different sources with orchestration.

<details>
<summary><b>Components & Architecture</b></summary>

- **OLake UI**: Main web interface for job management and configuration
- **Temporal Worker**: Background worker for processing data replication jobs
- **PostgreSQL**: Primary database for storing job data, configurations, sync state, and Temporal visibility data
- **Temporal Server**: Workflow orchestration engine for managing job execution
- **Temporal UI (optional)**: Web interface for monitoring workflows and debugging. It is not started by default. Run `docker compose -f docker-compose-v1.yml --profile debug up -d temporal-ui` and open http://localhost:8081.
- **Signup Init**: One-time initialization service that creates the default admin user
- **Fusion**: Maintenance control plane and API server
- **Fusion Spark Optimizer**: Spark-on-Kubernetes execution layer for maintenance jobs. It runs as a Kubernetes Deployment, and Kubernetes recreates it if it stops (in a Kind cluster in Docker)

![OLake platform Docker Compose architecture showing user, core services, containers, and external data sources.](/img/docs/fusion-architecture.webp)

</details>

## Prerequisites

The following requirements must be met before starting:
- [Docker](https://docs.docker.com/get-docker/) installed (Docker Desktop recommended)
- [Docker Compose](https://docs.docker.com/compose/) v2 (`docker compose`, included with Docker Desktop), not the legacy `docker-compose` 1.x
- Ports 8000, 1630, 1260 and 1261 free on the system (OLake UI, and the Fusion web UI and Thrift services)
- System Requirements:
    - Minimum: 8 vCPU, 16 GB RAM
    - Recommended: 16 vCPU, 32 GB RAM

## Quick Start

### One-Command Setup

The fastest way to get OLake UI running is with a single command:

Setup Maintenance and Ingestion stack with following command:

```bash
curl -sSL https://raw.githubusercontent.com/datazip-inc/olake-ui/master/docker-compose-v1.yml | ENABLE_OPTIMIZATION="true" docker compose --profile fusion -f - up -d
```

The OLake UI server reads `ENABLE_OPTIMIZATION` from the environment. Set `ENABLE_OPTIMIZATION="true"` in the command above to access maintenance module; the `fusion` profile starts Fusion and related services.

Spark maintenance executes on a Kind (Kubernetes in Docker) cluster (`fusion-cluster`) created by the Fusion profile. `fusion-db-init` downloads `config.yaml`, `kind-config.yaml`, `spark-rbac.yaml`, and `spark-optimizer.yaml` (the optimizer's Kubernetes Deployment) from the `olake-ui` GitHub repository over HTTPS at startup. Local overrides for those files are not supported at this time.

This command will:
- Read the latest `docker-compose-v1.yml` from GitHub (nothing is saved locally)
- Pull all required Docker images
- Start all services in the background
- Create a default admin user automatically

## Service Configuration

The settings below are made in a local copy of `docker-compose-v1.yml`. Download it, edit it, then start the stack from that file:

```bash
curl -sSLo docker-compose-v1.yml https://raw.githubusercontent.com/datazip-inc/olake-ui/master/docker-compose-v1.yml
# edit the file, then:
ENABLE_OPTIMIZATION="true" docker compose --profile fusion -f docker-compose-v1.yml up -d
```

### Changing Admin Credentials

The default admin user can be customized by editing `docker-compose-v1.yml` before starting:

```yaml
x-signup-defaults:
  username: &defaultUsername "your-username"
  password: &defaultPassword "your-secure-password"
  email: &defaultEmail "your-email@example.com"
```

### Updating OLake UI Version

To update OLake UI (Ingestion + Maintenance Stack) to the latest version, use the following commands based on your setup:

```bash
docker ps -aq --filter name=fusion-cluster \
| xargs -r docker rm -f; \
curl -sSL https://raw.githubusercontent.com/datazip-inc/olake-ui/master/docker-compose-v1.yml \
| docker compose --profile fusion -f - down && \
curl -sSL https://raw.githubusercontent.com/datazip-inc/olake-ui/master/docker-compose-v1.yml \
| ENABLE_OPTIMIZATION="true" docker compose --profile fusion -f - up -d
```

### Encryption Key Configuration

OLake supports encryption of source and destination configurations stored in the database. Configure the encryption key in `docker-compose-v1.yml`:

- **Custom String**: Provide any string (OLake generates SHA-256 hash):

    ```yaml
    x-encryption:
      key: &encryptionKey "your-passphrase"
    ```

- **AWS KMS**: Use a AWS KMS key ARN (recommended for production):

    ```yaml
    x-encryption:
      key: &encryptionKey "arn:aws:kms:us-east-1:123456789012:key/12345678-1234-1234-1234-123456789012"
    ```

- **Disable Encryption**: Use empty string:

    ```yaml
    x-encryption:
      key: &encryptionKey ""  # No Encryption
    ```

### Customizing Data Directory

The default data directory can be changed by modifying the host persistence path. Change only the `host_persistence_path` value and keep the rest of the `x-app-defaults` block as shipped:

```yaml
x-app-defaults:
  host_persistence_path: &hostPersistencePath /custom/path/to/olake-data
  amoro_log_persistence_path: &amoroLogPersistencePath ${PWD}/amoro-logs
  worker_config_volume_details: &workerConfigVolumeDetails
    type: bind
    source: *hostPersistencePath
    target: /tmp/olake-config
  amoro_log_volume_details: &amoroLogVolumeDetails
    type: bind
    source: *amoroLogPersistencePath
    target: /mnt/amoro-logs
```

This will create and use `/custom/path/to/olake-data` instead of the default `${PWD}/olake-data` (an `olake-data` folder in the directory where you run `docker compose`). The Fusion services reference the `amoro_*` entries, so the file does not parse if you remove them. To move Fusion's run logs as well, change `amoro_log_persistence_path`.

### External PostgreSQL Configuration

OLake UI and Temporal can use an **external PostgreSQL instance** instead of the built-in `postgresql` service. Set this up with an override file, as described in [External PostgreSQL Configuration](/docs/install/olake-ui/#external-postgresql-configuration) on the OLake Go Docker page. Add `--profile fusion` and `ENABLE_OPTIMIZATION="true"` to each `docker compose` command.

OLake Fusion always uses the built-in `postgresql` service in Docker Compose. `fusion-db-init` creates the `fusion` database on host `postgresql` as user `temporal`, and Fusion's `config.yaml`, downloaded at startup, points to `jdbc:postgresql://postgresql:5432/fusion`.

:::info
Keep the built-in `postgresql` service running. To run Fusion on an external PostgreSQL, use the Helm chart (see [External PostgreSQL Configuration](/docs/fusion/install/kubernetes-compaction/#external-postgresql-configuration)).
:::

### Service Environment Variables

Key environment variables can be customized within the `x-envs` section. These variables are automatically injected into the `olake-ui` and `temporal-worker` services, and into the `fusion-db-init` and `fusion` services of the `fusion` profile. Keep the keys that are already there and add yours below them:

```yaml
x-envs:
  shared: &sharedEnvs
    CONTAINER_REGISTRY_BASE: ${CONTAINER_REGISTRY_BASE:-docker.io}
    OLAKE_SECRET_KEY: *encryptionKey
    PERSISTENT_DIR: *hostPersistencePath
    ENABLE_OPTIMIZATION: ${ENABLE_OPTIMIZATION:-false}
    # add your keys below this line
    FOO: bar
```

### S3 Log File Storage

The shipped `x-envs.shared` block has commented `OLAKE_STORAGE_MODE` and `OLAKE_S3_*` keys. When you set them, OLake Fusion (v0.2.2 or later) also uploads the logs of each run to that bucket, under `<prefix>/fusion/logs/`. For the keys and the bucket permissions, see [S3 Log File Storage Configuration](/docs/install/olake-ui/#s3-log-file-storage-configuration) on the OLake Go Docker page.

### Disabling Telemetry

OLake Fusion sends anonymous usage telemetry to help improve the product. To opt out, set `TELEMETRY_DISABLED` under `x-envs.shared`:

```yaml
x-envs:
  shared: &sharedEnvs
    TELEMETRY_DISABLED: "true"
```

### Data Persistence

The Docker Compose setup creates the following data storage:

#### OLake Config Directory
- `olake-data`: Local directory created in the current working directory
    - Contains streams configurations, connection settings, and sync state
    - Persists across container restarts and recreations
    - Used by OLake UI and Temporal Worker services

#### Fusion Log Directory
- `amoro-logs`: Local directory created in the current working directory
    - Contains Fusion run logs (driver and sub-task logs)
    - The log retention cleaner does not remove these files. Delete old folders by hand, or use [S3 log file storage](#s3-log-file-storage).

#### Docker Volumes
- `temporal-postgresql-data`: PostgreSQL database storage
    - Contains workflow execution history, job metadata and sync state
    - Used by the PostgreSQL service
- `temporal-elasticsearch-data` (Legacy only): Elasticsearch search index storage
    - Used by the Elasticsearch service in the legacy configuration
- `fusion-config`, `kind-kubeconfig` and `spark-home` (`fusion` profile): Fusion's downloaded configuration, the kubeconfig of the Kind cluster, and the Spark files the optimizer uses

### Log Retention
OLake includes an automated log retention system that helps manage disk space by automatically cleaning up old OLake Go job log files in `olake-data`. It does not clean Fusion's `amoro-logs` folder.

#### What It Does
- Runs daily at midnight (00:00 server's local timezone) using a cron job
- Deletes entire log directories that are older than the configured retention period (defaults to 30 days)

#### Configuration
Set the `LOG_RETENTION_PERIOD` environment variable in the docker-compose of [olake-ui](https://github.com/datazip-inc/olake-ui)  to control how long logs are kept:

```yml
# In docker-compose-v1.yml
services:
  temporal-worker:
    environment:
      LOG_RETENTION_PERIOD: "30"  # Keep logs for 30 days
```

#### Monitoring Log Cleaner
The log cleanup process can be monitored through the logs of the `temporal-worker` service defined in the docker-compose configuration for [olake-ui](https://github.com/datazip-inc/olake-ui).

Every time the cron job runs, it emits the following log:
```text
running log cleaner...
```

As each log directory is deleted, a log entry is generated showing the full path of the directory being removed:
```text
deleting folder: /path/to/olake-data/<dir>
```

### Temporal Retention Period

OLake includes a configurable retention period for Temporal visibility data that controls how long job and sync history are stored and visible in the system. This helps manage database storage by automatically cleaning up old workflow execution history.

#### Configuration
Set the `TEMPORAL_RETENTION_PERIOD` environment variable in the `temporal-worker` service within the docker-compose configuration for [olake-ui](https://github.com/datazip-inc/olake-ui) to control how long visibility data is retained:

```yaml
# In docker-compose-v1.yml
services:
  temporal-worker:
    environment:
      TEMPORAL_RETENTION_PERIOD: "168h" # Keeps data visible for 7 days (by default)
```

**Configuration Constraints:**
- **Minimum value**: 1 day
- **Default value**: 7 days

The retention period is specified in **hours**. Only job and sync history within the configured retention period will be visible in the OLake UI.

## Troubleshooting

### Common Issues

#### Port Conflicts
If port binding errors occur:
1. Check what's using the ports: `lsof -i :8000`, and the same for 1630, 1260 and 1261 (on macOS/Linux)
2. Stop conflicting services or change ports in `docker-compose-v1.yml`

#### Database Connection Issues
- Ensure PostgreSQL container is healthy: `docker compose ps`
- Check PostgreSQL logs: `docker compose logs postgresql`

#### Memory Issues
- Ensure Docker has at least 8 vCPU and 16 GB RAM allocated
- Check Docker resource usage: `docker stats`

#### Permission Issues
- On Linux, ensure the user is in the docker group
- Check file permissions for the `./olake-data/` directory (or custom path if modified)

### Reset Everything

The OLake stack can be completely reset with:

```bash
# Removes containers and volumes
ENABLE_OPTIMIZATION="true" docker compose --profile fusion -f docker-compose-v1.yml down -v  
# Removes the Kind cluster
docker ps -aq --filter name=fusion-cluster | xargs -r docker rm -f 
# Fresh start
ENABLE_OPTIMIZATION="true" docker compose --profile fusion -f docker-compose-v1.yml up -d    
```

**Warning**: This will delete all job data and configurations.
