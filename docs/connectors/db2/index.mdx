# Overview {/* #overview */}

The OLake Go DB2 LUW (Linux Unix Windows) Source connector supports multiple synchronization modes. It offers features like parallel chunking, checkpointing, and automatic resume for failed full loads. This connector can be used within the OLake UI or run locally via Docker for open-source workflows.

:::tip[Integration guides]

Tested, step-by-step guides take DB2 to [Snowflake](/docs/integrations/db2-to-snowflake/), [BigQuery](/docs/integrations/db2-to-bigquery/), [Redshift](/docs/integrations/db2-to-redshift/) and [ClickHouse](/docs/integrations/db2-to-clickhouse/), each from a pipeline that was run end to end.

:::

## Sync Modes Supported

- **Full Refresh**
- **Full Refresh + Incremental**

<IndexStorageNote />

## Prerequisites

### Version Prerequisites
        
- DB2 Version 11.5.3 or higher.

### Connection Prerequisites

- Read access to the tables for the DB2 user.
- Table statistics for every non-empty table. OLake Go reads them to plan chunks, so run `RUNSTATS` first (see [Stats Not Populated](#2-stats-not-populated)):
  ```sql
  CALL SYSPROC.ADMIN_CMD('RUNSTATS ON TABLE schema_name.table_name AND INDEXES ALL');
  ```

:::info
- IBM Data Server ODBC and CLI driver is **not supported** for **Linux (arm64)**. Avoid using this machine for DB2 workloads.
- The recommended CPU architecture to run DB2 sync is **AMD64**.
:::

**After initial Prerequisites are fulfilled, the configurations for DB2 can be configured.**

### 3. Check Source Connection

To verify the database connection following command needs to be run:

```bash title="check command"
docker run --pull=always \
-v "[PATH_OF_CONFIG_FOLDER]:/mnt/config" \
olakego/source-db2:latest \
check \
--config /mnt/config/source.json
```

:::note
The `olakego/source-db2` image (linux/amd64 only) includes the IBM Data Server ODBC and CLI driver. When building from source, `./build.sh` downloads it.
:::

- If OLake Go is able to connect with DB2 `{"connectionStatus":{"status":"SUCCEEDED"},"type":"CONNECTION_STATUS"}` response is returned.

- In case of connection failure, refer to the [Troubleshooting section](#troubleshooting).

## Troubleshooting {/* #troubleshooting */}

### 1. ALTER TABLE in DB2 LUW

In DB2 LUW, certain `ALTER TABLE` operations can place a table in `REORG PENDING` state, and while in this state:
- Queries, inserts, or sync jobs may fail with errors like SQL0668N.
- A `REORG TABLE` is required before normal access is restored.

Operations that commonly cause this include:
- `ADD COLUMN`
- `DROP COLUMN`
- `ALTER COLUMN` (datatype/length changes)
- Some changes to row organization or table attributes

**Required fix:**
Running a reorganization is the correct resolution:

```sql
CALL SYSPROC.ADMIN_CMD('REORG TABLE schema_name.table_name');
``` 

This clears the `REORG PENDING` state and makes the table usable again.

### 2. Stats Not Populated

```logs
stats not populated for table[<schema>.<table>]. Please run CLP command: RUNSTATS ON TABLE <schema>.<table> AND INDEXES ALL; to update table statistics
```

**Cause**: The table has rows, but DB2 has no statistics for it, so OLake Go cannot plan chunks. Empty tables are skipped.

**Solution**: Collect the statistics, then run the sync again:

```sql
CALL SYSPROC.ADMIN_CMD('RUNSTATS ON TABLE schema_name.table_name AND INDEXES ALL');
```
