# MongoDB and Atlas CDC Setup

This guide covers setting up Change Data Capture (CDC) for both self-hosted MongoDB and MongoDB Atlas. Most steps apply to both, with notes where Atlas differs because certain configurations are pre-enabled.

CDC works on a replica set or a sharded cluster. For a sharded cluster, connect OLake Go to `mongos`, skip steps 1 and 2, and create the user through `mongos`. Standalone servers cannot open change streams.

## 1. Enable Replica Set Mode

- **Self-Hosted MongoDB**: Start MongoDB with replica set enabled to activate the oplog.

  - Inside Docker:
  
    ```bash
    docker run -d --name mongodb  -p 27017:27017  mongo:8.0 --replSet rs0
    ```
  - Outside Docker:
  
    ```bash
    mongod --replSet rs0 --bind_ip_all
    ```

- **MongoDB Atlas**: Replica set is pre-configured; **skip this step**.

## 2. Initialize the Replica Set (Self-Hosted Only)

- **Self-Hosted MongoDB**: 
  1. After MongoDB starts with replica set mode, initialize it:
  
      ```bash
      docker exec -it mongodb mongosh
      ```
  2. Then run:
  
      ```bash
      rs.initiate()
      ```
  3. You should see:
  
      ```bash
      { "ok" : 1 }
      ```

  ✅ Now your MongoDB has a replica set and oplog enabled.

- **MongoDB Atlas**: Initialization is already done; **skip this step**.

## 3. Create a User


**Applicable for both MongoDB (Self-Hosted) and Atlas.**

OLake Go only reads, so it needs a user that can:  
- Read your application database (to ingest data and open change streams).
- Read from the local database (where oplog is stored), for the optional oplog-retention check.

Create the user in the `admin` database:

```javascript
use admin
db.createUser({
  user: "olake_user",
  pwd: "your_password",
  roles: [
    { role: "read", db: "your_db" },
    { role: "read", db: "local" }
  ]
})
```

## 4. Verify oplog

**Applicable for both Self-Hosted and Atlas.**

Check that the oplog collection exists:

```javascript
use local
show collections
db.oplog.rs.findOne()
```
If you see an entry, ✅ oplog is working. 

## 5. Check the Oplog Window

The `oplog_retention` check in OLake Go's test connection warns when the oplog window is shorter than 7 days. If a sync is paused longer than the window, its resume point is lost and a full resync is needed. Check the window with:

```javascript
rs.printReplicationInfo()
```

To keep entries longer on a self-hosted replica set, set a minimum retention with [`replSetResizeOplog`](https://www.mongodb.com/docs/manual/reference/command/replSetResizeOplog/) (checked Nov 2026), for example `db.adminCommand({ replSetResizeOplog: 1, minRetentionHours: 168 })` on each member.

## 6. Enable Pre-images for Deletes (Optional, MongoDB 6.0+)

By default, a deleted document reaches OLake Go with only its `_id`. To write the full deleted document, enable pre-images on each collection ([change streams](https://www.mongodb.com/docs/manual/changeStreams/), checked Nov 2026):

```javascript
db.runCommand({ collMod: "your_collection", changeStreamPreAndPostImages: { enabled: true } })
```
