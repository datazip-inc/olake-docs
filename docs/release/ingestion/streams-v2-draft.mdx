# OLake vX.Y.Z — Streams v2

{/* TODO(STREAMS_V2_VERSION) */}

## 🎯 What's New

### Configuration Format

1. **Streams v2 -** <br/> Streams v2 replaces the single-file `streams.json` (Streams v1) with two files: `selected_streams.json` (editable stream settings) and `available_streams.json` (read-only discovered metadata). This change simplifies configuration, reduces diff noise, and makes discovery safer. Streams v1 remains fully supported and is deprecated for removal in a future release. See the [Streams v2 reference](/docs/core/configs/streams/).

### CLI Flags

1. **New stream flags -** <br/> Added `--selected-streams` and `--available-streams` for Streams v2. Added `--difference-selected-streams` and `--difference-available-streams` for comparing configurations. Deprecated flags `--streams`, `--catalog`, and `--difference` still work and will be removed in a future release. `--streams` and `--catalog` log a deprecation warning.

### Discover & Sync

1. **Backwards-compatible discovery -** <br/> The `discover` command continues to write all three files (`selected_streams.json`, `available_streams.json`, and legacy `streams.json`) with the same settings, so existing `--streams` scripts keep working and migration is a flag change. The `sync` and `clear-destination` commands now accept `--selected-streams` and `--available-streams`. The legacy `--streams` flag (alias `--catalog`) still works with `streams.json`, but cannot be combined with the new flags.

## 🔧 Migration

- OLake UI converts existing jobs to Streams v2 on startup and on source version upgrade. After that, the source version cannot be downgraded below the first version that supports Streams v2.
- CLI users switch from `--streams` to `--selected-streams` + `--available-streams`. Migration is one-way.

No action is required: Streams v1 (`streams.json`) continues to work. To adopt Streams v2, pass `--selected-streams` and `--available-streams` instead of `--streams`; discover already wrote both files. For a `streams.json` from an older version, re-discover against the source first. See the [migration guide](/docs/core/configs/streams-migration/) for detailed steps and the [Streams v1 reference](/docs/core/configs/streams-legacy/) for the old schema.
